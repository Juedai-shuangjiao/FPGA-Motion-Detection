## 七、fuse22 迭代记录（2026-11-03 下午，SW34 状态修复 + 摄像头数据采集链路）

### 背景
下板反馈两点 + 新需求：
1. SW34 拨到模式 0 默认自动；手动状态拨 SW34 切走再切回 0 就变回自动（手动状态没保持）。
2. Sobel 边缘阈值随亮度联动跳档不稳定。
3. 新需求：把摄像头原始数据采下来发到电脑，用原汁原味的数据离线优化各算法。

### 实现
**A. SW34 手动状态保持（key/auto_manual_sel.v）**
- 根因：原代码非 00 模式（!en）把 mode 复位为 1'b0（自动）——切走再切回手动状态丢失。
- 修复：!en 分支只清 held_flag，mode 保持不动；en 恢复后长按沿照常切换。
- tb_auto_manual_sel 用例⑤期望反转（en=0 保持 mode=1）+ 新用例⑥（en 恢复后长按切回自动）→ PASS。

**B. 检测模式曝光冻结门控补齐（design_top_wrapper.v）**
- ae_set 的 I_enable 补 01 检测模式冻结：`~S_mode[1] && ((S_auto_manual && ~I_sw[3]) || I_sw[2])`——手动态仅 00（SW4=0）或 SW3 高（10/11）可调；01 冻结（e8488bc 语义）。

**C. 摄像头数据采集链路（新建 src/hdl_source_clean/snapshot_tx.v，218 行）**
- 纯旁路方案：不改主逻辑。监听 bg_read 数据流（DDR 128bit 读、rd_tag=0 背景读、每拍 rd_valid），每帧 tap 4KB 窗口（256 beat×128bit）入官方 w128_d512_fifo（8KB，1 ERAM），2Mbps UART 循环发。
- 协议：帧头 {AA 55 53 4E} + 数据（DDR 128bit 低字节在前）+ 帧尾 {55 AA}；BAUD_DIV=150（300MHz/2Mbps）；全帧 336000 beat×16B=5.376MB ≈ 21.5s/周期（帧头重同步可切片）。
- 波特率选择：CH340 支持 2Mbps；115200 太慢（一帧要 6 分钟），2M 是带宽/可靠性平衡点。
- 接线：wrapper 例化 + S_rd_valid_d1 打拍 + uart_tx MUX（S_snap_en 控制，TD 先声明后使用——MUX 放例化块之后）；工程三文件注册 CompileOrder 89。
- 触发：仿真验证用 snap_en 直通；实机默认一直采（拨 SW 触发留作后续）。

### snapshot_tx 调试踩坑记录（UART 时序 5 连坑，全部仿真定位）
1. start 位双发：装载拍 line=0 后第 1 baud 周期又发 sr[0]=start → 改 bit_cnt 语义，装载拍发 start 后首个 baud 发 sr[1]（d0）。
2. stop 位被压成 2 拍：发完 stop 立即装载下一字节 → bit_cnt 装载 10，第 9/10 周期发 stop（双 stop，接收端兼容）。
3. fifo_re 双弹：re 脉冲后 1 拍 fifo_re_d1 还没置位，状态机又发 re → 加 !fifo_re 条件（单拍脉冲）。
4. ld_ack 提前发：UART 装载拍状态机 uart_idle 仍为 1，多发了下一字节（shifter 右移丢字）→ 三处发送分支加 !tx_load 抑制。
5. 仿真 IP 语义差：soft_fifo_al 的 valid=组合 !empty（与 re 后 1 拍 dout 语义不一致）→ RTL 按 TD 硬 IP 语义（valid 与 dout 同拍对齐）用 fifo_valid 装载；tb 用 NOREG 语义 stub 替换软 IP。
6. 复位后预发帧头：snap_en 之前状态机静止分支补发 → 加 !snap_en 静止分支。
