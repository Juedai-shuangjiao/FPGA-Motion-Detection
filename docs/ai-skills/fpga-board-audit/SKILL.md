# FPGA 板子资源审计（开工前必做）

**核心教训（2026-10-17 血泪）**：用户安路 PH1P35 板子做运动检测时，因为开工前没摸清板子资源，把合封存储「DDR3 SDRAM 512Mb/17Gbit/s」误判成「低带宽 SDR SDRAM 1.6Gbit/s」，算出「DDR 带宽顶 94%」→ 逼得运动检测降采样到 320×180 用片内 ERAM。后来一查 datasheet 才发现 DDR 带宽和容量都充裕，全分辨率根本不用降。**资源误判 = 白做降级方案 + 浪费几轮迭代**。

## 第一步：先要资料（别急着写代码，先让用户喂板子资料）

开工前先对用户说：「先把板子资料给我，我摸清资源再动手」。要这些：

1. **芯片 datasheet**（Device 命名 DSxxx、FamilyOverview）
2. **选型手册 / 器件对比表**（安路选型手册、Product Catalog）
3. **原理图**（开发板原理图，通常多页 PDF）
4. 板子的型号/封装（如 PH1P35MDG324，`MDG324` 是封装、影响合封存储规格）

用户板子资料通常放在一个固定目录（如 `D:\Users\user\Desktop\FPGA比赛\板子资料\<板子型号>\`，WSL 是 `/mnt/d/...`）。先 `find` 列目录结构，再 `pdftotext -layout xxx.pdf` 提取文字 grep 关键参数。

## 第二步：系统梳理芯片资源（要查的清单）

### 1. 逻辑资源
- LUT4s、DFFs（决定组合逻辑/寄存器余量）

### 2. 存储（资源受限的核心，最容易搞错）
- **ERAM（块 RAM）**：总块数 × 单块容量（如 108×20Kbit），**位宽配置是离散的**（1/2/5/10/20/40，没有 4bit/8bit，查 datasheet 的 RAM 配置表）——估算必须按「配置粒度」ceil(深度/单块深度)，不是「实际 bit 数」（4bit 数据塞 5bit 配置浪费 20%）。
- **分布式 RAM（Dis-RAM）**：小容量，用 LUT 实现。
- **合封存储**（DDR/SDRAM/PSRAM）—— ⚠️ 见下面「关键陷阱 1」，类型和带宽必须查准。

### 3. DSP / 时钟
- DSP 数量 + 位宽（18×18？9×9？）
- PLL 数量 + 每 PLL 输出路数
- 全局时钟网络数

### 4. 高速接口
- MIPI D-PHY 组数 + lane 数 + 线速率
- LVDS 速率、Serdes 通道
- 存储接口（DDR2/3/4 位宽 + 速率）

### 5. IO / 封装
- 最大用户 IO 数、封装类型（BGA/QFP，尺寸 pitch）

## 第三步：系统梳理板级外设（从原理图）

grep 原理图的关键信号/器件，列一张外设清单：HDMI / 摄像头（MIPI CSI）/ 按键 / LED / 数码管 / 蜂鸣器 / 以太网 PHY / Flash（QSPI）/ GPIO 扩展 / 时钟源（晶振频率）/ 电源（几路 VCCIO）。例程目录（`2_Example`）也能反推板子外设（有多少例程 = 多少外设）。

## 关键陷阱

### 1. 合封存储的类型不能只看名字，要看供电电压（这次栽在这）

「SDR SDRAM」和「DDR SDRAM」名字里都带 SDRAM，容量/位宽也常混写。**判据是供电电压**：

- **DDR3 = 1.5V**，DDR3L = 1.35V，SDR SDRAM = 3.3V
- 查 datasheet 的「最小供电要求」表里 **Integrated Memory I/O 电压**
- 原理图辅助证据：差分时钟（DDR 用差分 DQS/CK，SDR 用单端）、有 `DDR_VREF` 参考电压（DDR3 需要 0.75V VREF）

### 2. 带宽要算「峰值」再打折，别拍脑袋估低

DDR3 带宽 = 位宽 × 数据率。16bit × 1066Mbps = 17Gbit/s。这次把 17Gbit/s 估成 1.6~3.2Gbit/s（把合封当成低带宽 SDR），导致「带宽 94% 超限」的误判。**算出带宽后，用「某功能的数据量 ÷ 帧率」验证够不够，别用「百分比」空对空**（如全分辨率 RGB 4bit 背景读 = 11Mbit × 60fps = 0.66Gbit/s，只占 17Gbit/s 的 4%）。

### 3. 资源误判会导致「降级方案」

这次因为误判 DDR 带宽，把本可以全分辨率的运动检测降采样到 320×180。**任何「降采样/降精度/降分辨率」的妥协决定，先确认是不是被错误资源估算逼出来的**——开工前摸清资源，就是为了避免「有资源不用当冤大头」。

## 产出

审计完写一份 `资源清单.md` 存进工程（芯片资源表 + 板级外设 + 资源瓶颈评估），后续评估「能不能做某功能」「资源够不够」时直接翻，别重复查 datasheet。
