# 背景减除 / 运动目标检测（帧差法升级）

## 升级路径（帧差法 → 背景减除）

- **帧差法**：减「上一帧」，只检测帧间变化 = 手移动的**边缘**；手内部两帧都有、灰度相同的重叠区帧差≈0 是空的（工业界称「目标内部空洞」）。
- **背景减除**：减「固定背景 B」，检测「跟背景不同的整块物体」→ 手整体高亮（含手指、手掌内部，无空洞）。SW4 上升沿触发采一帧空背景，之后背景固定不更新。

## 阈值设计（两者本质不同）

- **帧差法阈值卡「运动速度」**：慢速挥手帧差(16~40) 和噪声(±20) 重叠 → 阈值两难（低白点/高漏检）。
- **背景减除阈值卡「前景背景差」**：手 vs 背景几十上百 >> 噪声 → 阈值好设（40~50 就能噪声全滤 + 整块检测）。背景减除顺便解决帧差法的阈值两难。

## 单通道选择（灰度丢颜色的解法，核心坑）

- **灰度减背景会丢颜色**：gray = R/4 + G/2 + B/4 是加权平均，会把「前景背景颜色互补」的差平均掉——手肤色偏红黄（R高B低）、背景灰白（RGB均衡），灰度算出来两者接近 → 手内部变黑、旋转 45° 只剩一半。
- **RGB 三通道减背景要 3 块背景 BRAM**：每块 65536 深 ≈25.6 ERAM，3 块必超 EMB 上限（PH1P35 总 108 ERAM）。
- **折中：选「前景和背景差最大的那个单通道」**：手肤色 B 低（约 90~100）vs 背景灰白 B 中（约 150），B 差 50~70 最明显，纯 B 单通道 + 1 块 BRAM 既保留颜色差又不超 EMB。
- **通用规则**：加权灰度会「平均掉」R高B低这种互补色差；选单通道前先看前景/背景在 R/G/B 哪个通道差最大，就用哪个（不一定是 B，取决于前景颜色）。

## BRAM 资源约束（PH1P35）

- ERAM = 108 个 × 20Kbit = 2.16 Mbit（不是早期误记的 1Mbit）。
- 背景 BRAM IP 深度固定 65536（一个占 25.6 ERAM）；改 down_cnt 回绕到更小值**不省 EMB**（IP 深度不变）。要省 EMB 只能：①减 IP 实例数（少通道）；②重新生成更浅的 IP（如 32768 深，需 TD GUI）。
- 降采样省不了 EMB，只影响实际用到的地址范围。

## SW4 采集触发 + 显示

- SW4 = I_sw[3]（引脚 D11 已接好）：0=等待采集，1=已采集，0→1 上升沿触发采一帧背景。
- 采集状态机：上升沿→等帧首→采完整一帧（bg_capture 持续一帧，避免采半帧导致背景前后不一致/分界线）。
- OSD 运动模式下显示「已采/未采」（字模 已/未/采，simhei 渲染）。
- 未采集（SW4=0）时输出全黑；采集后（SW4=1）才输出前景。
