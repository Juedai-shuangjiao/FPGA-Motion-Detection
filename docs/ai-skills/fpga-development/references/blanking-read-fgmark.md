# 消隐期读 + 前景标记片内（全分辨率 1×1 运动检测）

PH1P35 竞赛项目「运动检测」从「三路 DDR 竞争撕裂」升级到「消隐期错峰读 + 前景标记片内 ERAM」的完整方案。本文件记录已算清、已验证的关键数据与位序真相，避免下次重推。

## 1. 核心洞察（用户开发者提出，推翻「全分辨率不可能」）

减背景的「结果 = 前景标记」只有 **1 bit/像素**。1280×720×1bit = **0.92Mbit**，片内 ERAM 2.16Mbit **放得下**。所以全分辨率 1×1 前景可行，只要「消隐期算好前景标记存片内、有效期间显示叠加」。

数据流：消隐期读当前帧块 + 背景块（交替读 DDR）→ 分块相减 → 前景标记写片内 ERAM；有效期间显示读当前帧 + 读片内前景标记叠加（前景涂白）。

## 2. 时间预算（关键，推翻文档「消隐期 12.83ms」）

⚠️ 文档《当前状态与下一步.md》写「消隐期 12.83ms」是**错的**——那是有效显示时间，不是消隐期。

从 uivtc 参数实测（H_FrameSize=1650, V_FrameSize=750, HDMI 像素时钟 75MHz）：

```
帧周期   = 1650×750 = 1237500 像素 @75M = 16.5ms
有效显示 = 1280×720 = 921600 像素 @75M = 12.29ms
消隐期   = 315900 像素 @75M = 4.2ms   ← 实际只有 4.2ms
```

一帧 = 172800 个 128bit（1280×720×96/128），两帧（当前+背景）= 345600 个。

**usr_clk = DDR_SPEED/8**（PLL0 的 C0 输出，ph1p_ddrphy_pll0.v 顶部注释：C0=DDR_SPEED/8, C2=DDR_SPEED/2）。

| DDR 速率 | usr_clk | 读两帧时间 | vs 4.2ms 消隐期 |
|---|---|---|---|
| 半速 533Mbps | 66.67MHz | 5.18ms | ❌ 读不完（差约 1ms）|
| 800Mbps | 100MHz | 3.46ms | ✅ 余量 0.75ms |
| **满速 1066Mbps** | 133.3MHz | **2.59ms** | ✅ 余量 1.6ms |

结论：半速下消隐期读不完两帧，方案要满速或 800Mbps。

## 3. 前景标记 ERAM 布局（省 EMB 关键）

1bit/像素 × 1280×720 = 921600 bit。ERAM20K 位宽配置离散（1/2/5/10/20/40），最省方案：

- **40bit 宽 × 23040 深 = 45 块 ERAM**（512×40 配置，23040/512=45 精确整除，零浪费）
- ⚠️ **深度必须精确设 23040，不要取 2 的幂 32768**（32768/512=64 块，白浪费 19 块）。跟「RGB 3通道 4bit 从 65535 砍到 57600 省 3 块」同一原理，但这次是「信息量 921600bit = 45块×20480bit」完全匹配、理论零浪费。
- 128bit 宽反而要 4 块位宽级联（160bit 浪费 32bit）= 60 块，更费。
- 前景标记 ERAM 需双口（消隐期 DDR 域 133.3M 写 + 有效期间 HDMI 域 75M 读）。

## 4. DDR 时钟架构（usr_clk = DDR_SPEED/8）

PLL0 注释（ph1p_ddrphy_pll0.v 顶部）：C0=DDR_SPEED/8, C1=DDR_SPEED/8, C2=DDR_SPEED/2, C3=50MHz。CLK0_DIV=CLK2_DIV×4。

VCO = ref_clk/REFCLK_DIV × FBKCLK_DIV。ddr2.v 满速参数：tCK=1876ps, CL=7, CWL=6, REFCLK_DIV=3, FBKCLK_DIV=32, CLK2_DIV=2, PLL1_REFCLK_FREQ=133.3。

- 满速 1066Mbps：ref_clk=100M（K5/L5 差分），VCO=100/3×32=1066MHz，usr_clk=133.3M
- 半速 533Mbps：ref_clk=50M（I_sys_clk），usr_clk=66.67M
- **满速↔半速只改 ref_clk（100M↔50M）+ PLL0_REFCLK_FREQ（100.0↔50.0）**，tCK/CL/CWL/FBKCLK_DIV 都保持满速值（半速其实是「参数不一致」状态）

## 5. K5/L5 引脚（差分 DDR ref_clk）

- K5 = IO_L1P_11，L5 = IO_L1N_11，都是 **BANK11（DDR bank，VCC_1V5）** 的差分引脚
- 晶振 SIT9121AI-2B1（LVDS 输出），R262=100R/NC 未焊 → IBUF_DIFF 的 DIFF_TERM=TRUE 片内端接（但 ddrio 引脚端接不生效，裸跑能锁住）
- **IOSTANDARD = LVDS18**（不是 LVDS/DIFF_SSTL15，从之前满速综合日志反查的精确值）
- 顶层端口名 I_ddr_ref_clk_p/n，IBUF_DIFF 实例名 u_ddr_ref_clk_ibuf，SDC 时钟名 ddr_ref_clk_100m

## 6. 128↔24 位序真相（反序，不是 bug）

- `data128_96`（demosaic 128→96）转换：`O_tdata = {I_tdata[23:0], I_tdata[55:32], I_tdata[87:64], I_tdata[119:96]}`，确认 **96bit 位序 [23:0]=像素0(最左), [95:72]=像素3(最右)**
- 打包 data_96bit_to_128bit：128bit[0] = {96bit[0], 96bit[1][95:64]}，即 96bit[0] 在 [127:32]
- video_out 的 128→24bit 解包从 **[127:104] 高位拆**，跟 96bit 位序相反 → 输出是**每 4 像素反序**
- Python 精确模拟验证：反序**完整无损**（1280 像素全反序，行末尾 1279→1276 也反得规整）。反序靠后面坐标打拍抵消，画面正常，**位序本身不是 bug**

## 7. w128_d512_fifo 读时序（NOREG 是 1 拍寄存）

w128_d512_fifo 用 `OUTREG_EN("NOREG")`，但 ram_infer 的 read_b task 用**非阻塞赋值** `dob_tmp <= memory[addr]`，且 `assign dob = dob_tmp`。所以 **NOREG 下 dob 实际有 1 拍延迟（re 后 1 拍 dout 有效）**，不是「纯组合输出」。仿真 video_out 的 FIFO 读时序时按「re 后 1 拍 dout = memory[rd_addr 旧值]」建模。

## 8. 加裕量：Logo 路径时序优化

满速下 SWNS 最差路径（104ps）在 **hdmi_mixer 的 Logo 地址计算**（`S_logo_addr = (S_y_2d-LOGO_Y)*160 + (S_x_2d-LOGO_X)`），DSP 乘法器 + 6400 行 case 查表挤一条 12.8ns 组合链（14 级逻辑，net 延迟 52%，fanout 367）。优化三件套：

1. `*160` 改移位加法 `(S_y_1d<<7) + (S_y_1d<<5)`（160=128+32），甩掉 DSP 乘法器
2. Logo 地址打 1 拍（S_logo_addr_d1），拆「地址计算」和「ROM 查表」两段
3. 地址改用 S_x_1d/S_y_1d（提前 1 拍），抵消打拍延迟，保持「比坐标晚 3 拍」对齐不变

效果：HDMI 域 SWNS 104ps → 383ps（3.7 倍）。优化后全局最差变 DDR MC IP 内部（alc_mc_top/page_ctrl，259ps，加密 IP 改不了）。

⚠️ 排查时序先看 final_timing.rpt 的 Clock Summary：每时钟域 SWNS 一行，最差路径的 Begin/End point 一眼看出在哪个模块。

## 9. 跳帧 7→3 纠正（两路 DDR 下 3 帧够）

⚠️ 早期「跳 3 帧盖不住异常帧、改 7 帧」是**三路 DDR 竞争时期的误判**——当时的「每隔 10 帧闪几帧」其实是三路撕裂的闪烁，被误当成异常帧泄漏。摄像头切曝光的异常帧其实 ≤3 帧，两路 DDR 下跳 3 帧就盖得住。跳 7 帧是过度修正：多冻结 4 帧（117ms vs 50ms），这就是「改曝光卡顿」的元凶。**两路下用 r_skip_cnt<=3'd3**。

## 10. 调试方法：Python 模拟 vs iverilog 仿真（用户纠正过）

- 用户明确纠正过「为啥要用 Python 模拟，不能仿真吗」——**用 Python 重新实现一遍 RTL 逻辑，等于再引入一次复现错误**，不可靠。
- 正确分工：**纯组合逻辑的位序/往返**可以用 Python 精确模拟验证（本次「打包→128→24 反序无损」就是 Python 算清的）；**带时序的 RTL**（FIFO 读、打拍、跨时钟域）必须用 iverilog 仿真真实 RTL，不复刻。
- 仿真 video_out 这类「读 DDR 流水线 + 异步 FIFO + 解包打拍」的链路，坑：① video_out 的读触发在复位释放后立即（FIFO 空），会抢在打包填 DDR 前读空数据 → 给 video_out 独立复位，打包完成后再释放；② vsync 下降沿触发 FIFO 复位，会清空已读的数据 → vsync 先来（复位），再等读触发填满，最后 de 拉高；③ 像素激励要用 24bit（reg [23:0]），用 8bit 会让 96bit 只填低 32 位、解包输出全 0。

## 11. bg_read 消隐期读状态机实现（已实现并仿真验证）

架构：行块交替读（cur 行 240 个 128bit → bg 行 240 个 → 比较 → 下一行）→ 两个 w128_d512_fifo 缓存一行 → 3/4 节流同步弹（解包 128→96 的输入节奏）→ 两路 data_128bit_to_96bit 解包 → 96bit 逐拍比较（4 像素/拍，任一通道 |Δ|>40 判前景）→ 每 10 个 96bit 攒 40bit 字写 ERAM 0~23039 顺序递增（行对齐自动）。读命令避让写忙（I_video_in_wr_busy），返回按 mod-480 计数路由（0~239=cur 写 cur FIFO，240~479=bg 写 bg FIFO——返回顺序与命令顺序严格一致，与延迟拍数无关）。

**触发必须用「场消隐检测」不能用 vsync**：vsync 在 1084 行、距下一帧显示只剩 0.8ms < 读两帧 3.57ms。场消隐检测 = de 连续低超一整行（1650 拍；行消隐仅 370 拍不会误触）→ 场消隐电平（4.2ms 宽，跨域采样绝不丢）→ DDR 域打 3 拍上升沿触发。跨域信号用电平不用窄脉冲（脉冲宽 < 目标时钟周期会采丢）。

**实现坑（仿真逐项抓出，全是真 bug）**：

1. **读总数计数不能「到顶清零」**：`S_rd_total == TOTAL-1` 时清零会让「停止条件 rd_total==TOTAL」永不成立 → 读永不停止。正确：计数只加不清（blank_trig 时清），停止条件 = 「发出最后一个命令（rd_total==TOTAL-1 且 rd_en&&ready）」直接拉低 active，rd_en 条件用 `rd_total != TOTAL` 封顶。
2. **「读完」≠「写完」**：读返回完成时比较流水线（FIFO→解包→攒字）还有几十拍尾巴。首轮写满标志（叠加使能）必须判定「写完第 N 个字」（wr_en && wr_addr==最后一字），不能判定读返回计数。
3. **行弹条件不能拿水位当持续条件**：`fifo_num >= 240` 作为行开始条件对，但弹 1 个就 <240 立即失效 → 只弹 1 对。行内用「行弹计数器」（弹满 240 对回 0）做持续条件。
4. **行尾必须强制 1 拍空洞**：解包模块的 pending D（每 3 个 128bit 组的第 4 个 96bit）只在「输入空洞拍」输出——行尾无缝衔接时下一行第一个输入会吃掉 pending 位 → 每帧尾丢数据（差 2 个 96bit = 差 1 字）。行尾最后一对弹出后强制停拍（S_row_gap），给 D 输出留拍。
5. **解包输入 valid 必须接 FIFO 的 valid 输出（与 dout 同拍），不能接弹信号 re**：re 当拍数据还没出来，接 re 会错位 1 拍（帧头数据垃圾、帧尾丢数据）。帧头复位信号（frame_start）则要提前到弹拍（弹拍 valid=0 正好复位 cnt，数据拍 cnt 已归 0；若用数据拍复位，复位拍 cnt 还是 X → case X 丢第一个输出）。
6. **写忙打断读返回 → 行尾 FIFO 空拍拒弹丢数据**：弹使能的行内条件必须同时门控两 FIFO 水位 ≥1（空拍不弹、数据晚到后继续弹），行弹计数器只在真弹时递增——行边界不错乱（等的是本行最后一个晚到的数据）。
7. **帧开始无条件清场（读不满帧时 mod/行弹计数跨帧错乱，实锤）**：读不满帧（压缩帧/仲裁打断/带宽不足）时 active 保持、mod 与行弹计数连续滚入下一帧 → 新帧数据从错位 mod 开始路由 → cur/bg 分界乱、比较全错。修复：I_frame_start 无条件复位 mod、读/返回计数、FIFO（复位宽度 > 读延迟 40 拍）、解包 pending、行弹计数；攒字器写地址回半帧起点（读不满帧 half_sel 未翻转 → 重写同半帧，数据从头来）；清场期停读（rd_en 门控 abort）+ busy 降让仲裁。读满帧时清场无害（FIFO 已弹空，仅延迟启动约 3µs）。
8. **显示期水位门控在消隐期会饿死 bg（双阈值错峰的死锁带，实锤）**：vo 在消隐期不消耗 → 等效水位冻结在显示期末值；若该值落在「vo 触发水位 ~ bg 放行水位」之间的死锁带（vo 不触发读批、bg 被门控），bg 饿死整个场消隐期（浪费约 0.66ms 窗口），直到显示期 vo 消耗把水位压到触发点才解死锁。修复：水位门控只在显示期生效——de 电平跨域打 3 拍做成窗口信号，`room = disp_win ? (level>=300) : 1'b1`（消隐期直接放行）。行消隐期 de 低同样放行，bg 抢批最多消耗 vo 批长量级、远小于 FIFO 缓冲，安全。

## 12. 仿真 stub 的坑（自写 DDR/FIFO 行为模型必踩）

- **FIFO stub 指针位宽 = log2(深度)**：512 深用 9 位指针（自动回绕），用 10 位会越界读写 X——长时间仿真才暴露（跑 345600 拍后指针越过 511），现象是数据流中途变 X。
- **FIFO 水位 cnt 同拍读写合并更新**：`cnt <= cnt + (we?1:0) - (re?1:0)`；两个独立 if 分支的非阻塞赋值会互相覆盖，水位错乱导致弹条件永远不满足（数据流卡死，只写几个字就停）。
- **DDR 读模型用「命令队列 + 固定延迟 + 函数式数据」**：rd_data = f(addr)（不真存 32M 深数组），延迟拍数可缩短（如 40 拍改 2 拍）加速仿真——路由逻辑只依赖保序、不依赖具体延迟。
- **TB 数据图案位序必须与 RTL 约定一致**（96bit [23:0]=最左像素、[95:72]=最右）：图案像素序列构造反了会得到「周期 4 的 9EF7 模式」这类错位假象，误判 RTL 有 bug。先打印前几个输出核对位序，再怀疑 RTL。
- 定位「差 2 个输出」类尾部丢失：按行统计输出数（行弹计数器当边界）+ 层次引用（u_mod.signal）打印内部信号，别用整帧总数猜。

## 14. 整帧读终版（2026-11-03 下板验证，根治分段读细线/停止线）

分段读（第 11 节状态机）段与段交界处读/写/显示相位错开 → 交界撕裂细线（画面 1/3、2/3 处）；读不满段 → 停止行以下黑线。终版改为整帧读：

- **cap 恒值 336000 拍**（= 700 行×480 拍，3.36ms < 4.26ms 消隐期），`wire [18:0] S_total_cap = 19'd336000`——无分段、无 half_sel 轮转（half_sel 保留声明恒 0，写侧/统计分组 case 恒走 0 分支，最小改动）
- 每帧从帧头连续读满 700 行，读满自停（S_rd_active 清 0）、下帧头（I_frame_start）重启；S_frame_off 18bit（0~172799）、S_rd_total/S_total_cap_reg 19bit
- **底部 20 行放弃不涂白**：336000/480=700 行，牺牲画面最下 2.8% 换消隐余量 0.9ms——细线是全场可见的机制性撕裂，底部 20 行视觉影响小（外接框/质心仍有效），值得。读 720 行（cap 345600）余量仅 0.8ms，现场温度/时序波动下有拖尾风险
- **配套① S_vo_room 显示期完全禁 bg 读**：`I_disp_win ? 1'b0 : 1'b1`——原「水位≥260 放行」会让读不满的 bg 拖尾跨进显示期抢 grant 挡 vo 预读 → 顶部错位
- **配套② 写地址帧头复位 0**（原复位到 S_fg_half_base 段基址）：`S_fg_wr_addr_int <= 15'd0`，写拍递增封顶 23039，整帧顺序写满 ERAM

## 13. ERAM 原语直接例化 + TD 常量位压缩

- **PH1P_LOGIC_ERAM 可直接在用户源码例化**（无需 TD IP 封装）：位宽 40 恰好匹配「512×40」配置、深度 23040 由 TD mapper 自动级联 45 块（GUI 生成的 65536 深 IP 也是单原语 + mapper 级联，深度不必取 2 的幂）。参数照抄现有 IP 的 RTL：ASYNC 双口用 CLKMODE="ASYNC" + ASYNC_RESET_RELEASE 双 "ASYNC"；深级联用 IMPLEMENT="20K"（不用 "20K(FAST)"）。
- **⚠️ EMB 报告比预期少 = TD 压缩了写数据中的常量位**：日志 SYN-2593「A-width N due to unused data out」+「Optimize constant input of 1 erams」——debug 图案里恒 0 的位段不占存储（如 {addr,5'd0,addr,5'd0} 的两个 5'd0 → 40bit 压 30bit → 45 块变 34 块）。功能正确（读出自动补 0、自检通过），但**正式数据全动态后会实占满块数——ERAM 预算验证必须等正式数据接入再做，不能拿 debug 版 EMB 当预算依据**。
