# 仿真通过但下板失败 —— 根因排查清单

适用：功能/行为仿真（iverilog/vvp）全过，但板子现象不对（花屏/错位/无响应/固定错/计数异常）。这是与「二分诊断」正交的排查框架：二分找病根层，本清单找病根类型。

## 六大根因（按概率排）

0. **TD 隐式网拆网（仿真正常、实机功能全断的头号嫌疑，2026-10-26 实锤）**：wire 先使用后声明时 TD 建「隐式网」，若后面的声明带初始化（`wire x = expr`），TD 把驱动挂到新网、隐式网保持无驱动 → 综合日志 `SYN-5013 Undriven net` + `SYN-5025 Using 0 for all undriven pins and nets`（**无驱动网被接 0**）→ 功能恒 0（如 bg 读计数 0000）。iverilog 会把隐式网与后续声明合并 → 仿真正常。规律：**`wire x = expr` 写在 x 的使用之后必断；纯 `wire x;` 声明即使在后也安全（TD 合并）**。**reg 先使用后声明是同类隐患**（诊断锁存 reg 在数码管 case 使用之后才声明，实测同样触发隐式网）——扫描时 reg 声明也纳入比对。排查：编译后必 grep 日志 `HDL-7225 already implicitly declared` / `SYN-5013 Undriven` / `SYN-5025 Using 0`；修复：wire 一律先声明后使用，驱动放 assign；reg 声明行前移到首个使用点之前。
   - **全工程扫描法（几分钟扫完，零编译成本）**：脚本先剥离块/行注释，再逐行匹配 `^\s*wire\s+(?:\[[^\]]*\]\s+)?(\w+)\s*=`（带初始化的 wire 声明），对每个声明比对「声明行之前」该标识符是否已出现。误报排除（实测五类，逐一人工看过再动代码）：数字字面量（`14'd0` 匹配到 `d0`，正则 `(?<![\w'])` 排除前导引号）、function/task 局部 reg（gx_pos 在 function 内声明）、parameter 名（`wire [DATA_WIDTH-1:0]` 被当成 wire 声明）、注释行（`********wire signals********` 风格分隔注释）、模块名/端口名（module key_pulse、output reg O_iic_bus_error 的 ANSI 端口声明）。扫描结果与 TD 日志 HDL-5373（identifier used before its declaration）交叉验证。
   - **前移声明必查依赖链**（2026-10-26 实锤，isp_top algo_tlast）：把 `wire x = expr` 前移到使用点之前时，expr 引用的每个信号（wire/reg/parameter）的声明位置也必须在新位置之前，否则制造新的先使用后声明。依赖声明散落后面时（algo_mode_2d/sobel_tuser/bpc_tuser 都在 123~236 行），前移会连环搬动——**若该点历史上 TD 从未报过 HDL-7225/5373 且实机正常，说明 TD 对它走了合并、不拆网，保持原样比前移更安全**。判据：TD 只对「隐式网 + 带初始化声明」拆网，`assign 端口 = wire_declared_later` 的 RHS 隐式网若从未出现在 Undriven 列表 = 已合并，不动。
   - **reg 声明前移只移声明行、always 赋值块留原位**：always 块常引用声明位置更靠后的信号（如诊断锁存 always 引用后文才声明的 vsync 脉冲线），整块前移会制造新的先使用后声明——只把 `reg x, y, z;` 一行提到使用点前，驱动它的 always 留在原处（声明在前、赋值在后，语义不变且零新隐患）。wire=expr 与它依赖的 reg+always 构成闭环时（清场信号 `wire S_abort_active = (S_abort_cnt != 0)` 依赖 reg S_abort_cnt），把「reg 声明 + always + wire」作为整体单元一起前移，单元内部顺序不变。
   - **发现拆网点先查下游消费定优先级**：该信号若在顶层悬空/无消费者 = 无当前功能影响但属潜伏雷，顺手修；有消费者 = 功能恒 0 必须修。别因为「画面正常」就跳过——tlast/行结束类信号常常当前没人接、以后接上就踩。
   - **修复后复查**：patch 工具在 CRLF+中文注释的 Verilog 文件上 context_aware 近似匹配会偏移，拆 wire 声明时可能残留重复声明行——改完 grep 该符号确认全文件唯一，再走编译。
   - **patch/脚本替换「报 success ≠ 落盘」**（2026-10-26 实锤，S_disp_win 定义块）：替换目标文本与磁盘文件实际写法不一致时（如文件已从「声明即赋值」改成「纯声明+assign」，旧文本的 replace 静默无操作），写入后必须**读回文件验证目标字符串存在且位置正确**（定义行 < 使用行），再启动编译。落盘验证缺失的代价：bit 编出来了、时序全绿，但新信号被 TD 当 Undriven 接 0 → 功能残缺产物，只能废掉重编 45 分钟。
   - **修复后复验（2026-10-26 实锤，nogrant isp_top algo_tlast）**：把带初始化声明改成「纯 wire 声明 + assign」后，TD 日志 **HDL-5373 警告仍会报**（TD 对「使用早于声明」无条件报，纯声明在后也会报）——**但行为已正确（TD 会合并隐式网）**。复验看 **SYN-5013 Undriven 列表里目标网是否消失**，不是看 HDL-5373 是否消失：修复前 O_tlast 在 Undriven 列表（恒 0 实锤），修复后列表里已无 O_tlast、HDL-5373 仍在 = 修复生效。别再为消除 HDL-5373 警告把声明挪前重编译一次。
   - **SYN 完成即止损（先查日志再放行 PHY，2026-10-26 实锤）**：SYN 完成判据 = `.opt_gate.end.f` 出现（read_design→opt_rtl→opt_gate 三步递进）。此时立即 `ls -t td_*.log | head -1` 找**本次**日志 grep 隐式网三连——**目录里残留历史 td_*.log，grep 到旧日志会误判干净、放行一个带拆网的 PHY**。查到隐式网/Undriven → 立即杀编译进程止损（PHY 还没跑，省 20 分钟），修完重编。bit 生成、时序全绿 ≠ 产物可用——门控信号被接 0 的 bit 下了也白下，发现必须作废。
   - **SYN-5025 剩余条逐条甄别、别为 IP 固有警告卡发布**：三连清零后若还剩若干 `SYN-5025 Using 0`，对应着上面的 `SYN-5011 Undriven pin`——grep SYN-5011 看悬空 pin 归属哪个例化：官方 IP 内核的字节使能（BRAM 的 bea/beb）和未用引脚悬空接 0 是 IP 固有配置、无害（历史每次编译都有）；**只有关键功能信号（门控/使能/帧开始类）在 Undriven 列表里才是废品判据**。发布判据 = 递进标记 ✓ + SWNS 正 ✓ + 三连里关键信号为零 ✓。
   - **ERROR/CRITICAL 级日志同样逐条归类、只甄别新增**：编译完 grep 全部 ERROR/CRITICAL 行 `sort | uniq -c` 逐条对基线。本工程已知无害项两族：① SYN-8411 VCO 超范围——1600 参数组要求 PLL VCO 跑到 2400M、超 FPGA PLL 上限 2000M，PLL 失败回退（参数从未真正生效的实锤特征，不是编译失败）；② USR-8124/8130/8159 rename_clock/derive_clocks 失败——sdc 里的 DDR 时钟名与实际回退后的时钟不匹配。这两族每次编译都出现，别当新问题；只有不在基线清单里的 ERROR 才需要停下来查。
   - **「声明被同行注释吞掉」变体（批量删行事故第二现场，2026-11-03 实锤 S_bcd_sobel_threshold）**：批量 regex 删端口/删行后，声明行可能与上一行的「//...」注释粘在同一行——`wire [10:0] S_sobel_threshold; //注释 wire [15:0] S_bcd_sobel_threshold;` 后半段声明被注释吞掉 → wire 根本不存在 → iverilog/TD 都不报错（隐式 wire 合法）→ 16bit 输出接隐式 1bit wire 高位截断 → 数码管显示垃圾（0x1FFE 非法 BCD）、按键调了不显示。与「先使用后声明」不同：这里不是位置问题而是声明消失，隐式网三连（HDL-7225/5013/5025）都不会报——**批量编辑后必须 grep 同行多声明模式**：`//[^\r\n]*(wire|reg|input|output)\b` 逐条人工甄别（注释里提到 wire/reg 字样的正常注释是误报），只有「注释后跟真实声明」才算事故。同源事故还可能把例化端口行整段注释掉（demosaic 历史教训）——凡批量删行事故，同行注释吞声明是必查第二现场。
   - **「彻底无驱动」变体（分支工程抄漏一行，2026-10-27 实锤 nogrant algo_valid）**：信号在例化点被消费（`.I_96b_valid(algo_valid)`）但全工程**不存在任何驱动**（无 `wire x =`、无 assign、无 always 赋值）——不是声明位置问题，是复制主线建 1080P 分支时整行抄漏。TD 建隐式网后按 Undriven 接 0 → 该链输出恒 0（ISP 永不输出 → 写计数恒 0、画面全是 DDR 旧残留）。特征判读：帧开始锁存=1（tuser 链活）+ 写累计=0 + FIFO 满=0 → 断点必在「帧同步生成」与「FIFO 写」之间的数据路径上。排查法（零编译成本）：grep 信号名全文件——只有例化引用、无驱动 = 实锤；**对照参考工程 grep 同名信号**（主线有 `wire algo_valid = ...` 一行、分支没有）比整文件 diff 可靠——大 diff 眼扫/截断会漏看单行差异。分支工程「抄漏」类 bug 首选按信号名 grep 对照，不是 diff。
   - **杀编译先杀全树 + 确认进程归属（多会话并行编译时）**：杀 WSL 侧 bash 不会带走 Windows 侧的 td_commands_prompt.exe/TD 进程（cmd.exe 子进程树独立存活），残留进程继续写工程目录并占 license——重编前 `tasklist.exe | grep -i td` 确认全停。**杀 TD 前先确认归属**：多个 Hermes 会话并行编译时（主线 + 其他版本同时排编），Windows 侧 TD 可能是另一会话的编译，误杀让对方前功尽弃。归属确认：进程启动时间 vs 本会话编译启动时间、对方会话消息、`ls -t phy_1/*.db` 看谁在写。不同工程目录可并行但建议错开时间避 license；同一工程目录绝不并行。

1. **未约束的跨时钟域（CDC）**：多比特总线直接打拍跨域——仿真里所有比特同时翻转，板子上各比特布线延迟不同，采样拍会采到中间态 → 数据错乱。特征：大部分正常、偶发错；仿真永远复现不了。修复：多比特跨域用格雷码或异步 FIFO，单比特控制信号打 2 拍。
2. **依赖上电初始值**：`reg x = 初值` 的声明初始化在 FPGA 上不可靠；更隐蔽的是「没复位就用」的寄存器，某次上电飘非 0 才暴露。修复：初始值放进复位分支显式给出。
3. **复位释放时序**：复位撤销不在每个时钟域同步打拍（异步复位同步释放铁律），不同触发器在不同时钟沿退出复位 → 状态机进非法态。特征：上电/冷启动挂、按复位可能好。
4. **真实时序违例**：WNS 为正不代表收敛——没约束的路径（unconstrained path）不保证时序，温度/电压变化才发作。检查 sdc 是否覆盖所有跨时钟路径。
   - **hold 违例（HWNS 负）先查三件事再决定动不动**（2026-10-28 实锤）：编译后验证不能只看 SWNS，final_timing.rpt 顶部的 HWNS/HTNS 也要看（1 Viol Endpoints 就说明有 hold 违例）。查到 hold 违例先看：① 路径归属——违例段的 Begin/End Point 在不在本次改动过的模块上（与改动无关的旧链别急着修）；② Clock Uncertainty 行构成——`sdc uncertainty: 0.000, default uncertainty: 0.050` 表示 sdc 从未显式设过 set_clock_uncertainty，TD 把默认 0.050ns 计入 hold 检查——负 slack 幅度 ≈ −default uncertainty 且数据路径极短（0.2ns 级、1 级逻辑）时，按 0 uncertainty 计恰好压线 = 伪违例；③ 该链上版同构是否下板正常。三条全中 → 直接下板（50ps 量级在实机温压裕量内），实机异常再回来加约束——注意任何 sdc 改动都要重跑 syn 再 phy（约 55 分钟），不值得为伪违例空转。**先 grep 路径详情 Slack 列表再下结论**：Clock Summary 表里某时钟 HWNS 为负 ≠ 存在路径级 hold 违例——路径详情全正而表值负 = inter-clock hold 统计项（跨域同步链），按上述三条判定后仍可下板；只有路径详情出现负 slack 行才需要逐路径修。
5. **引脚/电平约束错**：全死类，最先排除。
6. **帧级状态机的帧开始复位链缺失（2026-10-27 白块实锤）**：每帧重复流程的模块（帧级读链/比较/攒字）里，所有「跨帧累积」状态必须在新帧开始（I_frame_start/vsync）无条件复位，漏一项就跨帧残留——三类实测：
   - (a) **行内偏移/段计数**：读满帧后残留（frame_off 停 86400）→ 下一帧段尾切行地址全错 → 读相邻帧数据 → 白块，且每帧递推、溢出回绕 → 块位置每帧变 = 闪；
   - (b) **段相位/交替相位**：读不满帧时残留 → 下一帧 cur/bg 段界错乱 → 跳变；
   - (c) **返回路由计数（mod）在清场期仍递增**：读不满帧在消隐期读中被 vsync 打断时，上一帧在途返回（DDR 延迟 ~40 拍）在清场 300 拍内到达仍计数 → 新帧帧头对齐偏移 = 在途数 → 块状错位。修：递增加 `&& !清场期` 门控。
   特征：白线→白块粒度变细 + 闪 + 读计数帧间跳变；首帧/部分帧正常。排查：列清单——模块里每个「每拍递增或随帧推进」的状态量，逐个确认帧开始复位路径；仿真必须覆盖「读不满帧 + 消隐期读中被 vsync 打断」场景（显示期碎批读自然停、无在途的旧 tb 永远复现不了），帧循环边界与 vsync 对齐、坏帧注入与模型赋值互斥（见 sim-debug-methodology.md）。

## 排查顺序（纯代码检查，零编译成本）

1. 复位树：复位源 → 各时钟域——有没有每域同步释放链（本项目实测：S_rst_n 直接用 PLL lock 全局异步复位、无同步释放，属第 3 类嫌疑，但因现象是确定性的而排在后面）
2. `grep -rn "reg .*= " --include="*.v"` 声明初始化清单
3. 多比特跨域路径：指针/模式/计数值怎么跨的——格雷码？FIFO？还是裸打拍
4. **工程文件清单核对（编译前 5 分钟，防 black box/文件漏登记，2026-10-28 实测）**：TD 综合读 .prj 文件列表（不是 .al——只改 .al 新文件不生效），新增源文件必须 .al + syn_1/.prj + phy_1/.prj 三处都登记。核对脚本：正则提取 .prj 全部 `File Path="..."` → 与磁盘文件逐一 exists 比对。两个方向：工程引用但磁盘缺失 = 必失败；磁盘有但 .prj 未引用的逐个甄别——该文件若被任何 .v 例化（grep 模块名）就必须登记否则 black box；无任何例化且历史从未进过 .al = 废弃模块（如旧版 ae_auto 被 ae_set 合并取代），不登记才是对的，别把它塞回工程。

## 现象特征匹配

- 固定位置/确定性错 = 逻辑层确定性 bug（地址/指针/打包对齐），别往 CDC 随机性上推
- **现象恒定 = 结构错位（2026-10-29 实锤）**：错位/伪影量不随摄像头内容、光照、运动变化 → 排除算法/阈值/亚稳态/竞争，锁定位置映射链固定相位（打拍对齐/地址时序/复位相位），错位量 = 固定拍数/字数。典型：攒字器 wr_data/wr_en/wr_addr 同拍非阻塞赋值（addr<=addr+1 在 en 拍已生效）→ ERAM 采样 addr+1 → 字 k 写进 addr+1 → 标记整体平移 1 字（40 像素）+ 首地址永远写不到。修复：地址递增放写拍（独立 always 块——写拍与下一字首组同拍，else-if 链会吞递增、同块独立 if 会双重赋值竞争）。**tb 判据必须覆盖「数据与地址的对应」**（如首写地址==base 类判据），只查数据内容/位序抓不出平移类 bug（全套仿真全绿、下板恒定错位的实锤案例）。写命令打 1 拍时（wr_en<=组合逻辑打拍），仲裁 busy 若用写批 valid（不打拍）→ valid 降拍仲裁切走、写命令尾拍与读命令同拍 → DDR 写优先吞读命令 → 标签 FIFO 压弹错位全链崩；修复 = 读使能写拍门控三处（顶层 rd_en && !wr_en、vo grant && !wr_en、bg 写拍避让端口）+ 仲裁 busy 展宽到写命令拍。
- **模块组合输出（长路径）被下游消费时，tb 测不出 TD 的寄存器插入——实机「右错位变左错位」的另一半**：O_data 写成组合输出（1280bit 移位寄存器 OR）→ 下游攒字器写数据路径 = 该组合 + 选择逻辑，路径长 → TD 综合为收敛在数据链插 1 拍 → dia 比 addra 晚 1 拍采样 → 字 k−1 写进 addr k → 标记整体左移 1 字（与地址 +1 的右移源方向相反、量级相同——修掉一个后另一个反向暴露，指纹 = 错位方向翻转且量几乎不变）。修复 = 模块输出寄存器化（O_data/O_valid 同拍打 1 拍）：写数据变纯寄存器输出短路径，TD 不再插拍。风格规则：**输出端口一律寄存器化**——组合输出端口是 iverilog 行为仿真永远覆盖不到的实机时序隐患（TD 插拍/重定时只在综合时发生）。**配套延迟账**：输出寄存后数据链延迟 +1（如 644→645），valid 门控链必须同步 +1 保持同拍——曾把 valid 链误缩 1 位（643+1=644 ≠ 数据 645）→ valid 早数据 1 拍 → 攒字器 +1 组偏移 4 像素，tb 首字 0xF0（预期 0x0F）秒抓；延迟账公式 = 「数据链拍数 + 输出寄存拍数 == valid 链拍数 + 输出寄存拍数」。**改 RTL 时序行为后必须同步核对 tb 判据的期望值**：tb 判据按旧行为写的「首字写拍 addr=1」在地址修复后变成 addr=0，判据抓到第 2 个字（全 0 数据）报假 FAIL——假警报指纹 = 「修复生效方向正确但 tb 报 FAIL」，先查判据里的拍数/地址期望值是否随 RTL 行为一起改。
- **恒定整字平移 = 写侧地址错 1 拍；读侧插拍做不出恒定平移（判别规则）**：读地址组合路径被 TD 插 1 拍的效果 = 每个字边界的第 0 列显示上一字内容（40 像素一列的周期错位），不是整块平移——addr 晚 1 拍后 mark 用的 col 链不受影响，只有 col==0 的拍错 1 字。实测「整块恒定左移 1 字 + 卷绕」只能是写侧：字 k 写进地址 k-1。判别口诀：恒定平移查写侧三件套时序，字边界周期单列错位查读侧地址链。**逐拍账推演出「周期性」结论时先和实测的「恒定性」对一下**——账算错时方向性特征比量级更早暴露（本次「读侧插拍」假设就是用户一句提问触发重对账被推翻，差点又修错层）。
- **写三件套（addr/data/en）显式同拍打 1 拍直连 ERAM/宏端口（防插拍兜底修法）**：写地址路径（addr+1 加法器+复位选择）被 TD 插拍 = 字 k 写进 k-1 = 恒定左移 1 字。修复 = 内部三件套 int 值 + 输出级三件套 q <= int 拍前值：写拍 T 内部 en=1，q 在 T+1 拍 = {addr=字 k 正确地址, data=字 k, en=1} → ERAM 采样 q 正确落位；tb 判据兼容（写拍显示 addr 拍前值）。有效原因：三件套都是寄存器直连宏端口，路径最短，TD 无插拍空间；即使「插拍具体在哪条线」猜错，此修法兜底全对齐。**组合读地址长路径的同类修法 = 预读+移位寄存器读结构**：地址全寄存器化输出；消隐期每拍发本行字 0 地址并装 shift（第一 de 拍 shift=字 0）；行中 col 37 拍发下一字地址（ERAM 1 拍 → 字末拍 col 39 装 shift）；其余 de 拍 shift 右移 1 位、mark=shift[0]。延迟全显式、无插拍空间，比「组合地址+col 打拍对齐」稳（后者组合长路径仍有插拍风险，手工对账易错）。
- 偶发错/温度相关 = CDC 或时序违例
- 「不相关的开关/显示内容改变现象」= 综合行为或间接链，用引用剥离法（见 ddr-debug-bisection.md）
- **静止背景物被涂白 = 比较数据两帧相对错位（不是叠加位置映射错）**：背景减除里静止物体 cur≈bg 本应零差，出现涂白且只沿物体一边偏 = cur 与 bg 两帧数据行内相对错位 N 像素——平坦区 N 像素内内容相同差不出阈值，只有边缘（水管/边框）有差 → 局部涂白+白点；若背景帧整体错位则是大面积涂白。叠加位置映射错（写地址/ERAM 列映射）只平移涂白位置、不会让静止物产生差异——按「静止物是否涂白」先二分「数据错位」vs「映射错位」两类，别修错层。**卷绕指纹**：变化在左边界涂白却出现在右边界、随目标左移循环 = 错位量恒定且 mod 行宽（左移 N 像素卷绕），恒定偏移源的直接证据。

## 读数据隔离：标签 FIFO 用 IP 实现（在途窗口方案已被仿真否决）

- **大深度标签 FIFO（reg 数组）在实机会被 TD 综合成 BRAM，读延迟比 tb 模型多 1 拍**：tb 里 reg 数组组合读 + 同步锁存 = 1 拍延迟，实机 BRAM 读 = 2 拍 → rd_tag 与 rd_valid_d1 对齐错 1 拍 → 收数门控/计数错 1 → 帧头误丢 1 字 → 比较数据整体左移 1 字。指纹：tb 全绿、实机恒定 1 字错位；仿真模型与综合器对同一数组的读延迟约定不同。
- **正解 = 标签 FIFO 改用 TD 的软 FIFO IP 例化（读延迟由 IP 固定，综合无变数）**：SHOW_AHEAD+NOREG 的软 FIFO 读时序 = re 拍后 1 拍 dout，与 rd_valid_d1（返回落地打 1 拍）严格同拍。数据位宽复用现有 IP 例化即可（128bit 数据写 {127'b0, tag}，读 dout[0]）。深度按在途峰值放余量：读批 240 拍 + 返回拖尾，512 深足够（批边界 + 写拍避让下真实在途 ≈ 40~300，远小于理论极端 552）。官方板子资料佐证：官方示例所有 FIFO 都是 soft_fifo IP 例化（从不推断数组）；官方 PH1P35 DDR IP 的 Native AXI 读通道只有 rlast（突发结束标志）没有 ID——官方对读数据归属的哲学同样是「保序返回 + 上游配账」，标签+保序是唯一可行的路由结构。
- **「在途窗口」收数方案被仿真否决（勿再试）**：弃标签改「自己的在途命令数 >0 时到达的返回 = 自己的」只在批间完全串行时成立。真实系统帧内 vo/bg 读批交替，vo 批尾的 40 拍返回与 bg 批开始重叠——启动延迟只挡帧首残余、挡不住帧内每个交替批的尾返回 → bg 误收 vo 尾返回 → 比较数据大面积错位（real tb mis 从基线 368 飙到 10172）。窗口方案仅在「批间确定空闲期 > 最大返回延迟」的独占通道可用。

## 消隐读半帧方案的参数与判据核对

- **读量/偏移/写起点三个参数必须与行数口径互洽（乘法验证）**：HALF_OFF/OVERLAP_BASE 按「行 N×每行单位」硬算，与 HALF_LINES 行数凑「起点+行数=帧底」零越界（如 176×1920=337920、176+544=720 恰好到帧底）；起点差 2 行 = 越界读 2 行垃圾 + 写封顶污染 + 撕裂点漂移。注释与代码口径不一致时以乘法验证为准，别信注释。tb 的 DDR 模型按「地址低位线性编码」时测不出越界读（越界地址照样返回同编码数据）——越界断言要单独加（off>一帧即报，且加方向保护 addr>base 防 rp 翻转竞态窗口的无符号回绕假阳性）。
- **读满/状态翻转拍会毒化依赖同一状态位的组合判据**：half_sel 在「读满拍」立即翻转 → S_total_cap（组合）同步变另一半上限 → DRAIN 触发判据 (rd_total==cap) 恒不成立 → 帧尾排空永不执行（对称半帧两半上限相同时不暴露，非对称半帧 A/B 上限不同必中）。修法：读满拍置「锁存标志」（S_full_done），后续判据用锁存不用会翻转的源；帧开始清。通用规则：**状态位在拍内翻转后，任何「同拍之后仍依赖该状态位的组合表达式」都会读到新值——跨拍判据一律用锁存**。
- **改读写寻址方案（分段→整帧/半帧→全帧）后，所有按旧几何标定的派生常数逐个重算（fg_init 恒 0 实锤）**：fg_init 判据「写地址 ≥22920」按分段读 B2 段写满（23040 字）标定；整帧读 700 行写满只到 22400 → 判据永远达不到 → fg_init 恒 0 → 涂白+外接框叠加使能全关 = 整功能静默失活（「检测不出来」）。整帧读改完后 grep 全部旧方案常数（就绪判据/排空窗口/段基址/回绕点），按新几何逐个数乘重算。**行为仿真必须断言可观察门控信号（fg_init/叠加使能/就绪标志），不能只查数据计数器**——tb 查了读拍数 336000 全对、行 699 写满全 PASS，唯独 fg_init=0 没断言 → 仿真全绿实机功能死。列 tb 判据清单时逐个问：这个信号恒 0 会不会让整条功能链静默失活？会就加上断言。

## 计数异常直读法

- **仿真验证读链必须验证「数据内容与地址对应」，不能只验证计数**（2026-10-26 实锤）：bg 读地址行内不递增（240 个命令全发同一地址，缺每命令 +8）时，读计数照样精确 172800、伪数据模型照样跑通——只有「DDR 返回按地址低位编码 + 层次引用比对解包输出 cur/bg 数据流」的测试向量才能抓出。地址类 bug 现象特征：**计数对、画面内容错**（白线错位、手成线不成块）。写读链仿真时返回数据永远做成地址函数（enc = addr[5:0]），别用递增伪数据。


- 诊断计数和正常值的**比例**直接给机制线索：读计数 0x3F840=260160 = 正常 0x2A300=172800 的 1.5 倍 → 每帧多读半帧 → 帧边界处 FIFO 压着半帧旧数据、vsync 复位丢弃 → 错位。多出的部分 ≈ 半帧（差 960 字）不是整行数，说明不是「多读几行」而是读/消耗节奏失配。
- 小数倍率（1.5 倍）= 读写节奏与消耗不同步；地址错误是整块偏移或卷绕，不是 1.5 倍——倍率先定性再查代码。

## 「完全没启动」类（诊断计数恒 0、无任何动作）

- 特征：诊断计数恒 0（如 bg 读计数 0000）、无任何功能现象，但画面/其他链路正常。**计数恒 0 = 使能表达式从未为真（一个命令都没发出），不是「读得慢/窗口小」**——窗口小只会让计数停在中间值。
- 排查链三步：① 静态 grep 启动/使能信号在顶层的生成逻辑（脉冲合成、电平跨域同步链、复位值、门控残留）；② **集成仿真复现**（被测模块 + 仲裁器 + 顶层同步链 + 标签逻辑 + 延迟模型 + 邻居 busy 模型一起仿）——仿真里启动正常则逻辑层整体排除；③ 断点必在实机信号链（触发脉冲源/跨域同步链/引脚/时钟域复位），上启动链多位锁存诊断码一次编译定位（见 ddr-debug-bisection.md）。
- **vvp 仿真速度有限，帧周期按验证目标压缩**：真实帧周期 165 万拍 @100M × 多帧，vvp 跑不动（百秒级超时）。验证「启动链路」时把帧周期压到 30 万拍量级——启动验证只看「计数从 0 开始增长、grant 发放」，不需要真实帧长；带宽/读满/帧边界类验证才需要真实周期比例。仿真粒度按验证目标裁剪，别为验证启动跑真实帧长。
- 实机与仿真的系统性差异（仿真正常、实机恒 0）优先查「仿真里理想化的信号」：仿真里 vsync 波形手工给、SW4 电平直接给、ready 恒 1——实机上这三类信号（触发脉冲源、跨域同步链输出、背压信号）才是断点所在；画面正常只能证明相关时钟域活着，不能证明「这个域里为 bg 同步的那条链」活着（vo 用的 vsync 是 75M 域原信号，bg 用的是 DDR 域打拍链，两者独立）。
- **仿真通、实机恒 0 的第一检查永远是综合日志的隐式网三连**（HDL-7225 / SYN-5013 Undriven / SYN-5025 Using 0）：集成仿真+静态检查全过仍 0000 时，先 grep 这三条再谈信号链（2026-10-26 bg 读不启动的根因就是这个，静态+仿真都排除了逻辑层，最后是网表把 I_frame_start 接 0）。启动链多位锁存诊断（数码管 1 位 hex = 4 个锁存信号）能直接区分「信号到了 DDR 域」和「到达后没动作」两段断点。

## 行为级仿真复现下板现象（延迟链法）

读节奏/水位类 bug 的复现模型三要素：

- **延迟链数组**模拟「读命令 → 数据延迟 40 拍落地」：`delay_q[39]` 收新命令、`delay_q[0]` 落地进 FIFO 计数、每拍移位——比「写指针-读指针差 40」的队列写法简单且不易错（队列写法容易把延迟写成 0）
- **触发判定用滞后水位**：真实 wrusedw 反映的是已落地数据，不含在途——模型里读批结束后水位仍低、触发条件立刻再满足 → 批间不停、过度读
- **模型没 grant 节流时过度读到 ~100% 占空是预期**（真实系统被仲裁压到 1.5 倍）：复现「过度读」的定性结论即可，别纠结定量一致；消耗侧节奏按各时钟域换算清楚（HDMI 像素时钟拍 ≠ DDR 域拍）

修复方向：读触发判定加「在途计数」= 已发命令数 − 已落地数，水位判定改成（空余 ≥ 阈值 + 在途）；或读批结束后强制等 N 拍再判定触发。

**已验证的修复数值设计（「过度读」实修）**：判定式 `(wrusedw + 在途) <= 触发水位`，触发水位从 211（≈批长 240）降到 30——关键原则：**触发水位必须远低于批长**。若水位阈值接近批长（如 211），读批 240 拍期间消耗掉几十字，批结束后等效水位仍 ≤ 阈值 → 立即重触发，批间不停；阈值降到 30 后，批后等效水位 ≈240 远高于 30，必须等消耗把水位压下去才读下一批 → 读节奏 = 消耗节奏。仿真实测：修复前读计数 100% 占空、FIFO 恒满溢出；修复后读计数 ≈ 消耗量、FIFO 水位健康。注意等效水位最大 = 水位+在途 < 512（FIFO 深），9 位截断安全；FIFO 复位期（帧开始 300 拍）在途清零且 -1 加下溢保护，复位宽度须大于读数据延迟（40 拍）保证残余返回在复位期内全部落地丢弃。

## 集成仿真 tb 的四类自坑（模型错会误导定位，先自查模型再怀疑 RTL）

- **软 FIFO 行为模型：计数只许单次赋值**。we/re 同拍时 `cnt <= cnt+1` 和 `cnt <= cnt-1` 两条非阻塞同时存在 = 后者覆盖前者 → 计数只减不加 → empty 判定虚高 → 提前弹出未初始化地址（数据 X）。写法：`if(wr_ok && !rd_ok) cnt <= cnt+1; else if(rd_ok && !wr_ok) cnt <= cnt-1;`。优先直接用 TD IP 目录自带的 soft_fifo_*.v 行为模型替代手写。
- **tb 里「命令」与「标签压入」必须同拍组合**：标签 FIFO 压入条件在顶层是 `(vo_en || bg_en)` 组合（与 grant 同拍）。tb 里若把 vo 命令打 1 拍再压标签，命令拍与标签拍错开 → vo 批返回被标成 bg 标签 0 → bg 误收 vo 数据 → 仿真里 50% 假错位。真实顶层组合时序 ≠ tb 打拍时序时，先对齐 tb。
- **iverilog 的 $time 以 timescale 的 precision（ps）计**：1ns/1ps 下 7ms = 7000000000，采样窗口条件写 `$time > 7000000` 会采到 7µs 的复位期（本会话浪费两轮定位）。打印调试对不上时间轴时先验证 $time 单位（跑 N 拍打印 $time 除拍数）。
- **帧末瞬时采样会被 vsync 清零吞掉**：帧末读计数在 vsync 拍清零重计，`repeat(帧拍数)` 后采样 dbg 计数值 = 清零后几拍的残值（常为 0 或消隐尾量），「读满判据」要用帧内累计最大值或帧中段采样，别用帧末瞬时值。
- **iverilog 的 `always @(*)` 在敏感输入从未变化时全程不触发（t=0 也不执行）→ 组合输出恒 X**。tb 给组合块输入接常量激励（如乒乓指针 rp 恒 0）时，case 基址选择器永不被求值 → 依赖它的地址/数据全 X；且 X 只染依赖该组合输出的那半数据（cur 段 X、常量基址的 bg 段正常），现象是「一半数据正常一半 X」= 仿真假象，实机综合成 MUX 无此问题。规律：tb 激励必须让每个组合块的输入真实翻转（真实场景这些信号本来就变）；排查「组合输出 X 但输入非 X」的死结：加变化监视 `always @(信号) $display` 看驱动块是否执行过（从未打印 = 块没跑），再把该组合块单独抽最小 tb 重现，分清「块写法问题」还是「激励/环境行为」——别在整机仿真里猜。
- **tb 资源模型速率必须贴近真实消耗值**：vo 消耗模型写 0.5 字/拍（真实 HDMI 显示 ≈0.14）会让 vo 读批触发频率虚高 3.5 倍 → vo 占满仲裁 → bg 饿死 → 假阴性（bg 读不满，误判 RTL 门控过严）。建模前先按带宽公式算真实速率（消耗率 = 显示字数/显示期拍数），再写模型；发现「某通道应读满却读不满」先复核各模型速率与真实值是否同量级，再怀疑 RTL。
- **计数器位宽先验算上限再声明**：line_phase 11 位（max 2047）装不下 2199 → `==2199` 永假 → 行计数死锁 → vsync 永不拉高 → tb 静默 TIMEOUT（日志只有几行看不出死因）。声明计数器前心算上限：周期值 > 2^位宽−1 即必断。
- **iverilog 条件编译不支持 `` `if 表达式 ``（被解析成 `ifdef 未定义宏）**：报错指纹「macro if undefined」+「`elsif without a matching `ifdef」。用 `` `ifdef MODE_A / `elsif MODE_B / `else `` 结构，编译时 -DMODE_A 选档。
- **档位对比定位法（mini tb 秒级定档）**：时序/相位类 bug 用「桩激励 + 判据」写 mini tb（如攒字器 + 连续 valid 桩 + 注入组 99），同一文件内条件编译三档位（递增放写拍/写拍后 1 拍/攒满拍），一次编译三个 vvp 秒级跑完——比在 full tb 里改 RTL 重跑 25 分钟快两个量级。判据 = 「注入标记落位地址+位」精确值，全 0/全 1 图案验证不了位置。
- **快 tb 判据要覆盖「帧头偏移」类 bug**：用「行首注入 + 首字落位」判据（组 0 应落 bit3:0），幽灵拍/组偏移会让落位变 bit7:4 秒抓；判据只查行中位置会漏帧头偏移。

## 串口诊断通道（数码管不够用时的实机数据直读）

- **用户偏好：错位/时序类实机问题用数据直读而非肉眼数像素**。数码管 1 位 hex = 4 个锁存信号；诊断量大时上串口。模式：uart_dbg_tx 模块（24M 域 115200 8N1，板子 tx=H1/rx=J1 LVCMOS33，引脚/驱动查板子资料包示例 16_uart_rs232），帧开始脉冲跨域打 2 拍取上升沿触发，每帧发 12 字节诊断帧：AA 55 | 半帧号 | fg_init | 关键地址低 8 | {valid,half,addr 高 7} | 读满率 3 字节 | SW4 | 预留 | EE。12 字节 @115200 ≈1ms，消隐期发完不占显示。**关键地址判据要选已知期望值**（首字写拍地址应=0/5632，非预期 = 错位实锤），发回字节一眼定位，比肉眼数像素强一个量级。发送状态机注意：起始位占满一个位周期（baud_cnt 满才发数据位），首字节直接锁存输入（当拍读 buf 是旧值）。
- **下板验证前不宣布「定位根因」**：综合行为类假设（插拍/BRAM 延迟/retiming）行为仿真永远测不到，连续「实锤」下板翻车的教训 → 一律说「最吻合假设」+ 优先兜底式修复（寄存器化输出消除插拍空间，即使插拍位置猜错也对齐）+ 预留诊断通道做下板二分，「定位成功」的宣布权留给下板结果。
- **报 ETA 前先 date 锚定当前时刻**再按编译耗时口径推算，别用记忆里的启动时间心算（长会话中多次算错被用户纠正）。

## 板测反馈处理纪律（用户明确要求，2026-11-02 实锤）

- **「分析完别着急编译」**：板测反馈多个症状时，先逐症状 grep 代码定位根因、改完代码 + 仿真全过后把分析与方案讲给用户，**等确认再启动编译**；分析完直接开编会被拦。多会话并行时别的会话编译快完成时用户会说「先别编译」，等对方结果合并后再编自己的。
- **用户说「这是下一版的任务」时，未授权的新功能改动立即 git restore 回退，单版本单目标收敛**：当前版本调试中用户提出「顺手做 X」的需求，实现后用户可能判定「X 是下一版任务、先让当前目标跑通」——此时把 X 的改动从工作区全部回退（git restore 到当前编译的 commit），保证工作区 = 当前版本基线，X 留到当前版下板验证后再重做（回退成本几分钟，混在工作区里才是风险：下次编译可能把它带进去、或它未完成的状态污染当前版的定位）。回退后向用户确认工作区状态等于正在编译的版本。
- **板测数值与源码矛盾时，先查 bit 时间戳是否旧 bit + 显示域换算，再怀疑 RTL**：本项目阈值有两个显示域并存——OSD 显示 mag8 域（11bit 阈值>>3，源码 512 在 OSD 显示 128 属正常）、数码管 BCD 显示 11bit 原值。用户报「初值 128 但源码 512」就是没对齐显示域，不是代码没生效。
- **数码管占位 {16'hFFFF,bcd} 会显示成 FFFF 前缀**：seg7 把 0xF 译码成字母 F（灭灯段码才是 8'hFF）——占位位要用灭灯需改 seg7 的 0xF 译码，别指望 0xF 天然灭灯。
- **自适应阈值的仿真验证必须含平坦区主导的真实分布帧**：人工构造场景（全图有弱边缘）验证通过后，真实 720P 画面 90%+ 像素梯度≈0 把均值公式拉垮——仿真场景的像素分布要和实机一致（含大量零梯度区），否则 sim PASS 对自适应类算法零保证（均值/三区间查表两版均翻车，最终回归手动可调）。
- **用户报的显示参数值先 grep 代码常量再下结论**：报「3990」时 grep 发现 3990 = AE_MAX（曝光上限 localparam 封顶值）→ 系统被自动控制钉在极限态而非普通工作值——极限态（曝光封顶+高增益）的传感器噪声是下游一切现象（前景点稀疏均匀、静止物残留一列、边缘底噪抬升、阈值有效窗口窄）的总根源。分析按根因链组织（极限态→噪声→各现象），别逐个现象打算法补丁；处理顺序也是先解除极限态（改善照明/重采背景/手动降曝光）再判算法有没有真问题。
