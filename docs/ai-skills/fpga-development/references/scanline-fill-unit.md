# 扫描线行填充单元设计（区域填充功能）

## 适用

运动检测链上加「区域填充」（每行首 1 到末 1 之间填满、手掌心空洞实心）+ 边缘提取（形态学梯度）+ 按键切换显示模式三态。插入点：morph 滤波输出与 ERAM 攒字器之间，在 4px/拍流上做，最省资源。

## 行填充单元（row_fill）设计定式

1. **行缓冲最终形态 = DRAM 环形缓冲（ram_style=dram），不是移位链**：移位链写法在 TD 里因复位/帧清分支不推断 SRL、全变 FF（一条 320 深×4bit 链 ≈ 640 slice），资源超限实锤。DRAM 环形定式：`reg [7:0] mem [0:511] /* synthesis ram_style = dram */;`（数据+边缘直通合并 8bit；深度取 2 的幂 512、环形只用 320），写 mem[wp]、组合读 mem[wp+1]。**等价拍账必踩**：读地址 wp+1（最旧位置）最后写入拍 = t-319，读值 = 319 拍前 ≠ 想要的 320 拍前 → **写数据必须打 1 拍补偿**（写 mem[wp] <= din_d1）→ 读值恰 320 拍前，与移位链尾严格同拍；读写地址恒错开，无同地址读写顺序问题。帧清 = 清指针即可（数据不清，旧数据靠 valid 门控不输出）。关键性质不变：输出组号与输入组号同余（320 拍回绕）→ 掩码直接用当前组号 S_grp 比较，无需相位偏移。
2. **valid 链用 18bit 有效拍计数替代**（省 320~644 FF）：帧清清零、I_valid 拍 +1，out_valid = (计数 >= 链深) && I_valid——输出寄存块采样计数拍前值，第 0 个有效输出拍 = 链深+1 拍时计数旧值恰 = 链深；帧内最大有效拍 < 2^18 无回绕。
3. **段统计状态机（多段版核心，见下节）**：工作寄存器（段状态/当前段 L/R/0 游程计数）+ 行末锁存段表（S_out_*）。行末拍锁存值必须含当拍组 319 贡献（行末关段的段宽 = (当拍有1?319:S_cur_R) − L + 1，用组合右值），同拍工作寄存器清零——下一拍（新行组 0）起输出掩码即用完整行段表。
4. **边界粒度 = 组 + 组内位**：每段 L=(首个含 1 组号, 组内最左位)、R=(末个含 1 组号, 组内最右位)，优先编码函数用 if-else if 链（不用三元索引映射）。段内掩码：g==L 且单组段 → [L_bit,R_bit] 区间全 1（单组 case 表 10 项 + default 0）；g==L → bit>=L_bit 全 1；L<g<R 全 1；g==R → bit<=R_bit 全 1；段外原值。无前景行全 0。输出 = mask | 原值（掩码外原值理论必 0，仍按任务书「否则原值」写保通用）。
4. **valid 门控 + 帧清与上游 morph 同款**：I_valid 拍才推进（空洞拍不 shift）；帧开始清链丢弃滞留 321 拍（旧帧尾约 1 行）；清链后到新帧数据到达有 ~600 拍空窗，valid 链已推进满，帧头不丢拍。
5. **DRAIN 排空期直通是必须的**：上游 morph 的 DRAIN（644 拍强制 valid 排空）跨行边界 → 行相位统计错乱 → 若照常填充会把帧尾底部行涂白一条线。I_drain 打「链深+1」拍延迟链与输出寄存器同拍对齐，直通期输出原值。
6. **多通道同拍输出**：fill（填充后）/edge（边缘直通延迟）/ori（原值直通延迟）三通道同延迟输出 + 单 O_valid，下游 mux 无需对齐逻辑。ori 直通 = 数据链尾本身（省一条链）。

## 边缘提取增量（morph 内做，形态学梯度 = 开运算 XOR 腐蚀）

最终形态 = **edge = dil_v ^ ero_v_322**（dil_v 中心 = 输入 644 拍前、ero_v 中心 = 322 拍前，ero_v 打 322 拍对齐：DRAM 环形 320 + 2 拍寄存器）。语义 = open(X)^erode(X)：目标外轮廓线（2 像素宽环）、单点噪点被腐蚀吃掉后两图皆 0 完全消失——比 dilate(X)^X 干净且省 5000+ FF（独立膨胀链 + 644 深原图链是资源超限后弃用的第一版）。延迟账逐级推：ero_h 中心 = 输入−2 拍、ero_v = −322、dil_h = −324、dil_v = −644。
⚠️ 不能复用开运算的 dil_v 做 dil_v^X 冒充「膨胀XOR原图」——dil_v 输入是腐蚀后的图，单点噪点已被腐蚀吃掉，结果退化成 open(X)^X（单点显示成孤立点而非膨胀环）。tb 黄金模型按帧语义 3×3 窗口建模（图案远离行/帧边界，使流式跨行水平窗口与帧语义无差异）；输出第 j 个有效拍 = 帧流位置 [4j, 4j+3]（延迟 645 拍恰被 4px/拍相位吸收，与输入同索引比对）。

## 多段填充（防止手与远处物体/噪声连成一片，用户明确需求）

单段 [L,R] 全行填充的固有缺陷：同行任何前景（手 + 远处物体 + 噪声残留）都被连成白条。升级 = 每行多段。⚠️ **阈值参数先查任务书/主线会话定稿再写代码，不自作主张**——任务书会被主线会话追加需求节（如「零、用户新增需求」定死 gap 阈值和噪点阈值），自己拍的默认值（如 64 组）会被推翻重编译白烧一小时。

1. **段分割 = 0 游程阈值，语义「> 阈值断、≤ 阈值填」**：关段条件 `zero_len >= GAP_T`（第 GAP_T+1 个 0 拍才断），对应「gap ≤ GAP_T 组照填（段内空洞）、gap > GAP_T 断段」。任务书初定 GAP_T=10 组（40px）。行级判定无垂直信息，「手洞 vs 物体间隙」本质都是 0 游程、只能按宽度区分——物体间隙 ≤ GAP_T 仍误连，这是已知取舍（彻底解 = 跨行连通域标签，代价大比赛期不做），参数做成 module parameter 现场可调。
2. **噪点段过滤 = 段内 1 像素总数（位级计数，非段宽组数）**：`S_cnt1` 累加每拍 popcount(I_data)，关段/行末时 `cnt1 >= MIN_W` 才压表（任务书 MIN_W=4px：连续 1 < 4px 的孤立段不填；morph 开运算已滤单点，这兜 2-3px 残渣）。行末关段与 0 游程关段都要做检查（行末含当拍组 319 的 popcount 贡献 `S_cnt1 + f_popcnt(I_data)`），漏一处 = 行尾噪声段混进填充。
3. **段表结构**：每行最多 K=4 段（L/R/L_bit/R_bit 寄存器组，行末锁存；超出丢弃），掩码组合 = 对段表逐段「组号区间 + 位粒度」OR。实测多段版仅比单段版 +46 slice（预估 +350）——4 段比较器被综合大量共享，资源增量远小于直觉估计。
4. **tb 黄金模型 = 与 RTL 同构的独立多段算法**（GAP_T/MIN_W/K 一致，含 popcount 位级过滤），场景设计要点：双段大间隙（>GAP_T）验证不连、窄间隙（<GAP_T）验证照填、孤立 1-3px 噪点段验证过滤、全 0 行 + DRAIN + 帧清回归。

## 洞环语义（边缘与填充独立时的必然现象，用户可能误报 bug）

边缘提取对象 = **填充前**的开运算图（任务书原文「膨胀二值图 XOR 原二值图」的「原」），与填充是两条独立通路——gap ≤ GAP_T 被填充填掉的小洞（指缝），边缘模式仍会画出它们的轮廓环。实机现象：两指贴近时边缘图在指缝位置出现「填充的那根线」。这不是残留 bug（数据通路直通不掺填充信息，先向用户解释语义再查代码）。
- 判别现象：轮廓环（洞的环 = 语义独立的结果，正常）vs 涂白区域边缘的白框残留（那才要查 ERAM 写残留/模式切换帧）。
- 方案 A（保持现状，任务书原文语义）：边缘展示「检测算法自己发现了什么」，洞环保留反而可讲解为「填充与边缘是两条独立算法链」的演示点。
- 方案 B（边缘跟随填充，用户嫌画面不干净时）：提边对象改成填充结果 = 新小模块对 O_fill 做 3 行窗口腐蚀 + 异或（DRAM 化行缓冲，~300 LUT）；坑 = 新链路延迟与 fill/ori 通道差拍，三通道必须补齐同相位（补 FF 对齐），否则边缘图整体垂直错位。用户未拍板前不做 B，别默认改语义。

## 集成要点（bg_read + top）

1. **写 ERAM 数据源 mux**：非区域填充模式写 ori 直通（保持原涂白行为零回归）；区域填充模式按显示模式写 fill/edge/0（0 = 原图不涂白，一帧内清 ERAM）。所有模式统一走填充单元三通道（延迟一致）、valid 统一 S_fill_valid——绝对延迟增加 321 拍对写地址递增链无副作用。
2. **串联延迟链后 fg_init 判据必须放宽**：帧尾清链丢拍 = 上游链丢拍 + 新增链丢拍累加。morph 645 拍 → 串 row_fill 321 拍后，无 DRAIN 最坏最后写地址 22942 < 原判据 22960 → fg_init 恒 0（涂白使能永不拉高）。规则：每加一级延迟链，重算「无 DRAIN 最坏最后写地址」，判据取它以下留 20+ 字余量（代价 = 底部多 1 行不更新，无感）。
3. **显示模式按键（KEY4 双驱动冲突实锤教训）**：disp_mode_sel（三态循环 0→1→2→0，if-else 不用三元）挂 KEY4 + en=SW3&&SW4。⚠️ **共享按键必须把「旧模块」也加使能门控，只门控新模块必炸**——algo_mode_sel（图像算法原样/灰度/二值/Sobel，直通 isp_top 影响整屏画面）原来无条件响应 key_pulse，填充模式按 KEY4 时两模块同时 +1：图像被切到二值化 = 画面全白/全黑，前景标记同时乱切三态（实机 bug）。修复 = algo_mode_sel 加 en=!(SW3&&SW4)：填充模式锁定算法模式为原样（进填充即回 0），KEY4 只归 disp_mode_sel；退出后 KEY4 恢复算法循环。
   排查定式：画面「全白/全黑」类整屏异常，先怀疑图像算法模式被误切（isp_top 的 algo_mode 档位），而不是新功能的数据链路——按键新增消费者前 grep 所有 key_pulse 连接点做冲突检查。2bit disp_mode 跨域用格雷码打 2 拍解码（01→10 两 bit 同变，二进制直接打拍会采中间态闪错一帧）。
4. **top 接线纪律**：新 wire 声明放例化使用点之前（TD 隐式网教训）；fill_en 的 assign 引用后面声明的 reg 合法（reg 无隐式网问题，只有 wire 有）。

## 验收核对（任务书口径）

手伸进画面实心涂白（填充后）/ 按键边缘模式只显轮廓 / 按键原图模式原始画面 / 三态循环无卡死。切换有 1 帧过渡（原图模式写 0 清 ERAM），60Hz 无感。hdmi_mixer 的错位补偿参数（S_fg_col 初始值）禁改。
