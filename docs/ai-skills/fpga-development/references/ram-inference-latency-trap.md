# 推断 RAM 综合延迟陷阱（tb 全绿实机错 1 拍）

## 症状
- 仿真（iverilog 行为模型）全绿、实机错位恒定（案例：cur/bg 比较数据左移 40 像素 = 1 字）
- 实机错位与画面内容无关、与摄像头转动无关（恒定偏移 = 结构性延迟错）

## 根因
reg 数组 + 组合读 `assign x = mem[ptr]` + 外部锁存的写法，TD 综合时：
- 大数组（如 1024 深）被映射成 BRAM → 读延迟变成「地址后 1 拍出数」
- 综合器可能吸收下游锁存寄存器当 BRAM 输出寄存器 → 实机总延迟与仿真模型差 1 拍
- 仿真模型（组合读+1 拍锁存 = 1 拍）与实机 BRAM 行为不一致
这是 FPGA 界公认的「Simulation mismatches」（推断 RAM 仿真/综合不一致），标准解法 = 原语/IP 实例化 + 寄存器化读路径（danstrother.com《Inferring RAMs in FPGAs》专节；vlsimentor：异步读退回 LUT RAM，映射 BRAM 则地址后 1 拍出数）。

## 案例：标签 FIFO（多主共享读数据线的路由）
- 结构：读命令发出拍压标签（vo=1/bg=0）→ 返回落地拍弹标签 → 下游按标签路由数据
- 标签延迟错 1 拍 → 收数计数错 1 → 帧头误丢 1 字 → 数据整体移 1 字（40 像素卷绕）
- 修复：标签 FIFO 改用 TD 的 w128_d512_fifo IP 例化：we=读命令拍压 {127'b0, vo_grant}、re=返回拍弹、rd_tag=dout[0]（IP 读时序固定：re 后 1 拍出数 = 与 rd_valid_d1 对齐，无综合变数）
- 深度论证：写拍门控+批边界下真实在途 ≈ 40~300 拍 ≪ 512；标签 FIFO 满前 mc 队列先满拉低 ready → 命令停发 → 不溢出
- ⚠️ 下板结果：该修复下板后现象完全不变（左偏/水管涂白/卷绕照旧）→ 标签 BRAM 延迟假设被证伪或非唯一源，左偏根因转入开放疑点（帧开始拍锁存 pend 的当拍计数口径，见 ddr-debug-bisection.md 帧尾在途锁存节 ④；增益/曝光差第二源，见 ddr-debug-bisection.md 涂白双源判别）

## 被否决的替代方案：在途窗口分流
- 想法：不用标签，用「自己的读命令在途数 >0 时到达的返回 = 自己的」
- 否决原因（real tb 实锤）：帧内每个 vo 读批的尾 40 拍返回与 bg 批开始重叠；600 拍启动延迟只挡帧首 vo 尾批，挡不住帧内批间交替 → bg 误收 vo 返回 → mis 从基线 368 飙到 10172
- 结论：多主共享读数据线，标签精确路由（按命令归属）是唯一正解；时间窗口在批间交替时必然泄漏

## 诊断方法论（本次用户推理，已证实）
- 静止物体（水管）被涂白 = 比较数据（cur/bg）相对错位，不是标记位置映射错——涂白映射错位不会让静止物体产生差异
- 只有边缘涂白、平坦区不涂白 = 错位量小（1 字级）：平坦区 40 像素内内容相同差不出阈值
- 卷绕现象（最左涂白跑到最右循环）= 恒定偏移 mod 行宽，可直接读出偏移方向与量级
- 方向判读：数据左移 N 像素 = 帧头误丢 N/像素数 个字；右移 = 帧头多收

## 通则
- 「仿真与实机不一致且错位恒定」的首选怀疑对象：推断 RAM/数组的综合延迟差异（其次才是 CDC/隐式网）；但修改下板后现象完全不变 = 该假设被证伪，立刻转下一层疑点，别在同一假设上继续打补丁
- 跨拍对齐的关键信号链（标签/ID/valid）必须用 IP 或显式寄存器实现，禁止依赖推断数组的读时序
- 官方资料佐证：安路官方示例所有 FIFO 用 soft FIFO IP（SHOW_AHEAD+NOREG），不用推断数组；官方新一代 DDR IP 读通道有 rlast 但无 ID → 官方哲学 = 读返回保序 + rlast 配账，user 接口无 rlast 时「N 拍计数」就是自造 rlast
