## 入门流水灯最常用（当前阶段）
| 信号 | 引脚 |
|---|---|
| clk（50M 时钟源） | C4 |
| LED1 | D10 |
| LED2 | E10 |
| LED3 | C6 |
| LED4 | D6 |
| KEY1（可当复位键） | D5 |
| KEY2 | A9 |
| KEY3 | B9 |
| KEY4 | C7 |

**LED 极性（两组相反，务必分清，别照搬写法）：**
- 4 个独立 LED（LED1~4，D10/E10/C6/D6）= **高电平点亮**（手册⑭节明确写「高电平点亮」）。流水灯输出单热码 `1000→0100→0010→0001`（一位高电平移动）才对。
- 8 个双色 LED（LED6~13 红绿，与数码管复用 C9/G15/C11/G14…）= **低电平点亮**（引脚输出 0 灭、输出 1 亮）。这两组极性相反，写独立 LED 流水灯别去套双色 LED 的取反写法。

板子没有专门复位引脚，用 KEY1~KEY4 之一当复位键。用户代码 `rst_n` 低有效（`!rst_n`），按键按下拉低触发复位、松开拉高运行。

## LED 极性（易踩的混淆点）
- **4 个独立 LED（LED1~4 = D10/E10/C6/D6）是高电平点亮**（康芯手册⑭节原文「高电平点亮」）。流水灯直接写 1000→0100→0010→0001（一位高电平移动）就是对的。
- **8 个双色 LED（LED6~13，与数码管复用、SW6 切换）才是低电平点亮**（手册「输出0熄灭、输出1点亮」）。别把这两组 LED 的极性搞反——很多人第一个怀疑「极性反了」，其实 4 独立 LED 是高有效。

## 其他外设
- 蜂鸣器 BUZZER=C12；乒乓开关 SW1~4=A4/B4/E11/D11（SW5 蜂鸣器开关、SW6 数码管/双色LED选择开关）。**SW1~4 极性（以实测为准，别信「拨上/拨下」这种方向词）**：手册⑯节写「拨上=1/拨下=0」，但丝印没标方向、「上/下」依赖视角，用户实测「拨到自认为上的一侧」结果是 0（LED 灭）、跟手册反了。准确判据：**拨向板框（板子边缘）一侧 = 高电平 1**、拨向板内侧 = 低电平 0。电路是接地式（闭合接地=0、断开经 10K 排阻上拉 VCC_3V3=1）。做模式切换直接读静态电平别检测边沿；第一次用时先 `assign led=sw[0]` 下个小工程实测方向，别照抄「拨上=1」。
- USB 转 UART：RXD=J1，TXD=H1。USB-JTAG：TCK=P15，TDI=R13，TMS=L14，TDO=T13。
- TF 卡(SD)：SD_CS=B12，SD_DAT0(MISO)=E8，SD_CMD(MOSI)=A8，SD_CLK=A7，SD_DAT1=D8，SD_DAT2=A12。
- 数码管/双色LED（引脚复用）：LED6红/DIG0a=C9，LED6绿/SEL0=G15，LED7红/DIG1b=C11，LED7绿/SEL1=G14，LED8红/DIG2c=B11，LED8绿/SEL2=A17，LED9红/DIG3d=E7，LED9绿/SEL3=A18，LED10红/DIG4e=E6，LED10绿/SEL4=B16，LED11红/DIG5f=B6，LED11绿/SEL5=A15，LED12红/DIG6g=B7，LED12绿/SEL6=B15，LED13红/DIG7h=E5，LED13绿/SEL7=A14。
- SPI FLASH（N25Q128）：QSPI_CS=D14，SDO=D16，SDI=E13，SCLK=N6，HOLD=A13，WP=C16。另一片 GD25WQ128：CSN=R8，DQ0=V12，DQ1=U12，DQ2=V11，DQ3=U11，GCLK=R15。

## 数码管（共阳，8 位动态扫描）—— 显示数字/数值用
8 个数码管与 8 个双色 LED **复用同一组 16 个引脚**，由 **SW6 拨码开关选**：**拨上=数码管工作、拨下=双色LED工作**（用数码管前先把 SW6 拨上，否则引脚被双色 LED 抢走数码管不亮）。段/位引脚见上文「其他外设」的 DIG0~7 / SEL0~7 行。

**极性（两组都反直觉，务必记住，别照手册字面）：**
- **段 DIG0~7 = 共阳数码管，段引脚低电平点亮**（段=0 亮、=1 灭）。共阳 8 段是 a,b,c,d,e,f,g,dp，DIG0=a … DIG7=dp。
- **位选 SEL0~7 经过 PNP9012 三极管（原理图 Q1~Q8）反相驱动，所以 SEL 也是低电平选中**（FPGA sel=0 → 三极管导通 → 数码管公共阳极通电亮）。手册⑪写「SEL 高电平有效」是从公共端供电角度说的，中间隔了 PNP 反相，实际 FPGA 引脚给 0 才亮。坑：`sel=8'b0000_0001` 想点第 1 个，结果是「第 1 个灭、其余 7 个亮」——sel[0]=1 让第 1 个三极管截止。正确写 `sel=8'b1111_1110`（低电平选中那一位）。排查这个 bug 的方法：读原理图第 5 页 "Nixie Circuit"，看到 SEL 串 PNP9012。

**共阳段码表**（位序 seg[7:0]={dp,g,f,e,d,c,b,a}，0=亮）：`0=C0, 1=F9, 2=A4, 3=B0, 4=99, 5=92, 6=82, 7=F8, 8=80, 9=90`；非法值 default 给 `8'hFF`（全灭）。要**熄灭**某位（高位无意义的 0 不显示）给该 4 位填非法值 `4'hF`（走 default 全灭），别填 `4'h0`——0 是合法数字会显示"0"而非熄灭；`data={28'hF,num}` 只亮最低位，`data={28'h0,num}` 前 7 位全显示"0"。

**动态扫描**：8 个数码管共用段线、各独立位选，同一时刻只能显示一组段码，所以要快速轮流点亮（每个亮 ~1ms，8 个一轮 8ms≈125Hz，靠视觉暂留看成同时显示）。模块结构：分频出 scan_tick（每 1ms 一个）→ sel_idx[2:0] 循环 0~7（3 位溢出自动回 0）→ 按 sel_idx 用 case MUX 从 data[31:0]（每 4 位一个数字，data[31:28]=最左第1位/最高位、data[3:0]=最右第8位/最低位，跟十进制高位在左一致）挑出 cur_digit[3:0] → seg7 译码成段码；位选 case(sel_idx) 输出低电平选中的独热码（1111_1110/1111_1101/…/0111_1111）。

## SC500 摄像头画面暗 / 增益调节
- **画面暗先分「摄像头采集暗」还是「HDMI 输出暗」**：看 OSD 叠加的「安路 Logo + 计数器文字」（FPGA 直接生成、不经摄像头）。Logo/文字亮、只有摄像头画面暗 = 摄像头采集暗（曝光/增益问题）；Logo/文字也暗 = HDMI 输出/显示器问题。
- **SC500 模拟增益寄存器**：`0x3e08`=整数档（0x03=1x、0x07=2x、0x0f=4x、0x1f=8x），`0x3e09`=微调档（0x20 基准，往 0x3f 加）。组合对照（数据手册表2-4）：0x0f+0x20=4x、0x1f+0x20=8x、0x1f+0x30=12x、0x1f+0x3f≈15.75x（最大16x）。数字增益 0x3e06/0x3e07 模拟不够才用。
- **默认 4x 室内偏暗**，调到 8x~12x 合适。改 `uics500reg_720p60.v` 里 `3e08`/`3e09` 那两行，重新编译下载（约14分钟）。增益越高噪点越多、光源越易过曝发粗，够亮就行别拉满。
- 改完下载若「无画面」多半是 JTAG 偶发没生效，重新下载一次即可（跟流水灯那次一样）。
- 下载后若「跑的是出厂程序（Flash 里的）」「黑屏但有背光」「花屏」等异常，且重下一次还不行，就**重启板子（断电重上电）+ 重启 TD 软件再下载**——JTAG 链路状态乱时这样最稳，跟注释/代码无关。
- **下载耗时是链路状态的晴雨表**：`download` 那条 log 的 `in XX.xx s wall`。正常约 20~30 秒；50~60 秒是冷启动稍慢；>90 秒（甚至 274 秒）说明链路不稳、bit 配置大概率不完整，下完多半黑屏/跑出厂程序。遇到慢下载直接重新 Run 一次，第二次回到 20 秒左右就正常了。所以下载后先看耗时，>90 秒别等画面，直接重下。
- **lab_ex1 的 I_button 接的是扩展口 GPIO，不是板载按键**：I_button[0]=N2（GPIOA_19）、I_button[1]=J14（GPIOB_12），板子上默认没实体按键接这俩。板载独立按键是 KEY1~4=D5/A9/B9/C7（流水灯/按键 LED 用的）。要用板载按键就得改引脚约束，把 I_button 绑到 KEY 引脚。ae_set 的 I_btn 映射：bit0=曝光减 bit1=曝光加 bit2=增益减 bit3=增益加；官方接 {I_button,2'b11} 即只让两个按键调增益、曝光加减被 2'b11 固定成「不触发」。
- **lab_ex1 的 isp/data96_128/data96_128.v 一个文件里定义了两个模块**：data_96bit_to_128bit（约第3行）和 data96_128（约第88行）。isp_top 例化的是 data_96bit_to_128bit，它的定义就在 data96_128.v 里，别再去找单独的 data_96bit_to_128bit.v（那个是废弃重复文件，.al 没添加它）。

## lab_ex2 官方例程 bug（边缘检测花屏/黑屏）
lab_ex2（边缘检测）下载后花屏、再下黑屏，lab_ex1/3 正常。根因：lab_ex2 的 isp_top 在 AWB 之后多插了 `edge_detect_96`（Sobel）+ `data_96bit_to_128bit`（96位→128位重新打包）这条链路，时序/数据对齐没适配好 720p60（综合报 `SYN-6021`、Bitgen 报 `BIT-8123` 是另一码事——那是没做引脚约束）。官方更新 720p60 时 lab_ex2 没调好。用户已跳过，计划自己写一版 Sobel 顶替（做多算法切换时本来就要自己写）。别在官方 lab_ex2 上耗时间。

## lab_ex 例程的「按键 I_button」不是板载按键（易踩坑）
lab_ex1/2/3 顶层 `design_top_wrapper` 的 `I_button[1:0]` 在 pin.adc 里约束为 **N2 / J14**，这俩是 **J2 GPIO 扩展口的引脚**（N2=GPIOA_19、J14=GPIOB_12），**不是板载的 KEY1~4（D5/A9/B9/C7）**。板子上默认没有实体按键接到 N2/J14，所以按板载 KEY1~4 调不动 lab_ex 里 ae_set 的增益/曝光（引脚对不上）。

`ae_set` 的 `I_btn[3:0]` 映射：bit0=曝光减、bit1=曝光加、bit2=增益减、bit3=增益加。顶层接 `{I_button,2'b11}` = 高2位接实体按键（增益加/减）、低2位固定 11（曝光加/减被屏蔽，只能调增益、调不了曝光）。增益初始 80≈4x，范围 16~89。

用户要「按键调曝光/增益」，正确做法：写 key_debounce 接到 ae_set 的 I_btn，并把引脚约束从 N2/J14 改成板载按键 D5/A9/B9/C7（KEY1~4），别用扩展口。
