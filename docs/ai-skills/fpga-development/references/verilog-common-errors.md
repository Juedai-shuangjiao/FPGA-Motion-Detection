# Verilog 入门 / 仿真常见错误清单

用户正在学 FPGA 入门（流水灯、分频、testbench 仿真）。批改入门代码时优先扫这几类高频错误——多数是「抄代码漏字符」或「分频时钟没用上」这类细节。

## 语法错误（编译直接报错）
1. **模块名以数字开头**：`module 001_run_led(...)` 非法，Verilog 标识符必须以字母/下划线开头。
2. **端口列表与声明不一致**：`module x(clk, rest_n, led)` 端口列表写 `rest_n`，下面却 `input rst_n` —— 名字对不上直接报未声明。统一成一个。
3. **冒号写成中文/英文冒号当分号**：`reg clk_1hz:` 应为 `;`。
4. **数字 1 和字母 l 混**：`1'bl` 应为 `1'b1`；`clk_1hz` 里的 1 别写成 l。
5. **变量名中间带空格**：`clk 1hz` 应为 `clk_1hz`。
6. **`timescale 写错**：标准写法 `` `timescale 1ns/1ps ``。三个要点：开头是**反引号** `` ` ``（不是单引号）；单位是**数字 1**（不是字母 l，别写成 `ins/lps`）；两个单位间是斜杠。
7. **花括号 `{}` 误当圆括号 `()`**：模块例化端口连接用圆括号 `u_xxx(.port(sig), ...)`，写 `u_xxx{...}` 直接报错。新手容易跟 C 语言的花括号代码块搞混——Verilog 里 `{}` 是**位拼接运算符**（如 `{a,b}`），不是代码块/连接符。这个坑用户会反复踩，看到例化处花括号要盯。
8. **`always @()` 少了星号**：组合逻辑应写 `always @(*)`，漏了 `*` 编译直接报错。`@(*)` = 任何输入变化都触发。
9. **★`output wire` 在 always 块里赋值**：`output wire [3:0] led` + `always @(*) led = ...` 编译报错——always 块只能给 `reg` 赋值，wire 只能被 `assign` 连续赋值（或作模块输出被驱动）。要在 always 里赋值就声明成 `output reg`。注意：组合逻辑 `always @(*)` 里的 reg 综合出来仍是连线/查找表、不是真触发器，只是 Verilog 语法要求。这是新手从「assign 直连」改成「case 译码」时最容易踩的坑（用户把 `assign led=sw[0]` 改成 always case 时忘了把 `wire` 改成 `reg`）。
10. **端口列表里端口之间漏逗号**：给顶层加新端口时（如加 `output wire [7:0] seg`），忘了在前一个端口 `output reg [3:0] led` 末尾加逗号，导致 led 和 seg 之间没分隔符 → 编译报错。端口列表规则：端口之间用**逗号**分隔，最后一个端口后面不加逗号直接 `)`。
11. **★多驱动冲突（assign 和模块输出同时驱动一根 wire）**：把静态显示改成模块输出时，忘了删掉旧的 `assign sel = ~8'b0000_0001;`，新例化的模块又 `.sel(sel)` 输出到同一根线 → 一根 wire 两个驱动源，综合报 multiple drivers。规则：一根 wire 只能一个驱动源；改成模块输出后删掉旧 assign。用户加 seg7 动态扫描时踩过（旧 assign sel 没删）。

## 逻辑错误（能编译但功能不对）—— 更重要
1. **★分频时钟分频出来没用上**：第一个 always 把 50MHz 分频出 `clk_1hz`，第二个 always 驱动流水灯却还写 `@(posedge clk, negedge rst_n)`，漏了 `_1hz` 三个字符。结果 led 每 20ns 跳一次，高频闪烁看着全亮，看不到流水。这是流水灯分频题最容易翻车的点——**批改时先盯第二个 always 的敏感列表是不是真用了分频后的时钟**。
2. **移位链用 else 兜底非法状态**：`else led <= 4'b1000` 能循环（0001 落到 else 跳回 1000）但不够严谨，更清晰的写法是显式 `else if (led == 4'b0001) led <= 4'b1000;` 再跟 else 兜底。
3. **仿真参数 T 太大跑不完**：DUT 里 `parameter T = 50_000_000/2-1` 产生 1Hz，仿真要跑 2500 万时钟周期，波形等半天看不到一个完整移位。标准做法是**参数化覆盖**，不改 DUT 源码：`run_led #(.T(4)) dut(...)`。
4. **testbench 缺 `$finish`**：会一直跑不停，加 `initial begin #2000 $finish; end`。
5. **仿真模块名笔误**：`run_led_tb` 抄成 `run_led_tp`（tb→tp）。
6. **时序逻辑混用 `=` 和 `<=`**：`@(posedge clk)` 的 always 块里必须全程用 `<=`（非阻塞），混入 `=`（阻塞，如 `cnt = 0`）会导致综合警告或功能异常。铁律：时序逻辑 `@(posedge clk)` 用 `<=`，组合逻辑 `@(*)` 用 `=`，**一个 always 块里不能混用**。
7. **`$display` 的 `%t` 显示时间用「时间精度」不是「时间单位」**：`timescale 1ns/1ps` 里第一个数（1ns）是 `#延迟` 的单位，第二个数（1ps）是 `%t` 显示的单位。所以 `#5_000_000`（5ms）后 `$display("%t",$time)` 会打印 5000000000（ps），看着大 1000 倍——不是仿真错了，是显示单位。写 testbench 时要么后缀写 ps，要么用 `$realtime`/自己换算，别误判成时序 bug。
7. **`$display("%t", $time)` 打印的时间戳是「时间精度」不是「时间单位」**：`timescale 1ns/1ps` 下 `#5_000_000` 是 5ms，但 `%t` 打印出来是 `5000000000`（因为 %t 按精度 1ps 显示，1ns=1000ps）。看到仿真时间戳「大 1000 倍」时别慌，要么把后缀标成 ps，要么心里 ÷1000。规则：`#延迟` 用时间单位（timescale 第 1 个数），`%t` 显示用时间精度（第 2 个数）。
8. **★case 缺 default 分支 → 综合出锁存器（latch）**：`case(digit)` 只列了 0~9，但 digit 是 4 位（取值 0~15），10~15 这 6 种情况既没列又没 default，组合逻辑里这些输入组合下输出没被赋值 → 综合器推断 latch（锁存器），报 warning、引入毛刺/时序问题。即使实际只用到 0~9，综合器不知道，照样按 16 种情况推断。规则：case 要么列全所有取值、要么加 default 兜底（如 `default: seg = 8'hFF;` 全灭）。判断：综合日志出现 latch/锁存器 warning 就是缺 default。用户写 seg7 段码译码时踩过（列了 0~9 漏 default）。

## iverilog 仿真坑（WSL 用 iverilog 快速验证 HDL 时）
1. **%0t 显示的是时间精度（ps），不是时间单位（ns）**：`` `timescale 1ns/1ps `` 里，`$display("t=%0t ns", $time)` 的 `%0t` 按第二个数（1ps）显示，所以 5ms 会显示成 5000000000（看着大 1000 倍）。仿真时间其实是对的，别被时间戳吓到；后缀别乱写 ns，要么写 ps、要么用 `$realtime` 换算。
2. **大计数器仿真慢**：分频器/消抖这种要数几千万周期的逻辑，iverilog 跑得慢（消抖 20ms@50MHz = 100 万周期，快闪 5Hz 半周期 = 500 万周期）。**不要用抬高时钟频率来「加速」**（总计数次数不变，时钟沿反而更多、更慢）。正确做法：testbench 里参数化覆盖把消抖/分频参数改小（如 `#(.DEBOUNCE_MS(2))`），或只观察快闪、跳过慢闪（慢闪 2500 万周期跑不动就打印初值即可）。

## 批改流程建议
1. 先问用户代码来源（是不是照文档/PPT 抄的）——「看文档编写」时，用 OCR 把文档里的原版代码提出来对照，往往发现是**用户抄漏了几个字符**（如 `_1hz`），而不是设计本身错。
2. 分「语法错误（编译不过）」和「逻辑错误（能编译但功能不对）」两类列，逻辑错误单独标 ★ 强调。
3. 给修正版代码，但点明每处改动的理由，符合用户「以题代学、自己改 bug」的偏好。

## 分频参数速算（复核用）
`parameter T = 50_000_000/1/2-1` = 24,999,999：50MHz 时钟产生 1Hz，计数器 0~T 共 2500 万周期 = 0.5s 翻转一次，翻转两次 = 1s = 1Hz。`cnt` 位宽 [24:0]（25 位）够装 24,999,999。复核分频题时用这个口径。
