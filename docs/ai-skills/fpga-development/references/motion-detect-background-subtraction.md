# 运动检测背景减除最终定版（2026-10-16）

motion_detect.v 从「帧差法」演进到「背景减除」的完整迭代链 + 关键踩坑。最终定版 = RGB 3 通道 4bit + 320×180 + 深度 57600 + 闭运算 + 叠加显示。

## 迭代链（每个方案为什么被否，都是踩坑）

1. 灰度 + 帧差法（最早）：只画运动轮廓，手内部空（帧差法原理：内部两帧都有差≈0）
2. 灰度 + 背景减除：手整块，但内部变黑（灰度 R/4+G/2+B/4 把 R 权重压到 1/4，丢颜色）
3. B 单通道：B 差仅 30 不够（阈值 40 检测不到）
4. RGB 3 通道 8bit + 320×90：内部变白但垂直 8:1 降采样 → 锯齿严重 + 旋转 45° 不完整（为省 ERAM 砍分辨率得不偿失）
5. **R-B 色差 + 320×180：全黑**（AWB 压缩，见坑 1）
6. R 单通道 8bit + 320×180：能检测但手内部 R 弱处变黑（单通道无互补）
7. ✅ **RGB 3 通道 4bit + 320×180 + 深度 57600 + 闭运算 + 叠加**（最终）

## 关键踩坑

### 1. AWB 白平衡压缩「色差类」特征（R-B 全黑根因）
AWB（awb.v）把整帧 R/B 归一化到 G（R 增益 = sum_g/sum_r，B 增益 = sum_g/sum_b）。画面肤色多时，AWB 把肤色「降 R 升 B」拉向中性 → 手 R-B 差被压到阈值以下，R-B 色差减背景全黑。
- 但「绝对值差」类特征保留：手 R 高 vs 背景 R 中，AWB 后 R 差依然大。
- **教训：AWB 之后别用「色差/色度」特征（R-B、R/G 比值），用「单通道绝对值差」（R 差、B 差）。**

### 2. ERAM20K 位宽配置只有 1/2/5/10/20/40（没有 4bit/8bit）
安路 PH1 ERAM20K 配置是离散的：16K×1 / 8K×2 / 4K×5 / 2K×10 / 1K×20 / 512×40。
- 4bit 数据塞「4K×5」（浪费 1bit=20%），8bit 塞「2K×10」（浪费 2bit）。
- 算 ERAM 数按「深度级联」：ceil(深度 / 单块深度)，**不是**「实际 bit 数 / 20Kbit」。
- 4bit×65535 深 = ceil(65535/4096) = 16 个 ERAM；4bit×57600 = 15 个（省 1 个/块）。
- 「EMB=109 超 108」根因：按实际 bit 数估（13 个）偏乐观，实际按配置粒度（16 个）。省 ERAM 用「更浅深度」（57600 刚好装 320×180）比「减位宽」有效。

### 3. 全分辨率做不了（BRAM 容量硬约束）
1280×720 全分辨率背景减除要存一整帧：8bit 灰度 7.37Mbit=360 ERAM、4bit 3.69Mbit=180 ERAM，都超 108。DDR 能存但带宽顶 94%（视频流已占「写当前帧 + 读显示」）。所以只能降采样 320×180（4×4 块）。锯齿、边缘偏差（最多 4~8 像素）、暗背景检测弱，都是降采样 + 背景减除的固有代价，消除不了——别为「像素级圆滑」反复堆形态学。

### 4. 闭运算（膨胀+腐蚀）填洞 + 修圆
加在 motion_filt 之后（降采样 320×180 网格上做 3×3）：
- 膨胀 3×3 OR（有前景就前景）填 <3×3 降采样像素的黑洞（手内部阴影小黑点）
- 腐蚀 3×3 AND（全前景才前景）修圆块状锯齿
- 两级各 1 拍延迟，总延迟 +2 拍（O_* 同步打拍；本次运动检测总延迟 3→5 拍）
- **line buffer 读旧写新时序坑**：reg 数组异步读 `wire x = mem[idx]` 在 posedge 后读到「新值」不是「旧值」。要读旧值，必须把 3×3 窗口计算放进 `always @(posedge)` 的非阻塞赋值右边（右边在 posedge 前用旧值求值），结果打 1 拍寄存。不能写成组合逻辑连续赋值读 mem[idx]（读新值 + 毛刺）。
- 3×3 膨胀只能填 <3×3 的洞；>3×3 降采样像素（>12×12 原始）的阴影填不掉。复位后重新采背景（背景完整）能改善大部分阴影。

### 5. 顶部边界效应（两处，都要屏蔽）
- **垂直 4 行平均「下移 3 行」**：结果在第 3 行（row_m==3）才输出，顶部 row 0~2 读放大回显 line buffer 垃圾 → 屏蔽 `row_cnt_d5 < 3` 输出 0。
- **闭运算 line buffer 前 2 降采样行垃圾** → 屏蔽 `down_cnt_d3/d4 < 640`（前 2 行透传，不膨胀/腐蚀）。

### 6. 叠加显示（原样 + 运动标记）
原样画面打 N 拍（N = 运动检测总延迟）对齐，每像素 `motion标记 ? 24'hFFFFFF : 原样`。SW4 集成到原样模式做开关（SW4 开 = 采背景 + 叠加，关 = 纯原样），算法模式精简掉「纯黑白运动」和「单独叠加」两个模式。OSD「已采/未采」提示改成「原样模式 + SW4=1」时显示。

### 7. 背景减除 vs 帧差法（概念 + 答辩话术）
背景减除（减固定背景）检测「跟背景不同的前景目标」，**静止也在标记**（不是严格「运动检测」，是「前景/目标检测」）。帧差法（减上一帧）才检测「变化」。背景减除是赛题「运动目标检测」的标准做法、比帧差法高级（整块 vs 轮廓、静止不丢）。答辩话术：「我实现的是背景减除（帧差法的升级），检测画面中相对背景出现的前景目标，运动进入立即标记、之后持续跟踪不丢失」。⚠️ 简介若写「帧差法标记运动区域」，答辩主动说「升级到背景减除」圆过去（或改简介）。
