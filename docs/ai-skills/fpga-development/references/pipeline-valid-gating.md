# 数据流处理模块：多级延迟链 valid 门控一致性

## 核心规则
滤波/窗口运算模块（形态学、行缓冲卷积）里所有延迟链必须用同一种推进策略：要么全部每拍 shift（延迟=日历拍），要么全部 valid 拍才 shift（延迟=有效拍）。

**valid 门控链的输出 valid 语义**：O_valid = 链尾 && I_valid——链在空洞拍保持 1，不加 && I_valid 会持续输出 valid、下游重复消费旧数据（morph 2026-10-27 实锤）。

**valid 门控链的帧尾语义**：帧间断层（无有效拍）链不推进 → 帧尾数据排不出、只能清链丢弃；下游写满判据要按「丢尾量」放宽，别等精确写满。

## 坑与现象
1. 部分门控部分不门控 = 白影错位 + 无目标飘线。水平链每拍 shift、垂直行缓冲 valid 门控，在空洞拍（相位空洞/行尾 gap，空洞率可到 25%）两者相对漂移——垂直窗口跨行错位，输出错位标记；背景噪声经错位窗口腐蚀/膨胀成伪前景线。
2. valid 输出链必须与数据链同策略（有效拍延迟则 valid 链也要 valid 拍才 shift），否则 O_valid 与 O_data 错位。
3. 帧开始清场脉冲若用日历拍移位链，帧尾数据排空时间按「延迟拍数/(1-空洞率)」留余量，否则帧末丢字（屏幕底部不更新）。
4. 行缓冲深度必须 = 每行有效拍数。注意 128bit 命令数 ≠ 96bit 拍数（240 个 128bit/行经解包 = 320 个 96bit 拍/行）；按命令行数设深度会错位两行。

## 仿真验证要点
1. tb 必须注入空洞拍（valid 断续）才能暴露门控不一致——valid 全程连续的 tb 测不出。
2. 大位宽移位寄存器（1280bit 行缓冲×N 条 + 深数组延迟链）在 iverilog 里拖慢 5 倍以上（400 万拍 >50 分钟）——滤波逻辑用单模块小 tb（几千拍秒出）验证，集成 tb 减帧数或后台跑；实机 FPGA 无此问题。
3. 形态学 tb 场景设计：测试块要 ≥3 行高（1 行高的块被 3×3 腐蚀清除是正确行为不是 bug）；孤立噪点与块间距要 > 窗口半径（同列不足一行距离会被垂直膨胀跨行覆盖）。
4. iverilog -g2012 下 expect 是 SystemVerilog 关键字，不能作变量名。
