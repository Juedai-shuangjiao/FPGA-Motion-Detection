# 视频/图像错位类 bug 排查方法论（PH1P35 项目 5 天实战）

来源：2026-10 底 PH1P35 竞赛项目「背景差分涂白错位 8-13px」实战（完整复盘见项目 错位bug复盘_GitHub分享版.md）。

## 核心结论
- bug 不是单点代码错误，而是显示/检测/标记三路径的固定延迟差（三路径相位账）
- 显示路径：DDR 读约 30 拍 + video_out 打拍 → 屏幕内容落后 x_2d 约 30 拍
- 检测路径：bg_read 读 DDR + 差分 → 位图列内容继承同样的 +30 拍偏移
- 标记路径：ERAM 读 1 拍 → 涂白跟 x_2d 几乎同步
- 净错位 = 位图偏移 38px - 显示路径抵消 30px = 屏幕 8px（人眼 8-9 低估，真实 12-13px）

## 排查步骤
1. 先定性：偏移恒定=固定拍数相位差（结构性延迟）；偏移随机=时序违例/亚稳态。修法完全不同。
2. ±1/±2 拍调整无效时，立即怀疑 DDR/行缓冲级延迟（数十拍），上片上逻辑分析仪抓波形（ChipWatcher 打通流程：WinUSB 驱动 + 官方 hwserver.exe + AL-LINK-FT 端口 5555）。
3. 贴边贯穿实验定物体真实位置：物体一半伸屏幕外，用「涂白开始位置」代替「涂白结束位置」，消除人眼估计误差。
4. 补偿走「读地址加偏移常量」：组合逻辑常量加法不会被 retiming 吃掉。
5. 拿两个实测点线性插值外推归零值（N30 左错 2 / N34 左错 4 → N26 归零），比继续盲猜快得多。

## 关键坑
- **补偿方向先算清再改参数**：col 初始值 N 的语义是「视频 x 处涂白显示位图列 (x+N)」——N 增大涂白左移、N 减小涂白右移。把 N 34→38 当成「右移 4」实测左错反而 4→8 加重（一次编译 60 分钟 + 一次下板才能发现）。拿到实测点后写线性方程（错位 = a·N + b）外推，不要心算方向。
- 抓跨域脉冲前必须展宽成电平：100M→75M 打拍会把 1 拍脉冲采丢（CSV 里信号全程 0，但地址停在 31 证明写侧活动过）。
- TD 综合器会 retiming 掉纯打拍链：mark 信号打 2 拍被优化成组合逻辑，补偿必须走地址常量加法。
- 人眼对错位量级系统性低估（8-9px 实际 12-13px），波形数据为准。

## 同类社区案例
- netv2-fpga issue #20：overlay 整幅平移绕圈，bunnie「DRAM 一次取一组像素，同步信号落在取数前后对齐就变了」
- MiSTer Arcade-Deco16：pointer resynced to write pointer at every HSync，FIFO 每行回空永不漂移
- 专利 CN109714548A：列地址计数器以行同步为起点

## 治本方向
- 行同步重对齐：行首强制清零列/批计数，行首像素永远落在批首字
- DDR 读侧对齐 FIFO 每行复位

## TD GUI 工程坑（同项目实战）
- GUI 打开 .al 工程**不要点保存**：保存会重算并清掉 ddr2.xml 引用，下次编译报 `ddr2 is a black box`；.prj 不受影响，命令行编译正常。
- GUI 编译 PLL 可能报 VCO 超范围（重算值 2400MHz > [800,2000]，源文件 1500MHz 合法）——GUI 会话内重算所致，不影响命令行编译。
