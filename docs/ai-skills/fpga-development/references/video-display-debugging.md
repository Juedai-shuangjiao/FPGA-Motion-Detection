# 视频显示链路瑕疵排查（PH1P35 竞赛项目实测）

满速 DDR 视频流显示链路的四类瑕疵（白点/切换闪/右边花屏/按键卡顿）的根因与修法。共同特征：**逻辑仿真（iverilog）查不出、下板才暴露**，都是时序/架构/跨时钟域问题。

## 1. 多算法切换闪（原样/灰度/二值/边缘 来回切闪一下）

**根因（两个叠加，缺一不可）：**
- **格雷码跨时钟域同步只解决「打拍采样中间态」**。格雷码转回二进制后二进制值仍会变多位：灰度 001→二值 010 变 2 位、原样 000→灰度 001 只变 1 位。case 组合 MUX 在输入变多位时毛刺——这就是「原样→灰度不闪、其余都闪」的原因（变 1 位不毛刺、变 2 位毛刺）。
- **不同算法模块延迟不一致**：canny/sobel 延迟 8 拍，灰度/二值 0 拍。切换瞬间 valid（8 拍）和数据（0 拍）错位，被下游 data_96bit_to_128bit 打包采到。

**修法：数据 + valid/tlast/tuser + 模式选择信号统一打 N 拍（对齐最长延迟的算法），case MUX 移到打拍之后。** 寄存器输出无毛刺、无错位。N = 最长算法延迟（canny 8 拍）。

**关键教训：格雷码同步 ≠ 消除 MUX 毛刺，两者是两码事。** 格雷码管「跨时钟域中间态」，MUX 毛刺管「组合逻辑多位变化」。寄存器统一对齐才根治，光换格雷码没用（实测）。

## 2. 满速 DDR 时序贴边 → 偶发白点

**现象：** 有光源/挥手/移动摄像头时画面出小白点；无光源不闪。

**排查链（关键是用官方例程做对照实验）：**
- 先怀疑增益跨档位（4x→8x）→ 固定增益 80 后仍有白点，排除。
- 再怀疑光源频闪（交流 LED 100Hz）→ 把官方 lab_ex1 下到同一块板子同场景，挥手/动摄像头均无白点 → 排除物理现象，定位是当前工程引入的。
- 低速版本（半速 DDR）无白点 + 满速 1066 有白点 → 满速 DDR 时序贴边。

**根因：** 满速 1066（usr_clk 133.3M）SWNS 仅 259ps = 3.5% 裕量，温度/电压漂移就偶发 setup 违例，DDR 读数据错 bit。高亮像素（≈255）错一个 bit 就是显眼白点，暗数据错了不显眼——所以「有光源才显眼、无光源不闪」。

**修法：** 降内存速率 1066→800Mbps（usr_clk 100M，SWNS 裕量 2.5ns）。ddr2.v 五个参数：`PLL0_FBKCLK_DIV 32→24`、`tCK 1876→2500`、`CL 7→6`、`CWL 6→5`、`PLL1_REFCLK_FREQ 133.3→100.0`。timing.sdc/pin.adc 不用改（ref_clk 仍 100M 差分晶振，usr_clk 由 derive_clocks 自动派生）。

⚠️ **增益/曝光上限 3990/143 是用户对照板子资料确认的正确值**（增益 143=8x 档，4x 会拍不清晰）。不要建议压回官方例程的 89/4x——官方例程是纯手动没加自动曝光，增益口径不同，不能照搬。

## 3. 右边花屏（最右列 + 下面 1/3 每帧闪）

**根因：** video_out 读地址只在帧开始复位、之后 +8 无限递增，无「一帧读满即停」限制。读触发用 wrusedw（写侧）跨时钟域反馈有延迟，帧尾多读越过本帧缓冲区，读到空隙/下一块的未初始化数据。

**修法：** 加帧内读计数（18 位），帧开始清零、每次读 +1，读满 172800（=1280×720×96/128）后读触发强制停，下一帧复位。一帧 720 次读突发（172800/240 整除），读满正好在突发边界。

## 4. 按键调节卡顿

**根因：** 每次按键调节（曝光/增益变化）都触发跳帧 3 帧（屏蔽异常帧），跳帧 = 画面冻结 50ms，连续按键累积成卡顿。跳帧本意是盖「曝光/增益切换瞬间的异常帧」，但把冻结副作用带给了每次手动调节。

**修法：** 跳帧只在自动模式触发（跳帧触发加 I_auto_en 条件，手动模式 I_auto_en=0）。自动模式后台偶发调节、冻结无感；手动模式用户主动按键、短暂 1 帧花屏比连续卡顿可接受。

## 5. 对照实验法（定位「代码 bug vs 物理现象」）

现象「跟光源/挥手/移动相关」时，别急着下「物理现象（光源频闪/传感器限制）」结论。**把官方例程下到同一块板子、同一场景、同一动作对照**：官方无此现象 → 是当前工程改动引入的，不是物理限制。这是排除物理干扰的最快手段，省掉在「频闪/噪声」方向上瞎猜。
