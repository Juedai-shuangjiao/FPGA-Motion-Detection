# 模式切换帧同步 + 帧级流水过滤拍级对齐 + 仿真坑

## 一、模式切换必须帧同步（KEY4 错位根治）

**症状诊断**：
- 错位「有概率」出现 = 切换拍与帧相位随机，帧中间切换撕裂数据链
- 错位「持续、要再按键或复位才恢复」= 撕裂破坏了行/帧对齐状态，非瞬时闪烁
- 只进出某个模式才错位（其余切换正常）= 该模式链延迟与直通链不一致（例：二分实验撤销统一延迟后 Sobel 8 拍 vs 原样/灰度/二值 0 拍）
- 与「按键本身无关」：检测模式按了无效按键→切回原样→再切算法才错位，根因仍是切换信号帧中生效，不是按键逻辑

**统一修法**（目标时钟域内做，不要在源域做再跨域）：
```verilog
// 算法模式：帧开始（bpc_tuser）拍才应用
reg [2:0] algo_applied;
always @(posedge clk or negedge rst_n)
    if(!rst_n) algo_applied <= 3'd0;
    else if(bpc_tuser) algo_applied <= algo_mode_2d;   // 帧开始采样
// 之后所有数据/valid/tuser mux 一律用 algo_applied，不再用 algo_mode_2d
```
显示模式同理用帧开始脉冲锁存（bg_read 用 S_fs_d512、hdmi_mixer 用 vsync）。

**帧同步不能解决的场景**：链延迟差异仍在（Sobel 晚 8 拍），帧同步只是保证「切换帧完整不撕裂」。若切换后仍持续平移，说明下游按固定时序对齐而非 tuser 对齐——那是另一个 bug（延迟补偿缺失）。

## 二、帧级流水过滤的拍级对齐（块密度过滤进 bbox_stat 的账）

- 块号必须从「统计拍锁存的地址」派生：写流每拍地址前进，累加拍（拍D）时当拍地址已是新字——拍B 锁存 S_wr_addr_b <= S_wr_addr_q，块号组合自 S_wr_addr_b
- 计数拍与累加拍错开：块计数在 S_st_en_c 拍（比统计拍延 1），累加器门控在下一拍；fs_pulse 拍「锁存有效图（cnt>=BLK_MIN）+ 清计数」原子完成帧级流水切换
- 首帧默认全有效（不过滤），否则上电第一帧无统计
- 块宽取 2 的幂个字宽时列块 = 字地址位段移位（/2 = [4:1]），行块用比较链（/80 非 2 的幂）
- 帧级更新多比特信号（亮度 avg）跨域打 2 拍即可（变化慢于时钟域采样），无需格雷码

## 三、定点截断与 tb 反馈环坑

- Verilog `W[17:10]` 位选择在负数上 = 向零截断：-4100>>10 得 -4（0xFC），不是 floor(-5)。定点近似（如 EMA (4a+b)/5 ≈ a+((b-a)×205)>>10）算期望值时按向零截断算
- 衰减/收敛类模块（EMA 背景平均）的 tb：「输出反馈回输入」的逐拍 NBA 环（old<=obg）与实际「每帧更新一次」语义不符，10 拍连续喂同值会把输出拉过收敛点。真实语义：old 固定（DDR 上帧背景值），每帧 1 拍更新，期望波动 = 输入波动/5
- 级联形态学（双次腐蚀）每级代价：+1 行延迟、+1 拍列延迟；tb 检查目标核的行号 = 输入行 + 级数（延迟链方向），不是减
