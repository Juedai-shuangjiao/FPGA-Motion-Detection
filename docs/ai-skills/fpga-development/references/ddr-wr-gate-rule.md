# 写拍吞读命令根因与五处门控铁律（2026-10-29 根因闭环）

## 根因链（五步实锤）

1. video_in 写命令打 1 拍：O_ddr_user_wr_en <= S_fifo_rd_en（写批 valid & ready & grant 打 1 拍）→ 写批 valid 降拍后写命令仍发 1 拍。
2. 仲裁器 I_vi_busy 若只接写批 valid（S_vi_wr_req），valid 降拍即切 VO/BG → 写命令尾拍与读命令同拍。
3. DDR 写优先 → 读命令被吞（命令未执行）。
4. 但顶层标签 FIFO 压入条件 = S_ddr_user_rd_en 照压 → 标签压弹错位。每帧 720 个写批 = 720 次错位累积，帧间随机 = 现象闪动。
5. 连锁症状（三现象一因）：
   - 标签错位 → vo 收 bg 数据/bg 收 vo 数据 → 画面错位（右边界移到画面内）+ 水管涂白（cur/bg 帧内容错位）。
   - bg 的 rd_total 计数与 DDR 实际执行错位 → 读不满（数码管 FC88 = 130184 拍 = 271 行）→ 半帧撕裂细线。
   - 与「半帧撕裂细线」互为表里：读满帧无细线但错位、读不满帧无错位但细线 = 同一根因两个症状（用户直觉正确）。

## 五处门控修复（互相兜底）

1. 顶层读使能：S_ddr_user_rd_en = (vo_en || bg_en) && !S_vi_ddr_wr_en && init_calib（写拍关读 → 标签压同步关 → 压弹匹配）。
2. vo 的 I_rd_grant 接 (S_vo_grant && !S_vi_ddr_wr_en)（vo 读计数/地址递增与 DDR 实际执行同步，防吞命令后计数多 1 累积）。
3. bg_read 加 I_video_in_wr_busy 端口（接 S_vi_ddr_wr_en 写命令拍精确避让），读使能门控（bg 计数同步）。
4. 仲裁器 I_vi_busy 展宽：S_vi_wr_req | S_vi_ddr_wr_en（写命令拍期间仲裁停留 SER_WR，源头防写读同拍）。
5. bg_read 例化接线 .I_video_in_wr_busy(S_vi_ddr_wr_en)。

## 铁律

- 这组门控在「撤销 grant」（20.19）重构时曾整组丢失，任何「撤销/简化仲裁」「直连官方同款」的改动后必须 grep 校验四处门控还在（顶层 rd_en、vo grant、bg 避让、仲裁展宽）。
- 判断写读同拍：grep video_in 的 O_ddr_user_wr_en 是否打 1 拍 + 仲裁 I_vi_busy 接的信号是否覆盖写命令拍。
- 历史教训同源：三轮下板「写拍精确门控三处」就是这个 bug 的第一次修复；标签 FIFO 压弹匹配依赖「压入条件 = 命令实际执行拍」严格同拍。

## tb 复现配套

- 复现实机读满率时 disp_win 必须含真实行消隐结构（每行 493 拍低、显示行 de 高 1707 拍、行周期 2200 拍 @100M 域；720 行 + 场消隐 30 行；帧周期 1650000 拍）。无行消隐结构的旧模型（显示期恒高）仿真读得满、实机读不满。
- tb 计数器位宽先核对上限：line_phase==2199 需 12 位（11 位最大 2047 → 永假死锁 vsync 不出 → TIMEOUT）。
- tb 目前无「写优先吞读命令」模拟（返回队列照收）——吞命令错位靠静态分析 + 三轮下板历史 + 实机现象三源坐实；下板若还错位，加吞命令模拟做差分实验。
- ADDR_OV 断言在 rp 翻转与地址更新竞态窗口假阳性：加 addr > base 方向保护。
