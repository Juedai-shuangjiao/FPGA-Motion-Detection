# 视频链路分辨率切换（720p60 ↔ 1080p30）

SC500/MIPI/DDR/HDMI 视频链路切换分辨率（如 720p60 → 1920×1080@30）的完整检查清单与教训。切换分辨率是「全链路」改动，漏一处就是黑屏/花屏/错行。

## 检查清单（全部要改，缺一不可）

| 位置 | 改什么 |
|---|---|
| 摄像头寄存器表 | uicfg 例化 uics500reg_720p60 → uics500reg_1080p30（分辨率/帧长/MIPI 时序都在表里；官方注释有使用说明先读） |
| VTC | 顶层 uivtc 例化参数整套换（1080p30 标准：H 1920/2200/2008/2052，V 1080/1125/1084/1089）；注意模块内部默认参数可能还残留旧值（被例化覆盖也要顺手修正） |
| uial2axis | IMG_WIDTH/IMG_HEIGHT 参数 |
| ISP | demosaic/awb/BPC/中值/sobel/canny 各例化的 IMG 参数，**逐个 grep 1280/720 确认清零** |
| 像素计数 | h_cnt/v_cnt 回绕值（319/719 → 479/1079）、边界屏蔽（318/711 → 478/1071）——**每个算法模块各有一份，极易漏**；写死的 reg 数组深度（如 canny 强边缘 s_lb1 [0:319] → [0:479]）也要改 |
| hdmi_tx 加密 IP | **例化传参整套换**（HTOTAL/HACTIVE/VTOTAL/VACTIVE/HFP/HBP/HSA/VFP/VBP）+​ **VIDEO_VIC 必须切**（720p60=4、1080p30=34） |
| hdmi_mixer | IMG 参数 + OSD 坐标（按新分辨率重排：TEXT_X/右下角 Y/AE_AG_X/ALGO_X 的 localparam 和行定位字面量） |
| ae_set | 曝光上限按新帧长重算（2×VTS-10：720p60 帧长 2000 → 3990；1080p30 VTS 1127 → 2244） |
| PLL | **不用改**：74.25M 恰好是 720p60 与 1080p30 共用的标准像素时钟（串行 371.25M 同） |
| video_in / video_out | **零改动**：写地址纯递增（帧开始重置基址）+ FIFO 攒批（240 个）是「速率匹配」（100M 写 vs 摄像头数据率），不是分辨率匹配；读窗口 = de 直通；读节奏 FIFO 水位驱动。1080p 只是每行批数 1→6，机制自适应 |
| DDR 乒乓地址 | 官方布局（0/7M/14M/21M）本就按大帧留间隔，1080p 一帧 1555200 个 128bit < 7M ✓ 不用动 |

## 坑与教训

- **加密 IP 的例化传参会覆盖模块声明默认值**：查 .enc 文件声明参数是 1080p 没用——hdmi_tx.v 例化时传了整套 720p 参数。黑屏、连 OSD/logo 都没有（显示链路本地生成，不依赖摄像头）= 查 VTC/HDMI 编码器/VIC，不是摄像头问题。
- **VIC（HDMI AVI InfoFrame 视频识别码）不对 → 显示器直接拒显黑屏**。官方寄存器表注释的「使用说明」点名要切 VIC——先读官方注释里的切换清单，再对照逐项 grep 残留（720p 特有值 1650/750/1280 等）。
- **分辨率切换的残留扫描**：grep `IMG_WIDTH(1280)`、`IMG_HEIGHT(720)`、`14'd319/14'd719/14'd318`、`[0:319]` 等新旧值对，两轮扫描才抓全（第一轮漏了 BPC/median_filter 的计数回绕和 sobel/canny 回绕第二行）。
- 帧率 60→30 的行为变化：跳帧 3 帧 = 100ms 卡顿、AEC 帧计数节奏减半——均按帧自适应无需改码，但调参预期要变。
- 1080p 全分辨率「消隐期读两帧」检测在 1080p30 下带宽做不了（消隐 5.4ms、需 7.8ms），1080P 版定位 = 显示/采集链路验证 + 画质对比。
