# 资源优化：TD 不推断 SRL 的写法（2026-11-01 区域填充超限实锤）

## 现象
slice 112.6% 超限 2683 片——模块 LUT 1659 + FF 3268，FF 暴涨。phy 报告 `#shifter lut = 0`（全工程没有一个移位寄存器用 LUT 实现）。

## 根因
TD 对「带复位/帧清分支」的移位链**不推断 SRL**：
```verilog
always @(posedge clk or negedge rst_n)
    if(!rst_n) sh <= 0;
    else       sh <= {sh[W-2:0], din};   // ← 全部展开成 FF
```
一条 1280 拍延迟链 = 1280 个 FF（而不是 1280 个 LUT 位）。

## 正确写法
1. **无复位纯移位**（官方 SRL 推断模板）：
```verilog
always @(posedge clk)
    sh <= {sh[W-2:0], din};   // 推断 SRL，LUT 实现
```
2. **数组+指针写法**：加属性强制分布式 RAM：
```verilog
(* ram_style = "dram" *) reg [W-1:0] buf [0:D-1];
```

## 验证
- phy 报告 `#shifter lut` 应 > 0
- slice 暴涨先查所有长延迟链的写法

## 案例数据（区域填充第一版）
- ori 原图链 2576 FF + 独立膨胀链 2560+8+1288 FF + row_fill 数据链 1280 + 直通链 1280 + drain 320 + valid 320——全部带复位写法 → 全变 FF
- 优化方案：edge 改 open^erode（省 5144 FF）+ row_fill 大链 DRAM 化——预计压到 +1500 slice 以内

## 三路并行资源纪律
- 延迟链一律无复位纯移位写法
- 清晰度提升禁止新增行缓冲（复用 morph 现有 3 行窗口）
- 融合预算：三路合计 slice ≤ +1500（基线 19321/21216=91.1%），ERAM ≤ +6 块

## 高占用下的布线拥塞违例识别（fuse13 92.73% 实锤）
- slice >91% 后布局随机性上升：新增几百片就可能触发某时钟域 setup 违例，且违例路径 cell 延迟占比 <5%、net 占比 >95% = 纯布线拥塞主导，不是组合逻辑深。
- 修复方向不是跟布局较劲，是降资源 + 切长组合链：对角算子 Scharr 系数降 Sobel（[3 10 3]→[1 2 1] 省 ~600 片）、统计累加输入打 1 拍切断「卷积+argmax+累加」长链、常数乘法改显式移位免 DSP。资源回落到 ~91% 即全绿。
- 判读技巧：final_timing.rpt 违例路径的 cell/net 占比一眼定性；cell 占比大 = 逻辑深（拆流水），net 占比大 = 拥塞（降资源/换布局 seed）。

## 除法器与 OSD 数值显示的省法（外接框/质心实测）

**恢复余数除法迭代拍数 = 被除数位宽，不能按商宽缩短**：低 DW-QW 位也要逐拍推进余数寄存器，截断迭代会把商算错（低 16 位对商的影响可达 2^16/除数）。「商宽压缩」只能缩商寄存器位宽（27bit→11bit 小省）；真正的大头省法 = **x/y 分时复用同一实例**（分母相同、帧内时间充裕：2×(DW+1)=56 拍 << 帧周期 166 万拍），两个并行实例合成一个，面积减半（实测 2×27/26bit ≈ 200~300 slice → 单实例 ≈ 50~80）。恢复余数除法的大位宽比较要拆段（高 11 位 + 低 20 位两级比较）配合 dsp_style="no"，防止 TD 把比较映射进 DSP。

**OSD 坐标显示用十六进制 = 零 bin2bcd**：十进制显示每新增一个数值就要一个 bin2bcd 实例（~100~150 LUT）；改为 3 位 hex 直显（`function hex2char` 把 4bit 映射成 '0'+n/'A'+n-10 的 ASCII，ASCII 字模库已有），坐标 0~1279 用 3 位 hex 覆盖，零新增实例零新增字模。演示级坐标显示满足简介承诺即可，别为十进制美观烧几百 LUT。位宽越界警告：hex 提取前注意端口位宽（11bit 信号取 [11:8] 会 HDL-8007 越界，高位补 0 成 4bit 再进 hex2char）。
