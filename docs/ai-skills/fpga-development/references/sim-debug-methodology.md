# 仿真调试方法论（2026-10-26 深夜教训，用户指正后总结）

## 铁律：先 dump VCD，再分析；禁止一轮一个 $display 重跑循环

探活性例外：只想知道「信号有没有在跑/计数涨不涨」时，先注释掉 $dumpvars 改用周期性 $display 探针（$time + 关键 reg 快照，如每 1ms 采样一次行计数）——不带 dump 跑得快一个量级，长仿真不超时；定位到可疑区间后再开 VCD 细查。全量 dump 长仿真会拖到超时，不要默认一直开着。

打印探针多轮二分仍定位不到时（用户认可的兑底手段）：把关键信号链的 VCD 事件画成时序图（Python 按时间轴画多信号波形，或文本波形行），一次看全「谁先变、变什么、间隔几拍」——比再跑一轮打印直观；打印与 VCD 矛盾/拍序对不齐时尤其要先出图再推演。

旧方式（低效，被用户批评）：$display 打单拍快照 → 看输出 → 再加打印 → 重跑仿真 3~4 分钟 → 循环十轮。每轮只能看几个时刻的静态值，看不到信号随时间变化，定位一个 X 源头花了一晚上。

新方式（高效）：tb 里一次 $dumpfile + $dumpvars 抓全部信号 → 一次仿真 → Python 脚本解析 VCD（vcd_parse.py 在 WSL scratch 目录），按名字找信号、查任意时刻值、统计窗口事件、看完整变化序列。一轮仿真全部分析完，不再反复重跑。

```verilog
initial begin
    $dumpfile("tb.vcd");
    $dumpvars(0, u_dut);   //只 dump 关键层级，别全 tb（文件小、跑得快）
    ...
end
```

## VCD 负证据不可信：0 事件 ≠ 信号恒 0（用打印探针定论）

排查「某机制不工作」时，VCD 查询显示某 reg 全程 0 变化事件，不能直接断定该 reg 恒 0——**VCD 的负证据（无事件）不如正证据（探针打印到实际值）可靠**。本会话 S_row_gap 在 VCD 里 0 事件，据此怀疑 gap 机制坏了推演一整轮，最后层次引用打印探针（`if(u_dut.S_row_gap) $display(...)`）证明机制完全正常、每次行尾都置位。VCD 与打印矛盾时，优先信打印探针（它直接读仿真内核当前值，不经 dump 管线）；「恒 0」结论必须由正证据（打印/断言/自由计数）坐实，别由「VCD 没事件」反推。

## 打印读拍前值、非阻塞锁存读拍末值（打印与锁存不一致的第一解释）

组合信号（assign/组合输出）在拍内变化时，`always @(posedge clk) if(valid) $display(data)` 读到的是 posedge 时刻的稳定值（= 上一拍末），而下游 `always @(posedge clk) reg <= data` 非阻塞锁存的是**拍末值**——两者可差一次「拍内变化」。本会话 FILT 探针打印 0000 而攒字器同拍锁存 1111，险些据此误判「morph 输出数据源错」。打印探针与「实际消费值」对不上时，先考虑这条时序差（打印 +1 拍再比，或打印锁存后的寄存器而非组合源），再怀疑 RTL。

## VCD 事件时刻 = 变化生效时刻（拍序对齐）

非阻塞赋值在拍末生效，iverilog VCD 的变化事件时间戳标在「生效时刻」= 下一拍起点。用 VCD 对齐「第 N 拍的值」时：事件 t=X 表示「拍 X 起点起该值有效」= 上一拍末更新——拿事件时刻直接当「该拍执行拍」会错 1 拍，多信号拍序交叉对齐反复错位时先把全部时间戳统一到「拍起点」口径再推。

## 断言 > 人眼比对

不变量（计数一致性、状态合法性）写成 always 检查 + $display/$fatal 自动报，不要靠人眼在打印行里比对数字。例：FIFO 本地计数与写弹差的关系、状态机非法状态。

## 组合信号不产生 VCD 变化事件（iverilog）

iverilog 的 $dumpvars 对「纯组合 wire/assign 信号」可能不产生变化事件（文件里只有 $var 声明无变化行）——需要分析组合信号时：dump 它的时序输入 reg，自己算；或改用 GTKWave 读 FST。本 tb 里 S_fifo_re/S_row_go/S_ret_hit_cur 均无变化事件，改用 S_row_pop_cnt 等 reg 的递增事件统计弹拍。

## valid 门控流水线的延迟记账：按有效拍逐级推导，别信前一会话留下的数字

valid 门控链（I_valid 拍才推进）的延迟按「有效拍域」记账：只数 I_valid=1 的拍，空洞拍不占延迟。逐级推导定式（v = 有效拍序号，g(v) = 输入组）：n 级寄存器链的输出中心 = g(v-n)；组合输出在拍 v 的值 = 拍前寄存器值（组合拍前效应已含在前一级延迟里，别再重复 +1）。例：水平腐蚀 2 级 → ero_h(v)=g(v-2)；+320 垂直 → ero_v=g(v-322)；+2 → dil_h=g(v-324)；+320 → dil_v=g(v-644)。

铁律：
1. **valid 链深必须 = 数据延迟有效拍数，错 1 拍 = 下游每个数据错位 1 个数据单元**：valid_chain[N] 的尾延迟 = N+1 拍，数据延迟 L 拍就要链深 L 位、取 valid_chain[L-1]。valid 链比数据早 1 拍时，攒字器把第 n 个数据放进第 n+1 组 → 标记整体水平错位（4 像素/组）。**给链尾加输出寄存器时的延迟账：数据延迟变 L+1，valid 链也要 L+1 拍（保持原链深 + 输出寄存 1 拍），不是「缩 valid 链保持总延迟不变」**——输出寄存对 valid 同样是 +1 拍。误缩 1 位 = valid 比数据早 1 拍 → +1 组偏移（tb 首字 0xF0 实锤）。任何一级加/减寄存器后，先逐级重推数据延迟、再定 valid 链深度，别沿用旧数字。
2. **改延迟链前先自己逐级推导，别信文档/前一会话留下的延迟数字，也别盲从其拟定的修复方案**：上一会话文档的延迟口径可能本身就是错的（把组合拍前效应重复计 1 拍），其拟定的「给某级组合输出打 1 拍」方案也可能是错的——打拍会整体平移窗口，「下行 = 当前拍组合输出」变成「下行 = 同行 k-1 组」。推导结论与文档方案冲突时，以推导 + 仿真为准。
3. **垂直/行方向窗口自洽性先验证**：行长度 = 320 有效拍时，垂直 1×3 窗口的「下行」= 当前拍组合输出、「中心」= 320 拍前、「上行」= 640 拍前——相邻行同组在流中恰隔 320 拍。
4. **tb 判据的期望值本身会错，FAIL 先推导期望再怀疑 RTL**：DUT 输出图案结构上合理但判据 FAIL 时，按输入图案（解包相位逐组算：A/B/C/D 组各是哪个 128bit 的哪段）+ 算法逐级窗口重新推导期望值。旧判据「行 0 首字全 0」（漏算膨胀下行扩散）、「行 1 首字 0xFFFF」（没按解包相位算 B 组实际差异位）两处全错的案例：推导结果与仿真一致且自洽时，改 tb 判据不改 RTL。**RTL 时序类修复后必须同步更新判据的「抓拍值」**：判据按旧行为写死（如首字写拍 addr==1），修复后（写拍递增 addr==0）判据抓到的是第 2 个字（数据全 0）→ FAIL 假警报、误导一整轮定位。地址/拍数/计数类判据预期随 RTL 改动同步改；判据 FAIL 且刚改过时序行为时，先核对判据预期是否还是旧口径，再怀疑 RTL 本身。
5. **valid 门控链的帧尾排空（DRAIN）——帧尾数据排不出只能清链丢弃的根治**：帧间断层无 I_valid → 链尾数据永远排不出 → 清链丢弃 → 每帧尾固定丢链深拍数据（实机 = 屏幕中部/底部固定 2 行标记永不更新 = 黑线，只在叠加活跃时可见）。修法：读满 + 两 FIFO 弹空 + 解包输出停（valid 拉低）再等 8 拍后，强制 I_valid=1 恰「链深」拍、I_data 强制 0——链内滞留的真实数据在链深拍内全部排出（下游照常消费，尾部行写满），假 0 数据要链深拍后才到链尾、DRAIN 已结束不输出（零污染）。三要点：①防重入——DRAIN 完成后「读满且弹空」条件仍成立，不加 S_drained 标志会无限重触发、假数据写越界覆盖下一半帧；②DRAIN 拍数 = 链深，多拍输出假数据、少拍真实尾部排不完；③读满必须早于帧边界足够多（消隐期内读满 → 排空窗口充裕），DRAIN 期间帧开始到 = 清链中断丢尾，退回旧行为无害。
④**DRAIN 触发判据别用读满后即变的组合阈值（对称配置不暴露、非对称配置必中）**：half_sel 在读满拍立即翻转（与停读同拍），而 S_total_cap 是 half_sel 的组合派生 → 读满后 cap 立即变成另一半的上限 → 判据 (S_rd_total==S_total_cap) 恒假 → DRAIN 永不触发 → 每帧尾固定丢链深拍数据（特征值：fg_wr_addr = 理论写满 − 65 字）。两半上限相同的对称配置下判据恰好成立所以仿真通过、非对称配置必中。修法：状态翻转拍同时锁存完成标志（S_full_done），事后判据一律用锁存快照。通用规则：判「过去事件」用锁存值，不用实时组合值。

## VCD 格式三个坑（vcd_parse.py 已处理）

1. 多字信号名带位范围后缀：`$var wire 19 %" S_rd_total [18:0] $end`——名字后跟 [n:m]，正则要允许。
2. 1 位信号变化行无空格：`0&"`（值+code 连写），多位是 `b1010 %"`。
3. 变化行值带 b 前缀（binary）。
4. **多 bit 值前导零被剥掉**：iverilog 写 VCD 时 `4'b0110` 常写成 `110`——按信号声明位宽在左侧补零再解释（110 + 位宽 4 = 0110），直接把 3 位值当「3bit 信号/十进制约 6」会判错图案。
5. **空洞拍使「第 k 个有效拍」的日历时间非线性**：valid 门控流里相邻有效拍间隔 1~4 拍不定，按 `t0 + k*period` 线性外推取样必然错位（白查一轮）。要按拍序号取样：先取 I_valid/O_valid 的完整变化事件时间线、过滤上升沿得有效拍时间戳数组，再按序号索引。注意 timeline 查询超 max_events 会被均匀抽样（得「只有 12 个样本」假象），事件密集信号要么调高上限要么分段窗口统计。
6. **分析前用 VCD 的 $var 行确认「信号名 ↔ code 字符」一一对应，别信 find 模糊匹配**：find() 用 re.search 部分匹配，可能匹配到多个信号，打印出的 code 未必是目标信号的（本次把别的信号的 code 当 hdmi_pixel 用，分析出每拍都变的「诡异像素序列」绕了多轮）。铁律：`grep "$var wire <位宽> " tb.vcd` 看目标信号的 code 字符，再用 `grep -cE '<code>$' tb.vcd` 数事件——每拍都该变的信号事件数只有个位数 = code 抓错信号，立即回 $var 行核对；信号名带 `[n:m]` 后缀时正则别漏。
7. **「变化事件序号」≠「拍序号」：VCD 只记值变化拍，同值拍无事件，按事件序号数像素必错位**——把「目标窗口后前 N 个事件」当「前 N 个像素/拍」读，遇到同值段（如解包同 enc 的连续 3~5 拍）会整体漂移，得出「每拍都变、丢字模式诡异」的假序列。拍级精确取证用 $display 打印对照（每拍含重复值可见），VCD 只回答「何时变、变成什么」。配套两坑：①多帧仿真抓「帧 N 头」用事件沿序号（如 vsync 第 2 个下降沿）定位，序号错 1 = 抓错帧（帧 1 头 vs 帧 2 头数据完全不同，分析一整轮全错）；②带计数上限的探针（`dbg < N`）在目标窗口之前的触发也会消耗计数——窗口前的事件把上限耗尽 → 目标窗口零打印（表面像「触发条件没满足」），打印条件必须带窗口过滤（帧号/时间窗）且上限留足余量。

## 定点算术的两个坑（EMA/均值类 RTL）

1. **有符号数的位选择 ≠ 算术右移**：`W_d5_r[17:10]` 对负值取的是「补码除法向零截断」（-4100 取位得 -4），`>>> 10` 才是算术右移（floor，得 -5）——两个语义差 1，tb 期望值与 RTL 位选择混用时必错位。定点近似文档里写「>>10」时必须注明实现是位选择还是算术右移，按实现语义推期望。
2. **移位近似除法的系数必须带常数偏差校验**：mean = sum>>20 对「cnt 恒定 ≈2^19.8」的帧级均值有固定 13.8% 偏差（2^20/921600=1.1377）——设计「×1.5 阈值」时把偏差吸收进系数（T = a + a>>2 + a>>3 组合出 1.564 而非直觉的 1.5），tb 期望值按实际系数推，别按理想公式手算。

## iverilog 语法小坑（编译秒报，别在 RTL 上怀疑）

1. **拼接/位选不支持「表达式直接位选」**：`{2'b0, (wloc+1)[5:0]}`、`(s-1)[5:0]` 都是 syntax error（iverilog 只允许信号名/reg 直接位选，带括号表达式不行）——先算中间变量（`wloc1 = wloc + 1; enc = {2'b0, wloc1[5:0]};`）再拼。写 tb 期望模型/参数化表达式时必踩，先写中间变量省一轮编译。
2. tb 里 `begin : blk` 命名块内的 reg/integer 声明必须在块语句前（Verilog 块内声明前置），case 分支内声明会报错——期望生成块写法 = 命名块开头集中声明、中间算、末尾比较。
3. **`edge` 是 Verilog 关键字（posedge/negedge 用），不能作信号名**：tb 写 `reg [3:0] edge` 报 syntax error 且报错位置诡异地指到模块头。避开：命名 eg/e_data；批量替换用词边界 sed `s/\bedge\b/eg/g`（\b 保证 posedge/negedge 里的 edge 不被误伤，o_edge/exp_edge 这类含下划线名字也不动）。
4. **iverilog 的 task 端口声明兼容性差（ANSI 风格与旧式 input 声明都可能报 syntax error）**：`task check(input [10:0] expect);` 与 `task check; input [10:0] expect; begin...` 两种写法在新旧 iverilog 上都实测报「syntax error in task/function port declaration」，`input integer id` 同样报错——逐拍检查断言不要封装成带参 task，直接内联 `total=total+1; if(信号!==期望) ... else $display(PASS...)` 最稳；task 只装无参数激励拍（置位→posedge→复位）。

## tb 激励进程的采样竞争（激励写法三坑）

0. **task 入参是「调用时求值」的快照，不是延迟引用**：`check(名, cond)` 式 task 的 cond 参数在调用拍立即求值——若 cond 是组合信号（如 `blk_en === 1'b1`），而激励刚用非阻塞赋值更新其依赖（row/col 的 NBA 还没生效），task 收到的是旧值快照，随后 task 内 @(posedge) 后采样到的已是新值 → 判据与期望错位、FAIL 假警报（症状：FAIL 处打印的实采值明明是期望值）。修法：task 只传「期望值」（常数入参）+ 信号名，task 体内 @(posedge) 后实采再比较——`check(name, exp)` 内 `if(实采信号 !== exp)`；判断逻辑一律放在延迟采样之后，别把组合信号的即时值当参数传。

1. **激励在 @(posedge clk) 恢复后立即阻塞赋值信号，与 DUT 的 @(posedge clk) 采样构成同一 time step 调度竞争**：谁先恢复不确定 → DUT 可能采到上一拍旧值 → 全链输出与期望错开 1 拍、比对成段 FAIL（症状 = 错误数量巨大、期望与输出像是错位一拍的同一序列）。修法：激励一律「@(negedge clk) 设置信号 → @(posedge clk) 让 DUT 采样」——半拍提前，DUT posedge 采样时值已稳定；封装成 beat/gap_beat/fs_pulse 类 task 统一节奏。复位释放（rst_n<=1）、帧清脉冲、key_pulse 单拍脉冲全部同规。
2. **task 封装激励拍时，task 结束前必须把瞬态信号归位**：beat task 若只在开头置 valid=1 而不在返回前拉回 0，task 结束后 valid 残留 1 → 后续 gap/排空/等待期间 DUT 每拍都收到虚假有效拍 → 输出凭空多出数千拍、比对 k=j−L 越界全错。铁律：task 里「置位 → posedge → 复位 → 再 posedge」成对出现；或放弃 task，把整段激励序列做成数组、单循环逐拍显式驱动全部信号（每拍 valid/data/drain 显式赋值，零残留）。
3. **黄金模型比对的输出索引定式：输出拍 j ↔ 输入拍 k = j（同索引，2026-11-01 fill 会话 diag3 实测修正）**：持续 valid 流中，第 j 个 O_valid 拍的内容 = 第 j 个输入拍（延迟 L 体现在「出现时间晚 L 拍」，输出序与输入序同索引，不是 j−L）。旧口径「k = j−L」在 j<L 时全部越界跳过、错过第一批输出比对。比对进程维护全局有效拍计数：k>=g_total（不该再有输出）报多余拍。帧清后输出寄存直通 1 拍 0（清链尾），帧清后的映射 = 帧清基准重对齐 + 直通拍补偿（fill 会话实测：场景 B 映射 k = j+320 = j+延迟−1）。帧清链后被丢弃输入区间 [g0−L, g0) 的输出必须为 0——比对进程对该区间显式断言「泄漏」；帧清后的行号/组号映射按「帧清后首拍 g0」重对齐（(k−g0)/320 等），不能继续用全局 k/320。多场景 tb（帧清前后）用「帧清基准 offset」双映射，比拆成多个 tb 简单。
5. **写 tb 前先确认 DUT 复位极性（高有效还是低有效），复位极性写反 = 复位恒拉、初值检查 PASS 其余全 FAIL**：DUT 的 I_rst 高有效时，tb 写成「#50 rst=0; #20 rst=1;」把释放写成拉高 → 此后 rst 恒 1 = 永复位 → 复位值检查 PASS（复位值本来就是对的）、所有后续激励检查 FAIL 且值恒 = 复位值。指纹 = 首项 PASS、其余全 FAIL、值卡在复位值不动——先查 tb 复位段极性再怀疑 DUT 逻辑；「再复位」段同理（拉高复位 → 拉低释放）。
4. **`while(!cond) @(posedge clk)` 采样错 1 拍——条件在 posedge 沿评估用拍前值**：`while(!(x==100)) @(posedge clk);` 退出时 x 已推进到 101（沿评估拍前值 x=100 才退出）→ 退出后采样采的是 x=101 拍 → 逐场景验证时「本行 mark」「无 mark 区」类判据错 1 拍、断续 FAIL（且过/败交错看不出规律）。修法：等待目标拍的前一拍 + `@(negedge clk)` 半拍后采样（`while(!(x==99)) @(posedge clk); @(negedge clk);` 落在 x=100 拍内、组合已稳定）。同款坑：tb 组合激励与坐标计数器同拍竞争（mark_comb 组合依赖 x/y 计数器、计数器 posedge 更新）→ 注入值进链的「槽位」错 1 拍——激励改为 posedge 置位（x=99 拍置位 → x=100 拍稳定），建模真实「寄存器稳定输出」路径，别用依赖计数器的纯组合激励。

## X 的常见来源排查顺序（本工程验证过）

1. **tb 例化漏接新端口**：改 RTL 加端口后 tb 没接 → 端口悬空 X → 组合链毒化。三元 X?A:B 在 A=0/B=1 时输出 X。**改 RTL 端口必须同步改 tb 例化**（编译不报错，仿真 X 阴魂）。
2. **iverilog 12.0 的 always @(*) 在输入信号从未变化时不触发**（不按标准在 t=0 执行一次）：tb 激励信号恒 0 → 组合块永不执行 → 输出 X。仿真激励必须让输入至少变化一次；实机 TD 综合成 MUX 无此问题，但仿真会误导——下板行为与仿真不一致时先检查 tb 激励是否与真实信号行为一致（真实 rp 每帧翻转，tb 恒 0 就是 bug）。
3. **reg 未复位**：复位路径缺失 → 上电 X → 传播。
4. **异步 FIFO 计数延迟**：wrusedw 是异步同步 2~3 拍延迟值，RTL 门控用它做实时判定会追尾弹空 → underflow X。门控改用本地实时计数（写口径与 we 一致、弹口径与 re 一致、同拍相消）。
5. **解包/pending 缓冲寄存器无复位 → 输入空洞拍走 else if(X) 输出 X 垃圾污染整条下游链**：数据解包器（128→96 之类）的 pending 缓存（S_pending_valid/S_pending）若只有数据路径赋值、无复位，上电 X 会在「首数据到达前的空洞期」（帧开始→首弹可长达数百拍）使条件判断走不定分支，输出 X/垃圾 valid，毒化 morph 行缓冲、攒字器、ERAM 写入（实机同样成立：上电随机 0/1 → 帧间残留垃圾）。三种隐蔽形态一次查齐：(a) 复位端口接了但 always 块只挂 posedge I_clk 没挂 negedge I_rst_n——注释写「rst 清 pending」但模块内无对应逻辑，接口接了 ≠ 逻辑生效；(b) 帧头复位脉冲发在「首数据拍」太晚（空洞期已泄漏），提前到「帧开始拍」不破坏相位——无输入时 cnt 保持，首个数据仍按相位 0 解出；(c) 帧头复位只清计数不清 pending。修复三件套：always 挂异步 rst、帧头清 pending+pending_valid、帧头复位提前到帧开始拍。

**X 入口多路监视（一次仿真定位 X 从哪个接口进来）**：在 tb 数据链的关键接口各挂一个「X 监视打印」——`if(^sig === 1'bx) $display("<名>_X t=%0t ...")`——标签/地址/返回数据/比较器输入/存储写入数据各一路，谁先打印、打印什么值（如标记 11xx 说明低 2 位 X），X 就从那个口进来的、传播路径一目了然。比逐模块推演快一个量级；配合「X 首拍的全局计数」（如有效拍 mcnt）可反推注入时刻对应的读命令/源数据拍，再上 VCD 波形细看该拍。注意 X 监视打印本身要在 tb 里（层次引用或接口级），不要为它加 RTL 探针。

**X 在 RTL 内部但所有 RTL 输入干净 → 中间隔着 tb 行为模型，先查模型再改 RTL**：接口级 X 监视显示「RTL 各输入无 X、RTL 内部信号 X」时，X 产生在 tb 的行为模型（FIFO/标签队列/延迟链）里，改 RTL 是徒劳。模型两类高频 X 源：
(a) **数组型队列空读**——标签/元数据 FIFO 用数组+读写指针实现时，读指针无门控读未写元素 → 元素 X → 标签 X 毒化下游收数路由（复位后 rptr=0 立刻读 mem[0]（未写）= X，打印表现为 `TAG_X wptr=0 rptr=0 elem=x`）。修法：读数组与 rptr 递增都加 `rptr != wptr` 门控，空拍输出给默认值（背景读返回默认标签 0）；修复验证 = 该 X 打印除复位前外全部消失。
(b) **mem 索引位宽越界**——FIFO 模型计数器常比 mem 深度多 1 位（判空满），若直接用全位宽指针索引 mem，指针越出 mem 深度区读 X。排查：打印 X 拍模型内部 wptr/rptr/cnt（层次引用 `u_dut.U_fifo.<例化名>.wptr`）——cnt 非空、写入口数据无 X 却读 X 时，比对指针值与 mem 深度（本会话实锤 rptr=513 > 512 深）。修复 = 索引处截断 `mem[wptr[ADDR_WIDTH_W-1:0]]`、`dout <= mem[rptr[ADDR_WIDTH_R-1:0]]`（真实 IP 内部即如此，10bit 计数只用于空满判断）。**数组型队列模型同款**：命令队列 `cmd_addr_q[0:511]` 配 10 位指针、延迟链数组、标签 FIFO 都是同一模式——读写索引一律截断到深度位宽（`cmd_addr_q[cmd_wptr[8:0]]`）；指针位宽与深度恰好匹配的（1024 深配 10 位）无需截断。截断漏掉的表现 = 指针绕第二圈（第 512 个入队）之后才读 X：前一帧头正常、后一帧头起 X。

**两路输出同拍同时 X（cur=xxxx bg=xxxx）→ X 在共用上游而非各自模块**：两路独立的解包/FIFO 同拍输出 X 的概率极低，同拍同 X 直接指向共用源（DDR 返回数据/读地址/标签链），把二分窗口立刻收窄到共用段，别在两路各自内部找。

## 时间单位核对

$display 的 %0t 和 $time 在 timescale 1ns/1ps 下以 ps 计（295000 = 295ns）。VCD 的 #timestamp 单位 = $timescale 声明（1ps）。换算错会采错窗口、白跑一轮。分析前先确认单位。

## 编辑与声明纪律（2026-10-27 凌晨 20.23 教训）

1. **替换/补丁报成功 ≠ 真落盘**：替换目标文本与磁盘文件实际写法不一致时，编辑工具可能报 success 但实际没改到（旧写法「wire = expr 声明即赋值」已被改成「wire 纯声明 + assign」后仍用旧文本做目标 → 假成功）。任何关键编辑后必须重读文件验证新内容确实在磁盘上（比对位置/次数），再信。同款形态（execute_code 批量编辑脚本）：**脚本中途 assert 抛异常 → 文件 write 根本没执行 → 前面所有 replace 全部丢失**（内存里改了、磁盘没动，下次运行还从旧文件出发）——批量编辑要么先跑完所有校验再统一写盘、要么 try/finally 保证落盘；每个 replace 后跟 count==1 断言防静默无匹配。**CRLF 文件的锚点匹配**：文件是 CRLF 行尾时，用 \n 结尾的锚点做 patch/replace 会静默失败或只中部分行——先 read→decode→统一 replace("\r\n","\n")，全部替换完成后统一转回 CRLF 写盘，写回后校验裸 LF 计数为 0。\r 不可见，用 file 命令先确认行尾再选策略。
2. **TD 隐式网拆网分两档**：wire 声明即赋值（wire = expr）在使用之后 = 拆网高危（TD 把先使用的隐式网与后声明的新网分开 → 使用点接 undriven 隐式网 → 接 0 → 功能断）；纯 wire 声明（无赋值）在使用后 TD 通常合并（只有 HDL-7225 警告、功能正常）。reg 先使用后声明同样修。
3. **前移声明前先查依赖链**：把 wire = expr 声明前移时，它引用的信号声明必须在更前，否则制造新隐患（isp_top 的 algo_tuser 前移会反转 algo_mode_2d/sobel_*/bpc_* 依赖——评估后保持原样）。
4. **扫描脚本甄别**：全工程「先使用后声明」脚本会误报——数字字面量（14'd0 里的 d0）、function 局部变量、parameter 名、注释里的词、模块名/端口名都要人工排除。
5. **大改动/下板验证通过的版本先 git 快照再继续改**（用户工作方式，明确要求过）：工程首次建仓时 .gitignore 排除编译产物（prj/FPGACompetition_Runs/、*.db、*.bit、*.rpt、*.end.f、*.begin.f，与并行工程同款），提交信息写清「本轮改动 + 待修现象清单」——回退和交接都靠它；用户说「先 git 一下保留当前版本，git 完告诉我，同意后再开工」时，git 完必须停下等确认，不要自作主张往下改。
6. **sed 替换 Verilog 数字字面量（含撇号）的转义坑**：`sed 's/1'b0/2'd0/'` 类替换若撇号转义写错（产出 `2.d0`）会静默留下非法字面量——iverilog/verilator 不报、TD 综合才报 `digits must follow decimal point in real 2.`，一轮编译白烧。sed 单引号脚本里撇号一律写 `\x27`（GNU sed）；替换后必 grep 残留验证（`grep -n '\.d0' 文件`），命中项里行首缩进 + `.d0 (` 端口连接格式的是合法端口名（如 ODDR 例化的 .d0），其余 = 笔误残留。批量改位宽优先用 patch 工具逐处改（自带 diff 可见），sed 只用于量大且同型处，改完必 grep。
7. **GUI 编译占源文件时（read_design 后），并行验证改动 = 复制 RTL 到 sim/ 子目录改变体 + tb 引变体编译**：不动 src、不污染编译中的工程；变体验证通过后等编译完再把改动合入 src。改变体删信号后必须 grep 已删信号名零命中（残留引用 = 编译报错或静默接旧值），tb 层次引用已删信号会以编译错误形式报出来，正好当检查清单。

## 对照激励二分：一个 tb、多个 parameter 变体跑出对照表

**前置铁律：仿真里「模块输出恒 0/恒无输出」先验证自己的激励控制信号真的产生过，再怀疑 DUT**（本会话 demosaic 两轮「O_tvalid 恒 0」假结论：第一轮 tb 的 cycle 计数上限写错导致 tlast 永不产生，demosaic 行缓冲永远等不到行结束 → 输出恒 0 是激励 bug 不是 RTL bug；第二轮是注释清理脚本把例化端口整行注释掉）。验证法：tb 加周期性 $display 探针打印 tlast/tuser/tvalid 输入（每 1ms 采样一次），确认行结束/帧开始脉冲真实存在且频率正确，再下「DUT 卡死」的结论。

定位「某信号异常但下板不可见」时，把 tb 写成 parameter 化激励（例：帧开始恒 0 / 恒 1 / 每行 1 拍三档），一档跑一次仿真，输出对照表（计数/锁存/事件数）。用「哪个档位能同时解释全部观测」排除假设：写 0 + FIFO 满锁存 0 + 上游 valid 恒 1 的组合，恒 0 档 FIFO 会涨满（满锁存应 1）、行频档写批能完成（写计数应 >0），唯一自洽档 = 恒 1（FIFO 恒复位）。比在 RTL 里逐模块翻代码快得多。

**切长链的 mini tb 桩替代（秒级差分，比 full tb 快两个量级）**：定位「写地址/攒字器时序档位」这类局部时序问题时，把上游长链（morph 等）换成桩（连续 valid + 已知组序列 + 单点注入），被测小逻辑按 RTL 同构抄入 tb，`ifdef MODE_x 做 N 个时序档位、一次编译 N 个 vvp 各跑秒级——哪个档位落位精确一目了然；定档后再跑 full tb 回归。注意 iverilog 不支持 `` `if 表达式 ``（`if FGMODE == 0 被当 `ifdef 解析报 elsif 不匹配），档位用 `ifdef/`elsif/`endif。full tb 与 mini tb 结果不一致 = 差异在桩掉的部分（帧边界间隔/写拍门控/行消隐结构），把 full tb 的差异要素逐个加回 mini tb 复现，比在 full tb 里 25 分钟一轮二分快得多。

**新增锁存/门控机制引起回归时，先「临时停用」确认因果再查实现**：把嫌疑机制的锁存源临时置 0（机制等效停用）跑一轮对照——回归消失 = 机制实现有口径/对齐 bug（查计数口径与对齐，别急着删机制本身）；回归依旧 = 元凶在别处。一轮仿真定因果，比读代码猜快。

**集成矛盾 = 单模块 tb 复现 + 三层探针二分**：模块单测 PASS 但集成输出错时，把集成里抓到的「模块实际输入序列」原样抄进单模块 tb 秒级复现——输出与单测一致 = 模块无辜、矛盾在例化接线/valid 时序；输出复现异常 = 模块对特定输入序列有洞（单测场景没覆盖到该序列）。同时集成 tb 里加三层探针定位错位断点：上游输出（如比较器 4bit 标记）→ 模块端口输入（层次引用 u_dut.u_mod.I_data，与上游同条件打印对照，验证「模块看到的」=「上游产出的」）→ 模块输出，每层打印前 N 拍（**含 0 值**——非零过滤会漏掉「该 0 却 1 / 该 1 却 0」的错位信息）+ 计数值，错位发生在哪两层之间断点就在哪。

**一侧探针正常但数据缺字/缺拍 → 立即切对侧取证，别在正常侧继续挖**：读侧节奏正常（re 间隔、dout 更新节奏符合预期）但 FIFO 内容缺字（dout enc 序列跳号）→ 丢字发生在写侧（we 失效拍）——在写侧加探针：we 拍打印「写入数据编码 + 各门控分量（标签/丢弃计数/在途计数）」，一次运行直接看出哪个分量在丢字拍失效；反之写计数正常但输出缺拍 → 查读侧。丢字拍的状态快照比整段序列推演快一个量级。

## tb 帧边界、注入与重跑陷阱

1. **帧循环边界必须与帧同步信号对齐**：主循环用「repeat(N 拍) 为一帧」时，若 N 拍与 vsync/帧开始脉冲周期不同步（vsync 在每帧中段触发），统计窗口会跨帧切错——帧末打印的计数是复位后的新帧值、比较计数混入下帧数据。改法：每循环开头 `@(posedge vsync_pulse)` 等帧起点，再 repeat 一整帧拍数。注意 vsync 周期 == 循环长度时，循环末与下一个 vsync 边沿同拍，下一个 @(posedge) 会等到再下一帧——超时预算要留出这个偏移。
2. **坏帧/异常注入要与被注入模型的其他赋值互斥**：always 块内多个 if 分支对同一 reg 赋值时后者覆盖前者（注入「锁水位 100」被模型自己的「读批 +1」每拍覆盖 → 注入静默失效）。注入条件和模型正常路径必须写成互斥分支（如模型路径加 `&& 时间门控`）。注入后先打印一个「注入已生效」的标记（如门控电平/读计数）确认，别假定注进去了。
3. **iverilog 编译失败会被管道/重定向吃掉 → 静默跑旧 .vvp**：`iverilog -o tb.vvp ... 2>&1 | head -3 && vvp tb.vvp` 的退出码是 head 的（恒 0）；`2>/dev/null` 同样吞掉编译错误，后台任务只报 exit code 1 且输出为空——此时先不带重定向重跑一遍编译命令看 stderr，别猜。编译报错时旧 .vvp 还在、vvp 照跑 → 改过的 tb 根本没生效，白等一轮仿真还以为跑的是新版。铁律：编译命令和运行命令分开两步（编译单独检查 rc 和 error 输出），跑之前确认 .vvp 时间戳新于所有源文件（ls --time-style 比对）。**同理 `grep -ciE "error" ... && vvp` 是错的门控**：grep 无匹配时退出码恒 1（不是 0），&& 短路 → vvp 根本没跑，输出只有计数的「0」，误以为「仿真无输出/挂了」重跑白等。要「无 error 才跑下一步」用 `! grep -qE` 取反，或直接分两条命令、肉眼读计数。
4. **wait/探针触发条件引用的每个 reg/integer 必须初始化**：`reg [N:0] frame_cnt;` 不初始化 → 上电 X → X+1=X → `wait(pix_cnt >= K && frame_cnt == M)` 永不满足 → 跑到 TIMEOUT 且无任何统计输出。**探针打印计数器同理**：`integer dbg_pix;` 默认 X → `dbg_pix < 24` 恒假 → 探针一行都不打（表面像「触发条件没满足」，实为计数器自身 X）。诊断「TIMEOUT 且零打印」或「探针静默」先查 wait/if 触发条件引用的每个信号是否声明时给了初值（integer 尤其易漏，声明即 `= 0`），再怀疑条件本身或 DUT。**同款症状的第二嫌疑 = 计数器位宽装不下终止值**：`reg [N:0] cnt` 的终止判断 `cnt == M` 在 M > 2^(N+1)−1 时永假（11 位装不下 2199 → line 计数永不推进 → vsync 永不产生 → 主循环 @(posedge vsync) 永远等不到）——TIMEOUT + 几乎零打印 + 上游信号从未拉高，查完初始化后立刻核对「终止值与位宽」，别先怀疑状态机逻辑。
5. **期望比对模型先跑无干扰基线校准，再跑干扰场景**：逐像素期望比对（地址编码 + 解包映射逐段推）容易带固有偏差（如软 FIFO SHOW_AHEAD=0 的 re→dout 1 拍延迟使解包期望错 1 段）——干扰源关掉（SW4=0）先跑基线：基线 mis=0 = 期望模型正确、后续错位由干扰源引起；基线 mis>0 = 先修 tb 期望模型（按真实时序推解包起始段），别拿带固有偏差的判据去量干扰效果。复现 tb 的判据窗口取判据帧头局部（如 1024 像素）即可检出帧头混入类错位，比跑完整帧快一个量级。期望模型必含的两个真实时序细节：①输出打拍链——O_data 比输入 valid 晚 1~2 拍（本工程 video_out 实测 2 拍：de→en_1d→O_data，de 首拍输出还是消隐残留值），段映射要按打拍后的拍序推；②case0 段读的是**当前 dout**（S_fifo_rd_data 未打拍）——行首 cnt=0 拍 re 沿后已生效、case0 求值时当前 dout = 新读出的字 s，故段 0~4 全部 = 当前字 s（期望模型 seg 0~4 → enc_s，不是「上一行尾字」；把 case0 当上一组尾字会让模型从帧头起整体错位）。行 0 首字 enc 恰为 0 时前几段全 0、与消隐残留无法区分，首错像素会「藏」过这些段才出现——校准期望模型前先 grep case 各段的位选源（当前 dout 还是 dout_1d）再写映射，别按记忆推。
   **修复部分生效的判读 = 看首错像素位置移动**：修复前首错在「帧尾混入字的位置」（如像素 2），修复后首错后移到「期望模型偏差处」（如像素 5）——首错位置后移 = 该修复生效、剩余偏差换了一层，逐层后移直到 mis=0；首错位置纹丝不动 = 修复没打到点上。
6. **VCD/结果分析脚本用 write_file 落盘 + terminal `/usr/bin/python3` 跑**：execute_code 在用户无响应时会因等待批准超时被拦（深夜长任务用户不在场时必现）——把分析逻辑写成 scratch 下的 .py 文件（import vcd_parse 即可），terminal 直接跑，不依赖用户在线；同一分析脚本反复改重跑比 execute_code 更稳。

## DDR 多流 tb 的位置映射验证（已知图案注入，全 1/全 0 测不出位置）

「整屏全白/全黑下板正常」只能证明链路通，证明不了「标记位置与像素位置一一对应」——本会话背景检测链全白测试过了、tb 全 0/全 1 场景 mis=0 全过，但下板标记错位 8 组（32 像素）。位置映射必须用「已知图案 + 抓写数据位序」验证：

1. **DDR 返回模型按地址编码 + 掩码制造「只打特定位置」的差异**：cur 返回 {16{enc}}、bg 返回 {16{enc}} ^ 掩码（掩码只翻转「每行行首 128bit 字的高 96 位」→ 只有最左 4 像素有差）。然后抓下游存储（ERAM/BRAM）写数据的位序与图案比对（如行 1 首字 [7:0] 应 = 0x7F）。
2. **掩码必须判流，防无符号下溢命中**：`(addr - BG_BASE) % N < M` 的判据对「非目标流的地址」会下溢成大数——`% 1920 < 1920` 对大数恒真，cur 流也被翻转 → 两流同差 → 差异消失（「全 1 实验」静默变「无差异实验」）。判据必须加 `&& (addr >= BG_BASE)` 显式判流。
3. **写接口地址 off-by-one 是 RTL bug，不是正常模式**：攒字器把「地址递增」与「写使能置位」放同一拍（攒满拍）非阻塞赋值——en 有效拍 ERAM 采样到的 addr 已是 +1 后的值 → 字 k 写进 addr+1 → 标记整体右移 1 字（40 像素/字）+ 行首字（base 地址）永远写不到（保持上电 0 = 左边界 40 像素无标记）。指纹 = 错位恒定、与场景/光照/内容完全无关（用户「摄像头怎么转现象都一样」= 结构性固定偏移信号，不是竞争/随机/算法）。正确写法：地址递增放「写拍」（en 有效拍）且用独立 always 块（写拍与下一字首组同拍时 else-if 链会吞掉递增），帧开始复位也在该块；tb 差分判据 = 首字写拍地址 == base（修复前 == base+1），并按「写地址 = 行×32 + 像素/40」核对整链落位。
4. **形态学链的图案约束**：差异图案放「帧首行行首」，**腐蚀级**输出会被垂直腐蚀清掉（首行无上行窗口 → 3×3 窗口不全），但**膨胀级**的 1×3 窗口含下行 OR → 第 2 行的膨胀结果扩散回首行 → 最终输出首行 = 第 2 行的膨胀值（非 0）。「首行全 0」只对腐蚀级输出成立（探针抓 ero_v 验证），对最终输出不成立——写判据前推完整链路（腐蚀清 + 膨胀扩散）再定期望值。要验证位序用「每行行首」图案，判据对准「行 1 首字」；同理 1 行高的块被腐蚀整体清除也是正确行为。
4b. **「复用开运算链做边缘提取」的语义坑：开运算流水的膨胀级输入是腐蚀后的图**——morph 链的 dil_v = dilate(erode(X))，拿它 XOR 原图得 open(X)^X 而不是任务书要的形态学梯度 dilate(X)^X：单点噪点被腐蚀吃掉后 edge 显示成孤立点而非 3×3 环（tb 黄金模型比对必错，先探针打印 dil_v 与 ori 对齐确认）。三种取舍按资源预算选：①严格 dilate(X)^X = 独立复制一条膨胀链（水平 2 拍 + 垂直 320×2 + 中心对齐链，资源 ~3900 FF）；②open(X)^X = 只需 ori 对齐链（644 拍）但单点语义退化；③open(X)^erode(X) = 只需 erode 对齐链（322 拍）且单点完全消失（最省、显示最干净，但非标准梯度）。写 tb 黄金模型前先把「RTL 实际用的膨胀输入」搞清楚，别按教科书 dilate(X)^X 硬套。
5. **探针分层二分断点**：上游输出（比较器标记）→ 模块端口输入（层次引用 u_dut.u_mod.I_data，与上游同条件打印）→ 模块输出 → 存储写数据，逐层打印前 N 拍含 0 值；某两层的图案对应关系断裂处即断点。
6. **行结构完整性用行首间隔验证**：怀疑「每行 N 组」不成立（行尾 pending 丢失/行边界漂移）时，打印每行行首标志拍（如判定值全 F 的拍）的全局有效拍计数——相邻间隔即实测每行组数，比逐行推演快且直接；间隔正确则行结构无辜，回头查别处。
7. **位置映射错位久查不决时，先跑一轮全 1 差异图案看输出有无 X 位**：温和图案（局部差异）下 X 可能被吞掉不显现，全 1 图案让 X 传播到存储写入 → 首字出现 X 位即实锤「未复位寄存器泄漏」，直接指向 pending/缓冲类寄存器复位缺失，避免继续在纯位序逻辑里空转。
8. **多像素打包链（128→96 解包）的掩码位段会按解包相位拆进不同组，「翻高 96 位」≠「翻组 0 的 4 像素」**：96bit 组的 x0~x3 = 解包输出的位 95:92，而 B 组（第 2 个输出）= {128位1[31:0], 128位2[127:64]}——若掩码只翻 128位1 的高 96 位（[127:32]），B 组的 x0~x3 恰落在未翻的 [31:28] → 组 1 判定 0000，腐蚀窗口把「组 0 的 x3 右邻 = 组 1 的 x0 = 0」传导成 7/e 周期边界图案，判据期望值全错。干净图案 = 整 128bit 字全翻（或掩码精确对齐组边界）；判据期望先按解包相位逐组算判定（A/B/C/D 各是哪个 128bit 的哪一段）再算形态学输出，别想当然「组 0~3 全 1」。
9. **写侧攒字器位序用「锁存流打印 + 写数据 hex」联合判读，别只看 hex 猜**：`S_word <= {S_word[35:0], new}` 左移语义下第 k 次锁存的组最终落在 bit[4(9-k)+3:4(9-k)]（新组进低位、最早组被推到最高位）——「组 1 = 1111 打印值」对应 hex 的 bit35:32 而非 bit7:4，是位序的自然结果不是 bug。判定「位序反没反」要把「锁存拍序（wcnt 计数 + 每拍 filt 值）」与「最终 hex 的组位」对照，并核对读侧约定（col 0 = 屏幕最左像素 = 第 1 次锁存组还是最后一次锁存组）；两侧约定不一致时改一侧，别在写侧 hex 上盲目对位。
10. **全同编码的 DDR 模型（每字 {16{enc}}）测不出位序/镜像/平移——位置类问题必须非对称注入**：enc 编码字节全同 → 字内位序反转、行内平移在「cur/bg 同值比较 + 落位检查」里完全不可见（mis=0 照样镜像）。测位置映射 = 在目标位置（行首/行尾字）翻高 96 位制造「只此一处有差」图案，抓 ERAM 落位打印（fg_wr_addr + data），标记落在哪个字哪个 bit 直接定论。行中列取证 = 同一方法的推广：注入条件改「行内已知单位偏移」——**先核地址单位再换算**：tb DDR 返回模型地址单位 = 2 字节（16bit），行 = 1920 单位 = 3840 字节（1280 像素 ×3），128bit 字 = 8 个单位（读命令 +8 递增即此单位），故 `% 1920 == 592` = 单位 592 = 字节 1184 = 128bit 字 74（÷16）≈ 像素 395（÷3），比较组 = 字×4/3 ≈ 99。换算链（单位→字节→字→像素→组）必须写进注释，并用 mis 打印的组计数（f_cmp）实测核对：f_cmp 应 = 注入字×4/3。**换算错了会制造假错位**（曾把字 74 的落位当字 37 算，得出 62 组假错位量，多轮探针后才用 f_cmp=99 实锤零错位）——落位差 × 40 像素/字反推错位量之前，先验证注入实际落在哪个组，别信注释里的换算。无错位时标记落「行首地址 + 注入字换算后的 ERAM 字」（128bit 字 → 像素 = 字×16/3 → ERAM 字 = 像素/40，逐级换算别心算）。**「无论场景/摄像头怎么转都固定方向偏 + 对侧边界内容卷到本侧」= 行内固定 K 字错位指纹（内容平移 K + 行尾卷行首），不是检测误差**——按错位量（像素 ÷ 5.33 = 128bit 字数）反推丢字/多字位置，查每行循环的机制（行弹对数、mod 路由、解包相位）而非逐模块猜。**tb 按地址生成数据的模型天然测不出「实机 DDR 内容 vs 读地址对应关系」的写链 bug**（写链在 tb 里不存在）——tb 位序全对但实机错位/镜像时，嫌疑在 tb 未建模的写链（打包/写 FIFO/写地址序列），别在 tb 已覆盖的读链上继续挖。**错位量用「输出拍序号 vs 预期位置」反推**：注入组在已知全局位置（如组 99）时，其滤波输出的有效拍序号（MORPH_NZ 式 cnt 计数）应 = 组位置 + 链延迟有效拍（99+644）——实测 cnt 大 1 = 帧头多 1 个幽灵有效拍（4 像素级偏移），比读地址换算快且直接；修复前后 cnt 相同 = 幽灵与刚修的 bug 无关，是独立存在的源。
**列取证注入图案必须打满全部行（竖线）**：单行/少数行的 4 像素差异块会被 1×3 垂直腐蚀整体清除（上下行无差异 → min=0）→ FGWR 落位全 0，表面像「注入没生效/无落位」——取证注入要每行同列都打（720 行竖线），腐蚀/膨胀链保得住、落位才可见。落位打印预期地址全 0 时，把打印改成「地址范围 + 数据非零」过滤（FGWR_NZ 式：fg_wr_en && addr 范围内 && data != 0），先找到实际落位地址再反推错位量（落位差 × 40 像素/ERAM 字），别死盯预期地址等打印。
**同拍打印的流位置计数 ≠ 该拍数据的流位置**：FIFO 排队（攒满 240 才弹行）使比较拍打印的到达序计数（如 S_ret_mod）领先比较数据几十~几百字——把「注入差异出现在 mod=342 拍」直接当「数据位于流位置 342」会得出假错位量（本会话差点把 65 字假错位当实锤，实际只是 FIFO 深度差）。位置类结论只认「落位存储地址 + 数据位序」这一级，中间流计数（mod/pop/到达序）只用于节奏与顺序判读；逐级定位错位断点用三层计数探针（比较链组计数 → morph 输出组计数 → 攒字落位地址）对照同一注入图案。
11. **运动方向相关的「落后/超前」= 空间偏移指纹，不是时间延迟**：涂白恒落后且与运动方向无关 = 检测延迟；「左移落后、右移超前」= 涂白恒在真实位置某一侧（空间偏移）——时间延迟不随运动方向翻转，空间偏移才会。平移 N+行卷绕会表现成镜像（N≈半行时「左处目标→涂白在右、右处目标→涂白在左」）；判别平移 vs 镜像别猜——让用户做三点位置实验（目标放 x=200/640/1100 报涂白位置），一次定位。

**错位方向翻转 = 两个方向相反的错位源在抵消，不是同一 bug 没修好**：修复前右错位、修复后左错位且量几乎相同 → 修掉的是 A 源，反向暴露的是「一直存在但被 A 抵消」的 B 源（净错位从 A−B 变 −B，修复净变化 = 2×单源错位量）。接着修 B 源（找与 A 同量级、方向相反的固定偏移），别当修过头来回退。**叠加错位的三源区分实验（下板零编译成本，实测数据先于推演）**：①静止参照物（画面中部静止物，无卷绕干扰）测固定水平错位的方向+量；②运动目标做「停住 vs 移动」对比——移动时涂白超前行进方向 1-2cm、停住即对齐 = 帧差超前（标记帧比显示帧新 1 帧，量 = 手速÷帧率）；③涂白恒朝画面中心偏、边缘处最大、摄像头怎么转/内容怎么变都恒定 = 镜头桶形畸变（光学固定属性非代码 bug，答辩解释 + 演示目标放画面中央，赛前别上畸变校正）。"错位恒定与内容无关"同时是「结构性固定偏移」的强指纹（排除算法/阈值/竞争），与「转动不变」合在一起直接锁定位置映射链。

## tb 三链全零错位但实机涂白错位 → 嫌疑在 tb 未建模差异，先做启动相位判据

「画面正常 + 涂白错位」= 叠加链与显示链相位错位，是 DDR 视频管线经典 bug，不是算法错。外网同款案例：netv2-fpga「Misalignment of Overlay and Stream」——DRAM fetch 批量取数相位 vs 显示流同步的时序关系决定 overlay 对齐，错位量随启动相位。判据实验（tb 全绿后先做，别继续翻静态逻辑）：同一 bit 重烧两次/重启，错位量变 = 启动相位问题（修帧对齐/固定对齐相位）；不变 = 固定逻辑错位（继续查链路）。tb 的 DDR 模型（按地址生成内容、固定延迟链）天然测不出实机启动相位/DDR 背压类差异，tb 全绿只排除静态逻辑错。两链组序列对比探针（tb 全绿验证的收尾手段）：联合 tb（真实 video_out + bg_read + ser_arbiter + DDR 命令队列模型，tb_vo_stream.v）里 VO 侧按 de 拍每 4 像素拼 1 组打印 hdmi_pixel[7:0]（位置编码的字节切片）、BG 侧打印 S_cur_96[7:0]，两流第 k 组的 enc 序列应同源一致（组号从各自帧头第 1 拍起算，与两流启动时间的绝对差无关）。两个判读口径：①VO 首帧启动期（显示 FIFO 未填满）前若干组是 X，对比从 X 期之后开始，首帧 X 不构成错位证据；②BG 流必须在读满场景对比——SW4 拨下时机不对或被显示期门控卡住时 BG 只弹十几组即断流，残缺序列对比无效，先调整拨下时机让 bg 读满再比。另一同源经典坑：sideband 标记（帧头/行尾/valid）必须与数据延迟同拍——任何链改延迟后同步重核 valid 链深度。比赛时间紧的兜底修法：hdmi_mixer 涂白列坐标加可调对齐偏移寄存器（SW 调、数码管显示），下板一次调准烧死。

**技术根因检索用英文关键词**：中文搜索引擎（百度/搜狗）有验证码墙、必应国内版中文 query 结果被污染（返回无关歌词/科普），中文技术贴基本搜不到深度根因；这类管线相位/错位问题用英文搜（background subtraction misaligned mask / ISP line buffer delay / frame sync phase shift）外网论坛命中率高得多。

## 行为模型三坑（视频链仿真）

1. **iverilog -P 覆盖不了已赋默认值的 parameter**（静默回落默认值，输出标签还是默认档）：用 `sed 's/parameter MODE = 2;/parameter MODE = 1;/' tb.v > tb_m1.v` 生成变体文件再编译；别信 -P 的覆盖结果。
2. **软 FIFO 行为模型（soft_fifo_al_*.v）的 rdusedw 在 re=0 期间可能不更新**（事件驱动计数）→ 仿真里「水位≥阈值」永假 → 写批永不触发 → 仿真写 0 是模型冻结，不是硬件行为（真实 FPGA 的 rdusedw 正常跟随写侧）。**水位驱动状态机在仿真里完全不触发时，先验证模型水位是否依赖 re/we 事件才变化，再怀疑 RTL。**
3. **DDR 读延迟模型不能把 rd_valid 拉恒 1**（命令 → N 拍延迟 → 每命令返回 1 拍）：恒 1 会让 FIFO 假满、写侧饿死、读计数失真。用移位链实现：命令把数据压入 delay_chain[N-1]，每拍 delay_chain[i-1] <= delay_chain[i]，出口用空标记（如地址 12'hfff）判 valid。
4. **多像素打包数据的 tb 激励按模块提取槽位拼，别按「每像素位宽全填」直觉拼**：96 位 tdata = 4 像素 × 24 位（RGB888），灰度模块只提取每像素的低 8 位（g0=[7:0]、g1=[31:24]、g2=[55:48]、g3=[79:72]，间隔 16 位）——正确激励 = {16'd0,g,16'd0,g,16'd0,g,16'd0,g}（共 96 位）。写成 {24'd0,g}×4 会拼出 120 位、截断后 g1~g3 槽全是 0 → 每拍只累加 1 个像素 → 平均/统计仿真值差 4 倍，误判 RTL 有 bug。先读模块对输入数据的位提取（g0~g3 下标），按槽位拼。
5. **异步 FIFO 模型必须按真实跨域结构分域建模（写 clkw、读 clkr 两个 always；判空判满一律指针直接无符号差，别用同步指针/保守判空）**：读写异时钟的 FIFO（如显示 FIFO：写 DDR 域 100M、读像素域 75M）若写成单 always@(clkw)，读侧 re/rptr 逻辑被写时钟采样 → re 每 5 拍被采错 1 次 → 读指针规律跳增 → **FIFO 内容完好但 dout 序列规律丢字**（如 enc 0,2,3,4,5,7 丢 1,6,11——每 5 字丢 1 的假象）。指纹 = 丢字节奏与读侧 re 周期（16 拍 3 re）相关且写侧探针证明写入序列完整连续 → 立即转向模型，别在 RTL 读写逻辑上继续挖。分域模型要点：①mem 数组+写指针在 clkw always，dout/rptr 在 clkr always；②指针跨域直通打 2 拍（仿真近似格雷码）；③**判空/判满/水位一律用指针直接无符号差 `wr_cnt = wptr - rptr`（位宽自然模 2^N 回绕，队列差恒 ≤深度不歧义）：empty = (wr_cnt==0)、full = (wr_cnt>=DEPTH)、afull/aempty 同理**——两个「防下溢」写法实测都是错的：同步滞后版 `wptr_s2 - rptr` 在滞后拍无符号下溢成巨数 → 判空失效、re 读未写地址出 X；三元版 `(wptr>=rptr)?diff:0` 把指针回绕窗口（wptr<rptr 的几十拍）当 0 → 周期性误判空 → 同域 tb 弹链断裂（写入 12.6 万字 = 123 次回绕、每次断一拍，fg_wr_addr 掉到 126/11455）。④判空判定走同步指针（wptr_s2）会让同域 tb 空判定晚 2 拍 → 多弹 2 对 → 数据错位——同域 FIFO 直接用未同步指针算差。读写同域的 FIFO（bg_read 的 cur/bg FIFO 全在 DDR 域）单时钟模型即可，分域结构才需要分域读写。

## 写链帧复位三坑与排空批（帧尾残留卷绕根治）

视频写链（摄像头 → 写 FIFO → DDR）的「帧边界复位」有三个连环坑，最终方案是排空批：

1. **复位窗覆盖帧头数据 → 丢帧头 K 字 → 全帧错位**：写 FIFO 复位挂在帧头数据拍（tuser 与首数据同拍）上，复位窗（展宽 8 拍 + 同步 3 拍 ≈ 11 拍）覆盖帧头数据 → 每帧丢帧头 11 字 → 第 1 批从第 12 字开始 → 全帧内容错位 K 字（卷绕，右边界内容出现在屏幕左侧）。指纹 = 错位像素量 = 5.33×K（128bit 字 ×16 字节 ÷3 字节/像素），且颜色错乱（字节错位不对齐 RGB 边界）。复位窗必须落在无数据的消隐期。
2. **帧尾判定别用 tvalid 边沿——ISP/传感器输出带行消隐空洞**（tlast 每行断一次，空洞几十~几百拍）：下降沿检测会把每行空洞当帧尾 → 每行复位一次写 FIFO → DDR 内容全烂 → 花屏 + 采背景全屏涂白（背景帧也烂，cur/bg 全屏差异）。判定改「tvalid 低电平持续 > 2000 拍」（行空洞远达不到、垂直消隐按 VTS 算 8 万拍量级必中）。判阈值前先查传感器寄存器表确认 HTS/VTS 实机值（如 HTS=1600/VTS=1000 → 行空洞 ~60 拍、垂直消隐 280 行）。
3. **帧尾复位仍治不了「帧尾残留混批」**：帧尾批（非 240 整批）在帧头拍被停 → 残留 K 字留在 FIFO → 新帧头数据进 FIFO 后残留混在第 1 批里 → 卷绕再现（历史「帧尾批跨帧卷绕」同源）。**根治 = 帧尾排空批**：帧尾判定后强制写 240 拍排空批，把残留 K 字写进 DDR 帧尾后区域（地址递增、块间隙大无害），FIFO 清零；排空落在垂直消隐期（新帧数据未到）→ 零混批零丢字。此后不复位 FIFO（S_fifo_rst 恒 0，指针自然循环）。tb 验证 = 帧流尾部注入 K 字残留（如 37 字），判据：帧区首错字 = -1、残留区（帧尾后地址）落位正确。
4. **FIFO 复位/触发信号不要依赖 FIFO 自身输出**（如 rdusedw 判空）：rst → 指针 → rdusedw → rst 组合环死锁，仿真表现「一帧不写、dbg=0」。判空/等待用固定拍计数（批长 + 余量），不读 rd_num。
5. **跨域 1 拍脉冲直接打 3 拍同步会被漏采**（75M 域 6.67ns 脉冲 < 100M 域 10ns 采样周期）：先在源域展宽 8 拍再同步取边沿（与帧头 tuser 展宽同款）。
6. **软 FIFO 模型的指针/同步链寄存器要 initial 置 0**：真实 IP 上电全局复位清指针；模型若复位信号从未脉冲（如改成排空批后不复位）会保持 X → rdusedw = X → 水位比较恒假 → 批永不触发（仿真一帧不写）。模型专用 initial 不影响 RTL 结论。
7. **排空批拍不计入诊断写计数**（dbg 门控 !S_fend_drain）：判据保持「每帧写满 172800 = 0x2A300」不因排空漂移；排空首尾各 1 拍的计数时序差（+2 字）无害可接受，不必为 2 字加打拍逻辑。

## video_in 写侧错位复现 tb 模式（跳帧/训练期/复位场景）

复现「画面整体平移 + 颜色错位」（写侧 FIFO 丢字/残字混入帧头）用 video_in 模块级 tb（iverilog 直编 RTL + 软 FIFO 模型 soft_fifo_al_*.v，无需 DDR IP）。五个构件：

1. **摄像头流模型（cam 域，异频 74.25M vs DDR 100M）**：帧计数器 fcyc 非阻塞推进；cam_valid/cam_data 一律 `assign` 组合派生（`fcyc % 行周期 < 行内 valid 拍`）——若用 reg 非阻塞更新，video_in 在 posedge 采到的是旧 valid + 新 data，拆 1 拍。帧头脉冲在「帧尾拍」置位（下一拍 fcyc=0 帧头拍可见，与首数据同拍）。行内留行消隐空洞（远小于帧尾判定阈值 2000 拍）。
2. **tdata 内容编码 = {帧号, 帧内字序}**：每个 128bit 字带唯一 ID（如 {frame_id[15:0], word_id[17:0]}），错位检测不用比对图案。
3. **仲裁 grant 模型**：WR/VO 各 240 拍轮转模拟串行仲裁占空比（~50%）。帧节奏必须让「每帧灌入字数 × 写时间 < 每帧总拍数 × 占空比」，否则 tb 自身把 FIFO 灌满制造假溢出——按 100M 域每帧可写字数反推 cam 域每帧最少拍数。
4. **场景注入**：(a) 跳帧 = 显示期给 I_ae_cfg_done 8 拍脉冲 + I_auto_en=1；(b) 训练期 = 复位释放后 I_ddr_user_ready 保持 0 N 拍（5ms ≈ 50 万拍@100M）再恢复 1；(c) 纯复位场景摄像头模型不接 rst（外部芯片不复位、持续出流）。
5. **错位 checker 按地址推字序**：帧内写拍（地址 < 帧长）期望字序 = (地址 mod 帧长)/8、期望帧号 = 跨域打 3 拍后帧号（S_frame_start 拍锁存）；错位字数 miss_cnt 逐帧统计清零打印。按地址推比按 wr_en 计数稳（不受批边界/排空批干扰，排空批写帧尾后区域天然被地址过滤）。

判读：跳帧恢复帧起 miss>0 且量随机 = 屏蔽写溢出复现；训练完成帧起持续 miss = 训练期溢出复现。修复验证同 tb：跳帧改覆盖写同块后 miss 恒 0；init_calib 清指针后训练后首帧起 miss=0。

## video_in 错位修复两式 + tb 实锤（2026-11-01 bug1/2 修复会证实测）

## 细线/黑线 = 读不满帧停止行（bg 检测链，2026-11-01 bug3 实锤）

## bg 检测链细线/黑线 = 读不满帧停止行（tb_bg_line 复现模式，2026-11-01 定位）

「涂白经过处细线/黑线闪（断续）」= bg 读不满帧的停止行：读窗口不足 → bg 读停在停止行 → 停止行以下 ERAM 标记永不更新 → 挥手时涂白经过停止行 = 新旧标记边界线（静止时该行标记与邻行同为 0 看不出）。读满帧 + DRAIN 644 排空正常时每行写满零漏写（tb 判据：每行写拍数 < 32 的漏写行清单 = 空 = 无线）。

**两种线两种机制判别（用户实测实验定论，别混为一谈）**：①**细线（恒在、挥手经过时上下错位）= 分段交替的交界撕裂**——交界两侧标记年龄差 1 帧，运动目标跨过交界就上下错开，静止无感；判别实验 = 手伸进细线垂直于细线水平转动，能明显看到细线上下错位 = 撕裂，不是停止行。②**黑线（涂白位置里面闪、断续）= 读不满停止行**——某行标记没更新，挥手经过时涂白区域内这条线闪黑。分段数增加（半帧→三分段）撕裂点 2→4 条，用户报「线变多」很可能只是撕裂点变多而非停止线恶化——改分段前先按两种机制分别评估观测量。

**整帧读下板验证通过（2026-11-02 用户实测）**：细线（交界撕裂）根除——整帧读 = 撕裂的唯一根治手段定稿，平滑逻辑待拆除。

**顶部错位（新 bug，进行中）**：开背景检测后画面最顶几行错位、静止也出现。用户观测三要素：①第 0 行 100% 不对、第 1~2 行隔一段时间交替对错（周期性与 bg 读满停相位相关）；②错位区域能被涂白覆盖（视频数据错位、mark 链对齐正常）；③像垃圾数据。排查路径：disp 上升沿触发抓「显示行开始」水位恒 480 满——但每行都满足触发、抓到的都是随机中部行，顶部行窗口没抓到，欠载排除不彻底；tb_vo_discard（帧尾批残余丢弃链建模：读批/水位触发/帧头停批/in_flight/discard_cnt/标签队列/bg 拖尾）复现结果 = 丢弃链基本链路无污染——失效不在丢弃计数口径，嫌疑在实机仲裁/时序交互。**下一步定式 = 抓显示开始瞬间**：video_out 加 O_dbg_discard（discard_cnt>0 电平）与 O_dbg_vo_we（FIFO 写使能）输出、wrapper 加 S_cw_vsync/S_cw_discard/S_cw_we 三个 MARK_DEBUG，触发用 vsync 下降沿（场消隐结束 = 显示开始），窗口一次看全「残余丢弃期是否拖过显示开始、新帧数据何时开始写 FIFO」。**抓特定行/特定时刻必须用该时刻独有的信号触发**（vsync 边沿 = 显示开始），行消隐电平边沿类触发只能撞随机行。ser_arbiter 结构备忘：WR→VO→BG 固定轮转、每状态服务完整批（busy 降才切、无批 1 拍跳过、超时 256 拍保护）——bg 批忙时 VO 请求最多等 2 个状态切换（BG 批剩余 + WR 片），延迟上限 ~480 拍。

## verilator 免 sudo 安装（WSL 无 root 时，快 50~100 倍）

长 tb（百万拍级）iverilog 解释执行太慢时用 verilator。无 sudo 密码的装法（清华源秒下）：`apt-get download verilator && dpkg -x verilator_*.deb ~/verilator_local`——然后 `export VERILATOR_ROOT=$HOME/verilator_local/usr/share/verilator`，**直接调用 `~/verilator_local/usr/bin/verilator_bin`**（外层 Perl 包装器按标准布局找 verilator_bin 会报 not found，绕过它直调 bin 即可）。编译运行：`verilator_bin --binary --timing -Wno-fatal tb.v --top-module tb_xxx` → `./obj_dir/Vtb_xxx`，百万拍秒级出结果。

**参数扫描用运行时 +PARAM=VALUE，一次编译多档跑**：`./obj_dir/Vtb_xxx +LAT_JIT=4 +DROP_RATE=2` 覆盖 parameter 初值（iverilog -P 覆盖不了已赋默认值的 parameter 的老问题在 verilator 运行时参数上不存在）——15 组参数 = 1 次编译 + 15 次秒级运行。**但覆盖可能静默失效**：parameter 被编译期常量折叠（如用于 wire 表达式 `ARB_CYC = BG_SHARE*240-1` 或派生局部参数）后运行时覆盖点不存在——三档扫描结果一字不差 = 覆盖失败的实锤指纹。铁律：多档扫描前先 $display 打印参数实际值验证覆盖已生效；不可靠时改用 sed 生成参数变体（改 parameter 声明行重编译），别默认假设「结果不同 = 覆盖成功」。

**verilator 两个语法坑（iverilog 不报、verilator 必报）**：①for 循环内对数组做非阻塞赋值（`for(...) arr[i] <= ...`）报 BLKLOOPINIT 不支持——tb 里改成阻塞赋值（`arr[i] = ...`）即可，语义在测试台里等价；②未定尺寸数字字面量超过 32 位（`20000000000`）报 Too many digits——加尺寸前缀（`64'd20000000000`）。

**实机化扰动扫描（用户质疑「仿真太理想化」时的正解，别推「真时序仿真不存在」）**：理想模型（固定延迟/无竞争/无亚稳态）全绿但实机错位时，把实机扰动的三要素参数化注入后再扫一遍：①DDR 返回延迟抖动（基础 40 拍 + LFSR 伪随机 0~J 拍）②读命令吞拍（模拟写拍避让/仲裁把命令吃掉，DROP_RATE 概率）③CDC 采样抖动（vsync ±1 拍）。三档参数独立可调，一次编译多档扫描，输出对照表——哪个扰动让「首字写拍地址」偏离基线就是哪类实机差异在起作用；全档零漂移 = RTL 账对扰动脉冲免疫，错位只能在综合后实机行为层（BRAM 化/SRL 化/插拍），实机诊断（数码管直读）才是最终裁决。注入源用 LFSR（`lfsr <= {lfsr[14:0], lfsr[15]^lfsr[13]^lfsr[12]^lfsr[10]}`），别用 $random（不可复现、扫描对不上）。

**大 tb 改造是下坡路，最小 tb + verilator 才是正路**：为旧问题设计的集成 tb（165 万拍帧结构）去套新问题会连环卡壳（iverilog 太慢 → sed 缩周期 → 超时边界反复 → 40 分钟耗在 tb 环境而非被测逻辑上）。新问题写最小 tb（复刻被测链 + 参数注入，几百~几千拍），iverilog 就够快；确需长仿真再上 verilator。sed 缩周期时注意：行周期/帧周期/超时预算三个数要同比例缩，漏缩任何一个（如 vsync 等待的行周期）会「跑通了还是 TIMEOUT」；总拍数账算清（循环拍数 × 循环次数 vs TIMEOUT 值）再跑，别靠试。

## 长延迟链仿真提速与后台仿真进程管理

1. **延迟链用位向量拼接移位，别用 reg 数组 for 循环**：`reg [N:0] chain; chain <= {chain[N-1:0], bit}` 与数组链语义等价（新值进低位移向高位），但 iverilog vvp 对数组逐索引循环赋值是慢路径——643 深 valid 链实测 2.1ms/拍，向量化后提速 2.4 倍；TD 综合向量移位也更优（映射 SRL）。RTL 和 tb 都适用。大位宽移位寄存器（1280bit 行缓冲）无法向量化时靠缩场景提速：单模块小 tb（几千拍秒出）验证滤波逻辑、集成 tb 去 VCD 去逐拍打印、判据收敛后 VCD 只在 FAIL 时加回。
2. **vvp 重定向到文件的 stdout 是全缓冲**：log 长期为空 ≠ 仿真没进度（杀进程时才冲刷）。后台长仿真用 `stdbuf -oL -eL vvp tb.vvp > log 2>&1` 实时输出才能按 log 判进度。**多个后台仿真绝不用同一个 log 文件名**：`>` 各自截断 + fd 偏移交错，先跑进程的结果不可恢复。
3. **杀自己启动的后台仿真/编译进程用 process_manage(action=kill)，别用 pkill**：pkill 属破坏性命令触发安全确认，用户不在时命令被拦、整条流程卡死；process_manage 按 background terminal 的 session_id 精确 kill，无确认门槛。
4. **长集成 tb 被 TIMEOUT 截断 ≠ FAIL**：TIMEOUT 分支先 $finish，主循环后的 check/错误统计根本不执行——评估结果按「已打印的帧统计行」判断（如帧 0 读满零错位 + 关键标志拉高已覆盖核心判据，部分帧/坏帧注入场景零错位也可数）。TIMEOUT 是 tb 计时预算问题（vvp 慢 + 帧数多 + vsync 对齐偏移），不是 RTL 问题；要跑全判据就提 TIMEOUT 预算或减帧数。

## TD 移位链不推断 SRL 的元凶：复位/帧清分支（2026-11-01 fill 会话 slice 超限实锤）

**带复位/帧清分支的移位链 TD 不推断成 SRL（shifter lut = 0），全部变 FF**：`always @(posedge clk) if(!rst) ... else if(fs) ... else if(valid) chain <= {chain[N-1:0], d};` 这种写法 320 深×4bit = 1280 FF（≈640 slice）。官方模板（SWUG106 5.5.1 Static）是无复位纯移位写法 `if(enable) chain <= {chain[DEPTH-2:0], d};`。SRL 硬件无复位端，任何复位分支都阻断推断。

**省资源三件套（按性价比排序）**：
1. **DRAM 环形缓冲**（`reg [W-1:0] mem [0:511] /* synthesis ram_style = dram */;`）：写 mem[wp]（时序写）、读 = 组合读 mem[wp+1]（TD 支持异步读推断，ram_async 模板）。**等价拍账必踩坑**：读地址 wp+1（最旧位置）的最后写入拍 = t-319，读值 = t-319 拍的数据 ≠ 想要的 t-320 → **写数据必须打 1 拍补偿**（写 mem[wp] <= din_d1）→ 读值 = 恰 320 拍前 ✓；读写地址恒错开，规避同地址读写顺序（read/write-first）问题。帧清 = 清指针即可（数据不清，旧数据靠 valid 门控不输出）——与移位链清链行为等价（帧清后 valid 门控期内不输出）。
2. **valid 链改有效拍计数**：644 深 valid 链 → 18bit 计数（帧清清零、I_valid 拍 +1），out_valid = (计数 >= 链深) && I_valid——拍账：输出寄存块采样计数拍前值，第 0 个有效输出拍 = 链深+1 拍时计数旧值 = 链深 ✓。帧内最大有效拍 174724 < 2^18 无回绕。
3. **shifter_style attribute**（`/*synthesis shifter_style = shifter*/`）可强制 SRL，但复位语义丢失（SRL 无复位）→ 用前先确认帧清能否改洗链。

**资源诊断入口**：综合后 syn_1/FPGACompetition_gate.area 的 shifter lut / dram lut 列 = 0 即推断失败；phy_1/FPGACompetition_phy.area 的 #slice 对照器件上限；基线 slice 使用率在上一轮成功编译的 phy.area 里（清缓存时保留 .area 报告）。

## 流式窗口（腐蚀/中值/卷积）tb 的对齐账

**1bit 流式 3×3 腐蚀原型的中心列/行对齐定式**（tb 判据错位高发区，逐项核对别心算）：
- 行缓冲 R_ln0/R_ln1 存「上一行/上上行」，当前行用 R_cur_l/R_cur_m 打拍缓存 → **输出中心行 = 上一行缓冲，行延迟 = 1 行/级**；窗口中心列 = 当前拍-1（R_cur_m 缓存 1 拍）→ **输出中心列 = 注入列 j-2**（j 从 1 起时：注入列 = j-1，再扣缓存 1 拍）→ 捕获位 = 位宽-1-(j-2)。行缓冲读列必须用「中心列」索引（W_cm = S_col-1 及 W_cm±1，模行宽回绕），用当前列索引 = 错位 1 列。
- **级联每级再叠 1 拍列延迟 + 1 行行延迟**：第 2 级输入流本身已带延迟 → 二级输出中心列 = j-3、中心行 = 输入行-2。tb 捕获/判据按级数写死前，先数清「注入时刻 → 该级中心」的完整延迟链，别复用单级的对齐公式。
- 判据图案选择：目标块须 ≥5×5 才能活过双次 3×3 腐蚀（4×3 会消失——每级吃掉 1 圈边界，2N+1 结构元吃 N 圈）；噪声团用「宽 3 高 1」横线验证单次腐蚀吃光。
- **行收集/输出阵列寄存器位宽必须 ≥ 每行像素数**：tb 把每行输出用「左移 1 位 | 新 bit」收进 reg [15:0] 而帧宽 32 像素时，前 16 个像素的 1 被后续移位逐位顶出丢失，行内容读出来全 0、误判「DUT 无输出」——左移溢出是静默丢位（不报错不警告），症状 = 收集计数正常、O_vld/O_edge 探针有值、但收集阵列全 0。修法 = 收集寄存器位宽 ≥ 帧宽，或移位方向反过来（右移、新 bit 进最高位）。同族：收集器行/列计数 integer 未初始化 = X 态索引写不进数组（已在「初始化」节）。
- **Sobel/梯度类 tb 场景禁用理想阶跃细线，用斜坡或边界线**：0→255 硬跳的窄线，Sobel 窗口沿线内部（左右同值）G=0，响应只在线的左右端点各 1 像素 → 输出只有 2 个孤立点，验证「边缘连续性/滞后传播」的 8 连断言必 FAIL。正确图案：水平边界线（上半 0 下半 255）使 mag 沿线连续；验证行内滞后传播用「同一行内强段邻接弱段」设计（滞后只能沿行传播，垂直方向的强弱分段验证不了行内滞后）。

## 下板诊断读数陷阱（数码管/LED 档位）



1. **诊断计数器的锁存事件会毒化显示**：调试计数若只在某事件（如帧开始）时锁存显示，该事件丢失 → 显示恒 0 → 误判「写 0/没数据」，即使写批在正常跑（帧开始链断时写批照常写、写计数显示却恒 0）。诊断信号设计铁律：(a) 计数自由累计（下板看涨不涨即活）；(b) 关键事件加「来过锁存位」（once-latch 1 bit 单显）。发现「计数恒 0」先查计数器的锁存条件是否依赖上游事件，再怀疑数据链本身。(c) 观测点随嫌疑链逐级前移：一次编译把 LED/数码管位接到嫌疑链的下一级节点（如 LED 从 ISP 输入端移到 ISP 输出端接输出数据锁存），用「数据到没到这一级」把断点二分到具体链段——8 个数码管 = 3 个锁存位 + 19 位自由计数，够当半个逻辑分析仪。
2. **拨码物理极性别信代码注释**：「拨上/拨下」注释与实际板子极性可能相反——用档位固定特征值反推当前档（如 case 分支 {16'hFFFF, bcd} 固定前缀 → 前 4 位恒 FFFF 即该档），确认极性后再解释读数；下板前给用户一张判读表（拨上/拨下各显示什么、每位数含义）。
3. **诊断 LED 驱动源先 grep 到 assign**：声明但从未驱动的 wire 被 TD 综合成 0，灯恒灭/恒亮是假诊断（tvalid_act = I_tvalid && O_tready，O_tready 悬空=0 → 灯恒灭，误判「摄像头不出流」一整晚）。
4. **调试设施生命周期**：问题解决后把临时诊断（数码管调试档、LED 复用、锁存位、自由累计计数）清理回正式语义再出正式 bit。高发残留形态：显示/行为 case 里的「拨码 ? 诊断 : 正常」三元分支——拨码恢复正式用途（如 SW4 从诊断复用改回背景采集）后该分支不会自动失效，拨码一拨下仍显示调试值（实机：SW4 拨下数码管恒显 fff00080 而非曝光值 3990）；改拨码语义时 grep 所有引用该拨码的调试分支一并删。清理三步验证：① 删端口时查端口列表逗号残留（iverilog 单文件编译报 Superfluous comma 即可抓出）；② grep 诊断信号名确认全工程零残留（顶层接线、wire 声明、端口三处）；③ 清理版 SYN 完成后 grep 最新 td_*.log 的 Undriven 列表，与清理前基线比对——只甄别**新出现**的条目（本工程固有悬空：hdmi_tx 去抖复位、awb BRAM 高位端口 dib[88:95]，历史每次编译都有，别为它们卡发布）。

## 主线对照 diff 排除法（同构工程一正常一异常时）

整条模块链 diff 主线 vs 变体（先 `tr -d '\r'` 再 diff——diff -q 会因 CRLF 把相同文件误报为不同），链上模块全部一致 → 整段排除，嫌疑立刻收敛到例化参数/寄存器表/时序约束差异。比逐模块读代码快一个量级。

**diff 报告干净不可全信**：diff 输出长时眼扫会漏看单行差异（本会话 isp_top 曾报过「diff 干净」但实际抄漏 `wire algo_valid = ...` 一行）。diff 干净仍怀疑时，把嫌疑模块的**关键门控/使能/valid 类信号逐个 `grep -n <信号名> 两工程对应文件`** 对照——每个信号一行输出，漏不掉，且直接看出「一边有驱动、一边只有例化引用」（无驱动 = TD Undriven 接 0 实锤）。

## 移植官方例程 .v 的 module 名陷阱

cp 官方文件到新文件名（如 uics500reg.v → uics500reg_1080p30.v）时模块内部 module 名仍是旧名，例化引用新名报 HDL-8007 black box（elaborate 阶段秒挂）。改完 grep 确认 `module <新名>` 与文件名/引用一致再编译。
