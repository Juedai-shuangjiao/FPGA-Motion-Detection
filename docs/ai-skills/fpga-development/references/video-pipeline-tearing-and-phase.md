# 视频管线：半帧撕裂与显示/前景两链相位错位

## 改 RTL 前必查项目文档的历史结论
bg_read 的全帧读（345600 拍 = 3.46ms）实机失败过两次：贴着消隐期 4.2ms，DDR 刷新/背压下超预算 → 读被显示期打断 → 画面水平错位/卷绕回归。动「读量/读策略」前先 grep 项目文档（当前状态与下一步.md）里的历史结论，别凭「带宽算得下」就改。

## 半帧交替更新的撕裂本质与解法
- 撕裂点 = 「每帧更新区」与「隔帧更新区」的边界行：两行标记年龄差 1 帧，快速运动时可见、静止消失。
- **重叠 N 行不会消除撕裂**：交界重叠 4 行（A=0~361/B=358~719）把 1 个撕裂点变成 2 个（重叠区两侧），细线依旧——下板实测证伪「重叠即根治」的推理。
- 正确解法 = **非对称半帧**：上 1/4 读 184 行（0~183）、下 3/4 读 544 行（176~719）、交界重叠 4 行（176~183 每帧更新）。撕裂点移到上部 1/4（行 177/178 与 183/184）= 静止背景区，运动场景无感。读量：A 帧 88320 拍（0.88ms）、B 帧 261120 拍（2.61ms），消隐预算内。读满上限用 half_sel 选两档参数（S_total_cap）。
- 带宽换算口径：读量 = 行数 × 480 拍（cur 240 + bg 240，128bit 粒度）；消隐 3.8ms ≈ 380000 拍（100MHz），读量须留 ≥30% 余量给仲裁损失与 DDR 刷新。

## 显示正常但前景标记错位 = 两链相位差（实机特有）
- 现象：画面正常 + 涂白（overlay）固定右偏 + 右边界内容卷到最左。这是 DDR 视频管线经典 bug（netv2-fpga「Misalignment of Overlay and Stream」同款：DRAM 批量取数相位 vs 流同步时序）。
- 取证方法：tb 注入「行中已知列」内容翻转（bg 行中 word、高 96 位翻转），用 FGWR 落位地址 + 比较链 f_cmp 组号 + morph 输出计数三点对拍判断列位移量。
- **tb 三链零错位 ≠ 实机零错位**：tb 的 DDR 模型理想保序零延迟，实机差异（真实 DDR 时序/启动相位）复现不了。此时停改 RTL，改用**数码管二分**：写计数（判据 A300=172800 低16位）+ 读计数（bg_read O_dbg_rd_cnt，非对称半帧判据 = 5900/FC00 交替显示）同时观测，判定错位在写链还是读链。
- sideband 标记延迟必须与数据延迟同拍数：morph valid 链 644 vs 数据 643 差 1 拍 = 错位 1 组（4 像素）的根因；行缓冲类模块的 tuser/tlast 同理。

## tb 探针自检
- Verilog tb 里 reg/integer 声明不初始化 = X，`X == 0` 恒假 → 探针静默失效（vo_px4 未初始化导致探针全不打印）。所有探针计数器声明时赋 0。
