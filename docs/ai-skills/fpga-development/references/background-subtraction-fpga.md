# FPGA 背景减除/运动检测：算法层知识（2026-10-27 调研 + 实机现象分类）

适用：背景检测类功能的算法层问题（数据对齐已修好但效果不达标的阶段）：识别不准、噪点、全白、残留、参数调不动。

## 开源现状（web_search 结论，供与老师讨论/写方案报告）

- **帧缓存式背景减除是标准做法，非自创**：背景模型存 off-chip SDRAM（「因 FPGA 内部 RAM 不够」），读回与当前流相减。SCIRP 论文（Hardware Design of Moving Object Detection on Reconfigurable System）：120MHz 专跑 SDRAM、25MHz 采集、七级流水、stripe 形态学、VGA 51fps。Appiah 60fps 用 4 个 frame buffer。本工程（纯逻辑 + 单口 DDR 串行仲裁，无 ZYNQ VDMA 兑底）独特点在两路数据都从 DDR 读，对齐难度比「一路 DDR + 一路实时流」高一档——平台约束不是思路缺陷。
- **ZYNQ 系主流实现**：VDMA 从 DDR 读参考帧 + 摄像头当前流，模块内做差。两路对齐的公开做法：参考帧先入 FIFO，等当前流帧头（SOF/tuser）到来才开读 FIFO；FIFO 读延迟 2 拍 → 当前流打 2 拍补偿。与本工程「标签门控 + valid 打 1 拍对齐 + mod 路由」同一思想。
- **算法家族**：帧差法（相邻两帧差，不需采背景、对光照鲁棒，但只检测运动轮廓）／固定背景减除（本工程所用，整块填充效果好）／Running Average（B=(7B+cur)/8 背景缓慢自适应更新，抗光照渐变）／GMM（硬件代价高，1080P 91fps 只需 3% 资源，超出竞赛需求）。
- **标配后处理**：灰度化（Y 通道，几乎全部项目都做，省 2/3 比较逻辑+抗噪）；形态学（腐蚀去噪点+膨胀补洞，见下）；包围盒框选（检测后行/列 min/max 画矩形，展示效果优于涂白）。
- 背景压缩存储（2×2 累加压缩省 1/4 内存）是省 BRAM 思路，本工程背景在 DDR 里收益不同。

## 实机现象分类与对应解法（数据对齐已修复后的算法层现象）

| 现象 | 根因 | 解法 |
|---|---|---|
| 静态背景出现白斑 | 传感器噪声，cur/bg 同像素微小随机差异超阈值 | 开运算（腐蚀去单点）+ 阈值调高 |
| 手/目标不能 100% 识别、边缘锯齿 | 目标与背景颜色接近处差值 < 阈值 → 漏判 | 阈值调低（颜色接近块是阈值问题，3×3 形态学补不了大洞） |
| 画面全白（偶尔/动作大时） | AE/环境光变化 → 全图像素漂移 → 处处超阈值；固定曝光下光照变化同样触发 | 根治靠背景自适应更新（Running Average）；演示应急 = SW4 拨回重采背景；阈值调高可缓解但会漏手 |
| 手伸走后白色残留 | 分半帧交替更新（每帧只刷半屏，固有 2 帧延迟）+ 读不满帧数据作废不更新 | 提高读满率（bg 门控水位 300→250、vo 触发 200→250 双降错峰）；半帧机制下残留 = 读不满的显性症状 |

核心矛盾：手洞要低阈值、全白要高阈值——单纯调阈值两头难顾，正解组合 = 阈值适中 + 开运算去噪 + 背景慢更新抗光照。

## 单口 DDR 带宽账（调度改动安全判据，快算法）

- 一帧总拍数 = 总行数 × 每行拍数；显示期拍数 = 有效行 × 每行拍数；消隐期 = 差值。
- 写一帧需拍数 = 一行 128bit 字数 × 有效行（720P = 172800 拍）；显示读同量；背景读同量。
- 三路合计占显示期比例：720P = 3×172800 / 1584000 ≈ 33% → DDR 空档 67%。写仅占 ~11%，「读优先/压缩写时间片」不会丢摄像头数据（写拿到 11% 时间片就够，怎么压都压不到）。
- 结论模板：带宽没吃满时，「谁优先」不是瓶颈——先修数据对齐/状态 bug，调度优先级留作鲁棒性保底。

## 形态学滤波硬件实现要点（morph_filter.v 已验证）

- **可分离实现**：3×3 拆成 3×1 水平 + 1×3 垂直两级，每级一个维度。开运算 = 水平腐蚀 → 垂直腐蚀 → 水平膨胀 → 垂直膨胀（4 级，总延迟 642 拍：1+320+1+320）。
- **行缓冲只在 I_valid 拍推进**（`if(I_valid) row <= {row[1275:0], data}`）：空洞拍不 shift，「320 拍」= 一行 320 个有效拍，行与行窗口严格对齐；空洞拍推进会导致上行窗口漂移、行边界错位。
- **垂直窗口延迟对齐**：上行 = row 缓冲 640 有效拍前（row2[1279:1276]）、中心 = 320 拍延迟链 [319]、下行 = 当前拍；输出天然延迟 320 拍。valid 链同步延迟（642 拍移位链）。
- **水平窗口位序**（4 像素/拍，bit0=最左）：处理中心 = 1 拍延迟 d1；左邻 p0 用 2 拍前 d2[3]、其余 d1[i-1]；右邻 p3 用当前拍 d0[0]、其余 d1[i+1]。
- **帧开始清全部行缓冲与延迟链**（防跨帧残留）；行首尾 1 像素窗口退化可接受（形态学边缘本来就退化）。
- 资源账：4 级垂直 = 4×2 条 1280bit 移位寄存器 ≈ 10240 FF，PH1P35 无压力。

## 参数与调试排布建议

- **拨码/按键占用查证要追到模块例化**（用户纠正过）：grep 顶层没有 `I_sw[0]`/`I_sw[1]` 直接引用 ≠ SW1/SW2 空闲——sw_mode 模块通过例化端口 `.sw(I_sw)` 整束用了它们（SW1/SW2 组合 = 显示模式切换）。判定输入资源空闲必须 grep 全工程（含例化端口连接 `.xxx(I_sw)` 形式）再下结论；给新功能分配拨码/按键前先向用户确认现有规划（用户有完整的拨码使用规划文档）。本工程四拨码全部有主：SW1/SW2=显示模式、SW3=曝光模式、SW4=背景检测。
- 阈值档位输入优先用空闲按键（KEY 系）+ 数码管显示档位，不要动拨码。
- 演示应急操作：SW4 拨回再拨下 = 重采背景（全白/环境变化后恢复），用户已会此操作。
