# 端口契约变更检查清单

改任何模块的端口（增/删/改位宽/改语义）时，按下三步走，缺一不可：

1. **grep 全部例化点**：`grep -n '模块名.*u_' wrapper文件` 或全局 grep 端口名——找出所有调用方，逐个同步接线。改语义（如 I_sw4 从锁存改实时）比增删端口更容易漏：名字没变、调用方不报错、功能悄悄错。
2. **联合编译验证**：iverilog 不能只编被改文件（新端口在单文件里只是声明，不报错）——必须连同 wrapper 顶层一起编：`iverilog -g2012 -o /tmp/chk -y src -y src/key -I src wrapper.v hdmi_mixer.v`，错误/警告全清零。TD 对未连接输入端口会悬空（综合可能不报错，功能随机错）。
3. **commit 前核对文件数**：端口契约变更预期改动数 = 声明文件 + 所有例化文件。git commit 输出「N file changed」与预期不符 = 漏改警报，立即查。
4. **一个物理量的两种语义必须拆成两个信号**：拨码/状态位的「实时电平」（当下状态，控使能/开关）和「历史锁存」（发生过即保持，控显示/标记）不能复用一个信号——复用后一个语义悄悄错（如：OSD「已采」要锁存、涂白使能要实时，共用后 SW4 拨上涂白永远关不掉）。改接口时先列出每个消费方要哪种语义，按语义拆端口（如 I_sw4=实时 + I_bg_captured=锁存），而不是一个信号两头迁就。

案例（2026-11-01 白点回归）：改 hdmi_mixer 端口语义后只改了 hdmi_mixer 本体，wrapper 例化漏改——I_bg_captured 悬空、I_sw4 接了错误语义的锁存——SW4 拨上涂白不消失。bug 由另一会话检查顶层例化发现。

5. **脚本化删端口行后扫粘连**：regex 删一行后，前一行行尾注释会把同行后面的声明吞掉（`wire A; //注释  wire B;` → B 被注释）→ B 隐式声明为 1bit wire，iverilog/TD 都不报错，上位宽输出截断 → 数码管显示垃圾（如「1FFFE」非法 BCD 恒显）+ 按键调了不反映。删除/批量替换后 grep 一遍 `//[^\r\n]*\s+(wire|reg|input|output)\b` 扫同行「注释后跟声明」模式，逐条拆行。诊断链：显示非法值 → 转码器（bin2bcd）对确定输入不可能出非法输出 → 倒查输入线声明是否被吞/悬空，而非怀疑算法。
