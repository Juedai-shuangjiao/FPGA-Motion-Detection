# 顶部行错位：多路读竞争诊断与残余丢弃链

## 背景
多路读（video_out 显示读 + bg_read 背景读）共用 DDR 读端口，读命令发出拍压入标签 FIFO（vo=1/bg=0），数据落地拍弹出标签路由数据归属。

## Bug 现象（整帧读版下板后）
开启背景检测时显示器顶部 1~3 行错位：
- 第一行 100% 不对（垃圾数据，可被涂白覆盖）
- 第二、三行周期性不对（错位 1~3 行波动），画面静止也错
- 关闭背景检测完全正常（关键二分证据：bg 交织才是触发条件）

## 最终根因（实机 ChipWatcher 四抓定位）
bg_read 的显示期读门控放行：`S_vo_room = I_disp_win ? (水位>=260) : 1`——
显示期水位满（480）时 room=1，bg 批继续读、拖尾跨进显示期，与 vo 预读抢
grant → vo 预读被挡 → 显示 FIFO 在第二三行断供 → 顶部错位。bg 关时无拖尾。
实测证据：显示期 rd_en=1 持续（bg 拖尾）、帧头清场期 grant=1（bg 抢仲裁）、
bg 批把 vo 预读爬坡打断（水位冻结）。

**修复**：显示期直接禁 bg 读——`S_vo_room = I_disp_win ? 1'b0 : 1'b1`（显示期
vo 独享仲裁）。代价：消隐期读不完时背景帧尾部缺行（底部用旧背景数据，
挥手检测在画面中部不受影响）。tb_bg_line 回归 10 帧读满无漏写。

**修复的后续坑（涂白消失）**：显示期禁 bg 后 bg 读量达不到「整帧完成标志」
（S_full_done 只在读满 345600 时置位）→ 差分/涂白链永不启动 → 前景涂白整体
消失。带宽账：bg 读 345600 命令 = 3.46ms，消隐 426000 拍（4.26ms）只留 ~5%
余量，任何损耗（vo 爬坡 480 拍、写批、批间隙）都拖尾——「读满全帧」与「显示期
零拖尾」不可兼得。正解：**读量上限主动缩减**（345600→336000 = 700 行，底部
20 行放弃），消隐期余量充足、读满标志正常置位、涂白链恢复。⚠️ 缩减读量时
「写满判据」必须按比例同步缩（fg_init 写地址判据 22960→22260 = ×700/720），
否则前景标记就绪标志永远等不到、涂白照样不出现——读量 cap 与下游完成判据
是耦合的一对参数。

**判别经验**：「水位满但内容错」= 数据路由/竞争问题而非预读不足；
「某功能开才错、关即正常、静止也错」= 该功能与主链路的仲裁/时序竞争，
不是数据依赖类 bug。

## 残余丢弃链加固（方案 B，防御性保留）
video_out 帧尾残余丢弃旧实现：帧头锁存 vo 在途数，之后「标签=1 的数据落地」才
减计数——标签错位时误减 → 残余漏丢 → 新帧第一批被污染。实机本案例中标签并未
错位（帧头 discard=0），方案 B 未解决顶部错位，但作为防御性加固保留。

```verilog
// video_out 端口
input wire [8:0] I_tag_wrusedw,   //标签 FIFO 已压未弹（wrapper 引出）
// 帧头打 1 拍（等 wrusedw 反映最后一条命令）
reg S_frame_start_1d;
// 锁存 + 递减
if(S_frame_start_1d) S_discard_cnt <= {1'b0, I_tag_wrusedw};
else if(rd_valid_d1 && (S_discard_cnt != 0)) S_discard_cnt <= S_discard_cnt - 1;
wire S_vo_we = rd_valid_d1 && I_rd_tag && (S_discard_cnt == 0);
```

## 验证
- tb_discard_tagless：帧头 vo 在途 10 + bg 在途 30，bg 残余 k 个标签错位（k=0~30）。
  旧实现污染 k 字（k≥10 全漏）；方案 B 污染恒 0。
- tb_vo_discard_b：完整链路（命令队列/标签 FIFO/返回延迟/水位触发/帧头复位），
  错位注入 20/100 全绿。

## 教训
- 计数型丢弃逻辑永远不要依赖「旁路信号的正确性」（标签会错位、计数器可能跳变），
  用「结构不变量」（DDR 保序 = 前 N 个落地就是在途 N 个）实现。
- 二分实验（关背景检测）是这类「交织触发型 bug」最快的定位手段。
- ChipWatcher 抓取组合拳：vsync 下降沿（帧头瞬间）/ disp 上升沿（显示开始）/
  Position 0（触发后全窗）/ Position 1023（触发前全窗）四抓拼图。
- **Trigger Position 是窗口内绝对位置（0~深度-1），不是百分比**：0=全窗在触发后、
  1023=全窗在触发前；用户不熟此概念，给抓取指令时直接说「填 0 / 填 1023」。
- 显示期多路读互斥是基本原则：显示数据补充（vo 预读）必须在显示期独享仲裁，
  任何「水位高就放行」的辅助读门控都会在满水位时拖尾挤占显示。
