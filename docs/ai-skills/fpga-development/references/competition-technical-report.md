# 嵌赛技术报告模板（官方 docx 模板结构）

模板文件在用户桌面（名字是 UUID.docx）；结构固定，写报告直接按此组织：

- 作品名称（≤15 字，汉字/字母/数字都算 1 字；全文不出现学校名）
- 摘要 ≤800 字
- 第一部分 作品概述：功能与特性 ≤400 / 应用领域 ≤400 / 主要技术特点 ≤400 / 主要性能指标 ≤200（用表格）/ 主要创新点 ≤200（逐点）/ 设计流程 ≤200
- 第二部分 系统组成及功能说明：整体介绍（系统框图，各子模块标注清楚+文字说明模块关系）/ 硬件系统介绍（2.2.1 整体、2.2.3 电路各模块；机械设计如无跳过）/ 软件系统介绍（2.3.1 整体、2.3.2 各模块从顶层到底层逐个设计说明）—— FPGA 项目「软件」= 逻辑设计
- 第三部分 完成情况及性能参数：整体介绍（实物正面+斜45°全局照）/ 工程成果（电路成果、软件成果照片）/ 特性成果（逐功能+量化指标，仪器测试/现场照片）
- 第四部分 总结：可扩展之处 ≤300 / 心得体会 ≤1000
- 第五部分 参考文献 ≤20 篇

## 写作要点
- 照片没有就写「（此处插入…照片）」占位，用户补拍；不要虚构配图
- 内容与演示动作严格对应（评分点是唯一导向）：基础要求 4 项 + 扩展要求 2 项 + 高阶挑战 5 项逐项在文中可找到对应表述
- 摘要用词与作品名称/简介一致：背景减除法≠帧差法（帧差=相邻帧相减无采集步骤）；「简介仅一次修改机会」——名称和摘要措辞定稿前让用户确认
- 性能指标表直接填实测值（分辨率/帧率/延迟/资源占用 LUT%+ERAM 数/时钟域）
- **名称定稿后全局同步**：用户确认最终名称后，技术报告名称行、视频脚本解说词、简介全部同步改；正文功能列表必须覆盖名称里的每个词（如名称含「跟踪」→ 功能特性里要有质心速度向量/目标跟踪的对应表述），评委对名称和内容对不上很敏感。向用户确认名称时先摆出候选名和已填入的位置，不要只问「名称确认什么」这类无上下文提问。
