# DDR 视频帧缓存 bug 二分诊断（三路仲裁调试定式）

适用：花屏/错位/卷绕/读旧内容/横黑线等 DDR 帧缓存视频问题，在仲裁结构已改过仍复现时按此定式查。

## 病根定位框架

- **架构级改动后现象「和之前一模一样」= 病根不在改动的那一层**。例：并行门控 → 串行仲裁后花屏错位不变 = 病根不在仲裁竞争；别在改过的层继续挖，回各版本共有的基本读写路径（采集写 → DDR → 显示读）。
- **现象特征定性**（用户问「时序不对还是读的问题」时，回答结构 = 判断 + 论据 + 二分实验三步）：
  - 随机闪烁/白线/位置不固定 = 时序竞争类（仲裁、门控、跨域竞争）
  - 固定位置错位/竖线/卷绕/读旧内容 = 地址/指针/对齐类
  - 「错位竖线 = 采集右边界出现在画面中部」= 帧内偏移或打包对齐错位的指纹（vo 读地址在 vsync 复位后帧尾批未停 → 批带帧头地址读 → 卷绕）
  - **涂白（背景减除差异）双源判别**：涂白 = 位置错位类与亮度差类两源、可叠加。位置错位 = 比较数据/标记映射错位（指纹：高对比静止物体边缘涂白且偏固定距离、卷绕、白点位置固定）；亮度差 = 背景帧与当前帧增益/曝光不同 → 全画面差异 ∝ 增益（指纹：白纸铺满画面时增益高几乎全白/增益低不涂白、白点时间上「飘」= 自动增益波动）。判别实验 = 白纸全屏 + 调增益看是否全白；修法 = 存背景时锁存增益/曝光、检测期间冻结自动曝光（ae_set 闭环，用户自管）。

## 二分三刀（成本低到高）

1. **bg 读参与**：bg 的 I_frame_start 按模式门控（仅检测模式才读），模式 0/1/2 完全不读——隔离 bg 对显示的影响
2. **采背景污染**：上电不碰 SW4 直接看画面——隔离 bg_capture 写 BG_BASE 对正常乒乓块的污染
3. **基本读写路径**：与官方 baseline diff 全部非官方改动（video_in/video_out 写批状态机、grant 门控、帧开始停批、FIFO 复位宽度），逐个审

## 二分隔离门控是临时设施，诊断结束必须撤销

- **「仅模式 N 启动某功能」的门控是诊断期二分隔离用的临时设施**，不是正式设计：隔离实验做完、元凶锁定后要把门控改回正式用途条件（如 bg_read 启动 = SW4 已采电平跨域同步打拍，而非「仅 KEY4=Sobel 模式」）。门控残留的表现 = 正式功能在任何常用模式下「完全没反应」，且代码层查不到禁用开关——最隐蔽的一类「功能不通」。
- **查「功能完全没反应」先 grep 启动/使能信号在顶层的生成逻辑**，找注释带「诊断/仅模式X/隔离」的与门残留；grep 不到「禁用/disable」字样不代表没被门控（门控形式是「与上一个恒假条件」，不是显式 disable）。
- **锁存类使能（fg_init 首轮写满拉高保持）与开关型功能组合时，输出门控必须再 AND 开关电平本身**：init 一旦拉高永久为 1，开关拨回后功能继续生效、无法关闭——涂白门控 = init && sw4_电平 && 标记。开关型功能的每处输出/使能都要带上开关电平（各自时钟域打拍），拨回即停。

## 诊断读数与标志的语义陷阱

- **数码管诊断读数先 grep case 映射**确认显示的是哪个信号（写计数/读计数/bg 读计数/帧开始计数）——把 A 计数当 B 计数推演会整段错方向。
- **诊断显示语义会随调试 patch 漂移**：同一个拨码位置的显示内容被反复改（同一位置先后显示过写计数/bg 读消隐期计数/帧开始计数），用户报的数可能来自旧 bit 的旧语义——读数前确认「当前源码该 case 显示什么」+「用户下板的是哪个 bit」，两个都对上才推演。**LED 同样会漂移**：诊断 patch 复用 LED 后（如 LED4 从「摄像头配置完成」改成「写 FIFO 满锁存」），用户记忆的 LED 语义与当前顶层 O_led 接线已不一致——用 LED 判据前先 grep 顶层 O_led 的当前赋值，别把用户记忆的语义当现状。
- **诊断显示绑定调试对象的使能输入，不破坏原规划**：需要新诊断读数时，把显示切换挂在「用户正在测的功能的使能输入」上（SW4 拨下 = 正在测背景检测 = 数码管临时切显 bg 读计数 + LED4 显 fg_init；拨回立即恢复原规划显示）——常态显示保持正式用途，诊断值只在主动测试时出现，既绕开「占用显示入口」与「无观察手段」的两难，也避免用户反感的「乱占 SW 显示」。编译前把每个观察量的判据表写好（数码管值/LED 亮的含义对应哪个断点层），一次下板分清断点。
- **诊断 LED 用锁存设计**：FIFO 满（full_flag）这类瞬时事件做成「满过锁存到复位」接 LED——上板后 LED 常亮即实锤溢出丢字，比数码管计数更直观。
- **启动链多位锁存诊断码（「功能完全没反应、计数恒 0」的定位快刀）**：模块一个命令都没发出类故障时，把启动链上每个嫌疑信号做成「见过高电平就锁 1」的锁存位（脉冲锁存/电平直引），全部拼进数码管空位**一次编译同时观察**——SW4 电平位、触发脉冲锁存位、状态机 active 锁存位、仲裁 grant 锁存位各占 1 位数码管，编译前写好判读表（0xxx=电平没到 / 1 0 xx=脉冲没到 / 11 0 x=active 没置位 / 111 0=仲裁没给时间片 / 1111+计数0000=内部门控），一次下板定位断点，省去每个嫌疑信号各编译一轮。**拼 seg_data 必须凑满 32 位**：`{12'hFFF, 诊断位, cnt[15:0]}`——28 位表达式赋 32 位会高位补 0，最高位数码管显示 0（用户看到 0FFF0000 而非 FFF0000 会来质疑，这是显示拼接瑕疵、不是诊断值错，回答时先解释位序再判读）。
- **OSD「已采」提示只是电平显示**（条件 = 模式0 && SW4 电平），不是真采完标志——用户报「显示已采但检测不通」时，不能据此断定背景已写入；诊断背景写没写要引真状态标志（bg_captured/bg_writing）输出。
- **patch 后先验证语句层级再编译**：patch 插入的 if/赋值若落在 always 块外（块先 end 闭合、if 成模块级语句），TD 编译器静默忽略该段且编译照样出 bit——「编译成功」不证明代码生效。实例：数码管阈值覆盖 if 落在 always 块外 → 板子数码管永远显示 case 内容、功能「没生效」，重新逐行核对 begin-end 层级才定位。补丁后用 read_file/sed 核对插入语句的确切层级，确认在目标 always 块内。
- **帧开始频率诊断**：计数器每 S_frame_start +1 送数码管，正常 60Hz 下每秒匀速 +60；秒级跳几千 = 帧开始信号毛刺（FIFO 频繁复位 + 读写指针乱 = 错位花屏的直接机制）。反向解读同样关键：**计数不动 + 画面实时正常 = 帧开始信号停了（不是显示 bug）**——「模式内数码管冻结、切换模式瞬间值才变」说明该模式期间信号真的没跳（组合逻辑显示不会冻结）；帧开始停 → 写指针不切换 → DDR 退化为单块循环 → 写读永远同块、画面实时且不错位。即「乒乓切换活跃反而花屏、帧开始停了反而正常」——帧开始驱动的乒乓块切换与显示读的 vsync 帧不同源，切换本身就是错位源；诊断时别把「信号停了」当新故障急着修，先利用它反推「活跃时为什么错位」。
- **排除「显示链影响」用引用剥离法**：现象随拨码模式变化且该模式只接数码管显示时，把其他模式的显示分支全部改成固定常量（不引用任何诊断信号），若现象不变则显示链/信号引用与病根无关，收窄到按键使能链或硬件共网。

## 现象随 UI 开关/模式变化的诊断

- **现象和 SW 拨码模式相关时，先查该模式在代码里的全部用途再下结论**：grep 顶层 + 数据路径模块（video_in/video_out/bg_read/仲裁器/hdmi_mixer）确认这个 mode 信号只用于数码管 case/按键调节使能/LED 时，它不可能直接改数据路径——病根在间接链，别再顺着「模式本身」挖数据路径。间接链按序查：①各调节模块的 I_enable（如 S_mode 0/1 使能 ae_set、S_mode 2 使能二值阈值、S_mode 3 使能 Sobel 阈值）+ KEY2/3 tick 毛刺 → 乱调寄存器；②SW3/SW4 关联逻辑（自动曝光跳帧、背景采集）；③SW 引脚与其他信号在 PCB 共网（拨低拉低共网信号）。先做 SW3/SW4 独立隔离实验（固定其电平只动 SW1/SW2），别一次拨多个开关测。
- **提问前先 session_search 回看历史对话**：拨码/按键的「某个模式是干什么的」往往在此前会话里定过（调试期临时占用、门控约定）。用户说「回看之前的对话」= 先查历史再问，别把历史上已定的约定当新问题抛回去。
- **SW 拨码模式（S_mode，选数码管显示/按键使能）和 KEY4 算法模式（S_algo_mode，切原样/灰度/二值/Sobel）是两套独立系统**——用户报「模式 X 正常/不正常」时先问清是哪一套（SW 拨码还是 KEY4），两套混着推理会把门控结论全盘带错；调试门控信号（如 bg 读的启动条件）挂在哪一套模式上，改代码时要写清楚注释。
- **多日调试项目把每个二分实验结论写进项目状态文档**（如「模式 3 = 禁用 bg_read → 画面正常 → 元凶锁定 bg 读」）——后续会话先 grep 项目文档里的「模式 N 正常/禁用」类结论再推导，能直接找回当时锁定的元凶，省掉重复二分。

## 仿真行为模型的坑

- FIFO/BRAM 行为模型的时钟结构必须匹配真实 IP：**读写同域 → 单时钟近似；读写异域（如显示 FIFO 写 DDR 域/读像素域）→ 必须分域建模**（写指针在 clkw、读指针在 clkr 各自 always + 指针 2 拍同步）。**判空/判满/水位一律用指针直接差 `wptr - rptr`（位宽自然模回绕）**：empty = (差==0)、full = (差>=深度)——同步滞后比较（`wptr_sync <= rptr`）让同域 tb 空判定晚 2 拍多弹错位，三元防下溢在指针回绕窗口把差当 0 周期性误判空（弹链断裂），两者都别用。异域 FIFO 用单时钟模型时，读侧 re 被写时钟采样 → 读指针规律跳增 → dout 序列规律丢字假象（每 5 字丢 1 与 re 周期相关），会引着往写侧/仲裁方向查多轮；双时钟模型指针行为也易出假象（rdusedw 卡死、每帧只写 1 批等）——模型复现的异常必须先解释清楚模型自身机制再当真，否则整段诊断被模型 bug 带偏（实例：双时钟模型复现「每帧只写 1 批」，一度误导往帧开始停批方向查，实为模型指针回绕假象）。
- **自写 FIFO 模型先检查同拍读写时计数的双重非阻塞赋值**：`if(we) cnt<=cnt+1` 与 `if(re) cnt<=cnt-1` 同拍都命中时后者覆盖前者 → 水位虚低 → 行弹提前、弹出未初始化 mem（X）——模型里 cnt 更新必须单次赋值（`if(wr_ok&&!rd_ok) ... else if(rd_ok&&!wr_ok) ...`），且 mem 数组读出的 X 是 underflow 指纹，不是 RTL 信号真值。**首选 TD IP 目录里的真行为模型**（src/ip_source/<ip名>/soft_fifo_*.v，iverilog 可直接编译，模型自包含子模块）替代自写模型，别在模型 bug 上耗诊断时间。
- **iverilog 的 `$display("%0t",$time)` 以 timescale 精度（1ps）为单位**：7ms = 7000000000ps。写「时间窗口采样/打印条件」时把 ps 值误当 ns 写（如 8000000 想表达 8ms 实际是 8µs）→ 采样窗口永远不触发、打印空白——用 $time 条件时先换算成 ps 再写，或改用「帧相位计数器」做窗口判定（不受单位坑影响）。
- **模型的赋值语义必须复刻 RTL**：RTL 用非阻塞 `<=`，模型里若改成阻塞 `=`，同一时钟沿多个 always 块的执行顺序会把「cnt==N 停批判定」错过（计数块先跑把 cnt 从 N 直接推过、判定块看到的是 N+1）→ 读批永远停不下来、读占空 100% 假象——模型卡住先查赋值语义和块顺序，别顺着假象推 RTL 结论。
- **帧边界清模型状态**：帧开始的 FIFO 清空要连「在途计数/延迟链」一起清零——不清则跨帧累积，触发条件（等效水位 ≤ 阈值）永不满足，模型表现为读死锁（读计数 0），与真实 bug 无关。
- **压缩帧仿真（为缩短 vvp 时间而压缩帧周期）的判据必须按帧统计、只判「读满帧」**：压缩帧下目标模块每帧读不满是模型必然（数据作废、路由错位是预期），把整段仿真的错位计数全盘累计会把「读不满帧的预期错乱」当成 RTL bug。正确判据 = 每帧单独统计 + 帧末检查计数是否达到理论总量（如 172800），只对读满帧的统计做断言。**配套：判据前提要先断言成立**——「读满帧内零错位」在 full_frames==0 时是空通过（没有样本），先 check(读满帧数>=N) 再 check(错位==0)，否则修复无效也会显示 PASS。
- **模型里邻居通道的消耗速率必须按真实值**：vo 显示消耗 ≈0.14 字/拍 @100M（172800 字/12.29ms 显示期），模型写成每 2 拍 -1（0.5 字/拍，快 3.5 倍）→ vo 读批占满仲裁把 bg 饿死 → bg 每帧只读消隐期那点量，被误诊为「bg 读不满」——供给/消耗类模型的速率比例失真会造出方向相反的假结论。

## 读地址不递增（「240 个命令读同一地址」类，白线错位根因）

- **读地址生成必须逐命令递增**：行块读状态机的地址 = base + 行偏移 + 行内字偏移，行内字偏移要在每个命令拍 +8（128bit 字 = 8 个 32bit 字地址，参考 video_out 的「读使能拍地址 +8」节奏）。只按「每行 + 一行量」推进且忘了行内递增 → 一行 240 个命令全部发同一地址 → 读回 240 个相同字 → cur/bg 逐字比较全错 → 实机「静态画面白线飘、手伸进成密集线不成块」。地址单位还要核对：行偏移若按「128bit 字数」存，拼地址时要 <<3，与 base（32bit 字地址）统一量纲。
- **为什么这类 bug 能活过多轮仿真：旧仿真只验证「读计数」（发出/收到 172800 拍），DDR 返回模型是伪数据，从未验证「数据内容与读地址对应」**。地址类 bug 不改变计数 → 计数类判据全绿。
- **验证数据-地址对应的仿真手段（地址编码数据法）**：返回数据 = 地址低位编码函数（如 enc = addr[5:0]，要求各缓冲基址的低 6 位全 0 → cur 字 k 与 bg 字 k 的 enc 相同），再**层次引用直接比对两路解包输出**（u_bg_read.S_cur_96 vs S_bg_96 同拍相等）——错位 1 个字（地址差 8 → enc 差 8）立即检出，不经过阈值（阈值 40 会吞掉小错位，测不出）。基址低位不全 0 时换「基址贡献为 0 的位」做编码。

## 写批跨帧卷绕（帧尾批写到新帧头，主线仿真实锤、两工程已同步修复）

- **机制**：写批 240 拍在仲裁挤占（读通道 grant 优先）下会被拖慢，可能跨过帧开始拍；帧开始拍写地址已复位到新帧头 → 帧尾批（上一帧数据）写到新帧头 → 帧内容卷绕错位。bg 读挤占命令通道时最容易触发，但 bg 禁用后读批挤占仍可能造成，是确定性 bug 不是概率 bug。
- **指纹**：错位竖线/帧内容卷绕/画面首部出现上一帧尾部内容，写计数与读计数都≈正常帧长（不是计数异常类）。
- **修复（已定型的写法）**：S_frame_start 打 1 拍后进写批状态机，帧开始拍强制 S_ddr_wr_valid <= 0 停批——组合脉冲直接进状态机易 hold 违例，打拍后转 setup。停批丢弃的帧尾残留（<240 字）由 FIFO 帧复位清除，下一帧从头写：丢尾行比整帧卷绕可接受得多。

## 读批帧尾在途返回混入新帧（vo/bg 读侧的卷绕，复现仿真坐实）

- **机制**：vsync 前 vo/bg 发出的读批命令还在 mc 命令队列里排队（bg 显示期补读挤占命令通道时最常见），返回被拖到帧边界清场窗口（vo FIFO 复位/bg abort 均为 300 拍）之后才落地——复位窗只挡窗口内的落地，拖过窗的帧尾返回照进新帧：vo 侧帧尾字混入新帧 FIFO 头，bg 侧帧尾返回参与新帧的 mod 路由计数。
- **指纹（与写侧卷绕区分）**：显示器左边界一段显示右边界的内容（从上到下贯穿的垂直条带）+ 视频内容整体右移 K 列 + 叠加标记相对目标方向性错位（目标左移时标记显超前、右移时显落后——标记位置正确、视频内容右移所致）+ 静态物体（水管类）被误标记（bg 的 cur/bg 路由错位 → 比较数据错位）。读计数/写计数可能都正常，无计数类异常。
- **坐实手段（tb 结构）**：例化真实 video_out + bg_read + ser_arbiter + 标签 FIFO，DDR 模型用「命令队列（512 深、每拍执行 1 条）+ 40 拍返回延迟链 + 地址编码数据」，HDMI 侧用真实行/帧时序模型 + 逐像素期望比对。判据只比对判据帧头 1024 像素即可检出（错位在帧头，不必跑完整帧）；判据帧选择 = 干扰源活跃一整帧后的下一帧头（SW4 拨下后第 2 个 vsync 之后的帧）。
- **修复（已应用，tb 编译通过，待下板验证）**：帧开始拍锁存「在途读数据数」→ 之后每落地一个本路标签返回递减，减到 0 前的返回按序丢弃（DDR 保序保证残余先于新帧数据落地，不会误丢新帧）——vo 锁存 S_rd_in_flight → S_discard_cnt 门控 FIFO 写使能（we = rd_valid_d1 && tag && cnt==0），bg 锁存 rd_total−ret_total → S_pend_discard 门控 S_ret_mod 递增。三个实现细节：①vo 递减条件与写使能同口径（rd_valid_d1 打 1 拍对齐标签）；**且锁存源计数（S_rd_in_flight）的递减口径必须同步改成同一拍对齐**——旧口径 rd_valid（未打拍）&& rd_tag（打 1 拍）使 tag 恒比数据晚 1 拍 → in_flight 恒多计 1 → 锁存值 = 真实残余 +1 → 丢弃时多丢 1 字 = 新帧头第 1 字丢失（tb 实锤：首错像素停在帧头第 1 字）；②bg 的残余递减分支必须不含 !abort 门控——清场期（abort 300 拍）落地的在途返回同样要递减计数，否则 abort 结束后 pend 仍是锁存初值，会把新帧头 K 个真实返回误当残余丢掉（丢字错位换一种形式回来）。固定加宽清场窗也行但代价大（新帧读启动延迟），锁存-按序丢弃自适应拖尾长度。**锁存源声明要前移到使用点之前**（改递减口径会用到后声明的 reg——TD 先使用后声明拆网教训同样适用于 reg）。
③**锁存差的两个计数必须同口径（都计「全部已发/已收」），锁存值才等于真实在途**：ret_total（已收返回总数）必须对每次落地都 +1——含清场期落地与残余丢弃拍；若 ret_total 在清场期停计（曾为配合白块修复这么写），锁存 = 真实在途 + 清场期落地数，把「清场期已丢弃的」再当残余丢一遍 → 新帧头一批真实返回被误丢、cur/bg 路由错位回归（表现为比较数据整体错位）。正确分工 = ret_total 全计数、mod 路由保持清场门控（!abort）——计数与路由解耦，各自口径独立正确。④**边界拍当拍落地漏计候选（左移 40 像素未破案的开放疑点）**：锁存差 = rd_total − ret_total，ret_total 是 rd_valid 打 1 拍（d1）后才计数——帧开始拍当拍恰有最后 1 个返回落地（rd_valid=1 未打拍）→ 锁存值多 1 → 新帧头多丢 1 字 → cur 前移 1 字。验证 = tb 加模型侧真值计数器（按返回流来源判定归属，不依赖 RTL 标签）与锁存值同拍对比，帧开始拍打印 rv/rvd1/rd_total/ret_total 四信号。修法方向 = pend 锁存与 rd/ret_total 清零推迟 1 拍到 frame_start_d1（新帧首命令 ≥340 拍后发出，安全）。
- **同族症状区分（都是帧边界丢尾，修法不同）**：屏幕中部/底部固定 2 行黑线（叠加活跃时可见）不是本条的返回混入，而是 valid 门控链帧尾数据排不出被清链丢弃 → DRAIN 排空根治（见 sim-debug-methodology.md 有效拍域一节规则 5）；本条的指纹 = 左边界垂直条带显示帧尾内容 + 内容右移 + 方向性错位（左移显超前/右移显落后）。

## 写拍吞读命令（写命令打 1 拍的尾拍溢出 → 标签 FIFO 压弹错位全链崩）

- **机制**：video_in 的 DDR 写命令打 1 拍（wr_en <= 写批使能寄存），写批 valid 降拍后写命令仍发 1 拍；仲裁器若只接写批 valid（vi_busy = wr_req），valid 降拍即切走 grant → 写命令尾拍与 vo/bg 读命令同拍 → DDR 写优先吞掉读命令 → 但标签 FIFO 按顶层读使能照压 → 标签压弹错位。每帧 N 个写批 = N 次累积错位，帧间随机 = 现象闪。
- **症状双面（同一根因，用户直觉「细线↔错位循环」的机制）**：①标签错位 → vo/bg 收数路由乱 → 画面错位 + 背景减除 cur/bg 内容错位（静止物被涂白）；②读命令被吞但 bg 内部读计数照 +1 → 计数与 DDR 实际执行错位 → 读不满（数码管读满值/中间值交替）→ 半帧撕裂细线。修一个不修另一个就表现成「细线消失→错位出现」的循环——两个症状共享一根因时别当两个 bug 分头修。
- **修复五件套（互相兜底，缺一必漏）**：①顶层读使能 & !写命令拍（标签压同步关 → 压弹匹配）；②vo 的 grant & !写命令拍（vo 读计数/地址与 DDR 实际执行同拍）；③bg 读使能 & !写命令拍（bg 计数同拍，bg 需新增写拍避让输入端口）；④仲裁 vi_busy 展宽到写命令拍（valid | wr_en，源头防写读同拍）；⑤例化接线。**架构回退（撤销 grant/直连）时必须逐条检查此前「写拍精确门控」类修复是否被连带撤销**——历史上修过的三处门控在撤销 grant 时全丢、同款 bug 数月后复现；注释描述的门控与代码不一致时以代码为准（直接 grep 读使能的完整条件表达式）。
- **tb 模型差距**：简化 tb 若不给写命令建模（wr_en 尾拍溢出）且 DDR 模型没有「写优先吞命令」行为，仿真全绿测不出——补模型 = 写命令拍模型（wr_en <= busy && grant 打 1 拍）+ 顶层同款门控 + 断言「写读同拍拍数 == 0」；吞命令错位本身靠静态分析 + 实机现象坐实（DDR IP 闭源，吞命令行为下板才可见）。

## 读计数倍率直读（过度读定位，2026-10-25 实战闭环）

- **读计数/写计数与理论帧长的比值是强诊断**：正常一帧 1280×720 数据 = 172800 拍（128bit 字），数码管读计数 0x3F840=260160 = 1.5 倍 → 每帧多读半帧。多读的帧数据压满 FIFO 溢出丢弃，vsync 帧开始丢半帧 → 错位花屏（画面下 1/3 花屏+内容像背景上 1/3）。计数报「非整数行」偏差（多 87360 = 68.25 行）说明不是多读几行，而是读节奏整体快于消耗。
- **过度读机制（video_out）**：DDR 读数据约 40 拍延迟才返回进 FIFO，读触发判定用滞后水位（空余≥300 读 240 一批）→ 读批结束时滞后水位仍低 → 批间立即重触发 → 读节奏 1.5 倍于消耗。
- **修复**：读触发条件加「在途读数据计数」（已发命令−已落地，等效水位 = wrusedw + 在途）且触发水位降到 30——读批 240 结束后等效水位 ~240 远高于 30，必须等消耗压下去才读下一批，批间留出消耗间隙、读节奏=消耗节奏。在途计数在 FIFO 复位期清零（残余返回落地丢弃）。
- **行为仿真复现/验证**：模型建 40 拍延迟链 + 等效水位触发——修复前读占空 100%、修复后读计数=消耗量、FIFO 水位健康。模型踩过的坑：读批计数必须非阻塞赋值（阻塞 = 会错过 cnt==N 停批判定）；帧边界清在途计数（不清则触发条件永不满足、读死锁）。
- **诊断计数寄存器位宽不够时读数 = 总量 mod 2^N（溢出截断）**：切分辨率前检查所有 debug 计数器的位宽——18 位最大 262144 够 720P（172800）但 1080P 一帧 388800 会截断成 388800−262144=126656（0x1EEC0）。截断读数本身不说明数据坏：先算「期望总量 mod 2^位宽」对照，对得上 = 计数正常、只是显示截断；别把截断值当异常值去查数据路径。
- **修复后 WNS 可能变薄**（916ps→200ps，仍为正）：全量重综合布局差异 + 加法比较逻辑成本，属正常波动但记档观察。

## 运动检测交互铁律（关联 SKILL.md「SW4 集成到原样模式」段）

- 算法模式恒 4 档，新功能只内嵌模式 0 + 开关，绝不新增第 5 档；叠加用逐 24bit 掩码 MUX（前景白/背景原样），不需 ERAM 涂白链。
- **检测「完全无效果」时先一刀切输出链：恒白实验**——把叠加 MUX 的掩码条件临时换成开关电平本身（SW4 开=整帧恒白，无视检测结果）编译下板：SW4 拨下全白 = 开关→MUX→打包→显示整条输出链通，问题在检测内部（阈值使能/背景写入/行缓存）；画面纹丝不动 = 输出链断（MUX 选择、valid 对齐、打包），顺链查。检测内部不白而恒白实验也不白时，先怀疑输出链而不是继续抠检测算法。
- **SW 拨码做上升沿触发时注意「上电前已闭合 → 无沿可采」**：SW4 采背景用上升沿检测（sw4_1d && !sw4_2d），若上电/复位前 SW4 已拨下则检测不到沿、背景永不采（BRAM 全 0，检测输出大面积白或恒无标记）。让用户测试时「拨回再拨下」制造新沿；若要稳定可改成电平判定（SW4 开即每帧采背景）或上电复位时同步读一次电平补一次触发。
- **KEY2/3 的 tick 会同时进所有使能成立的调节模块**（S_mode 0 自动模式下 target_set 和 motion_threshold_set 使能可同时为 1）：用户报「按键调的是目标值」只能说明 target_set 在响应，不能证明另一模块没响应——数码管被原规划显示（曝光/增益/阈值）占用时，运动阈值这类「无显示出口」的调节值实际变没变是盲区，要靠现象（画面白点变化）间接验证，别据「按键调了目标」就断定另一条使能链断。
