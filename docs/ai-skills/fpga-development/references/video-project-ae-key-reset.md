# 视频流工程：复位链路 + ae_set 按键调节 + tick 连续调节模式

FPGACompetition 工程（PH1P35MDG324，SC500→MIPI→CSI→RAW10→ISP→DDR→HDMI）里几个非直观点，分析或重构按键逻辑前必读。

## 复位链路（HX1P35A 没有独立复位按键，别搞混）
pin.adc 里 `I_rst_n = R10`（PULLUP），但**这个 R10 是米联客例程(_video_base)遗留的错误映射**：康芯 HX1P35A 引脚表里 R10 实为**以太网 TXEN**（发送使能），板子根本没有独立复位按键（手册里的 RESET_N=V8 是以太网 PHY 复位，不是系统复位）。工程能正常跑，因为复位链路本身设计成「只复位 PLL」：

```
I_rst_n (R10，实为 TXEN，接错也无妨)
  → ~I_rst_n（取反，高有效）
  → PLL.reset（design_top_wrapper.v 第 170 行 .reset(~I_rst_n)）
  → PLL 锁定 → S_pll_lock
  → S_rst_n = S_pll_lock（第 160 行 assign S_rst_n = S_pll_lock）
```

所以真正的系统复位信号是 `S_rst_n` = 「PLL 锁定标志」，跟 I_rst_n/R10 接什么引脚基本无关。所有模块（ae_set/isp/video_in/out/hdmi）接的都是 `S_rst_n`（低有效）或 `~S_rst_n`（高有效，如 ae_set 的 `.I_rst(~S_rst_n)`）。**新模块复用复位直接接 S_rst_n，不用新引脚**。

## 按键/拨码开关引脚现状（重构多算法切换前要知道）
- pin.adc 里 `I_button[0]=N2`、`I_button[1]=J14`，是**扩展口不是板载按键**。
- 顶层 `I_button` 是 `[1:0]` 两位，接 ae_set 补成 `{I_button, 2'b11}`（后两位恒 1 = 没按键）。
- 板载 KEY1~4 = D5/A9/B9/C7（按下=低电平、松开=高电平，见 hx1p35a-board-pins.md）。
- **拨码开关 SW1~4 = A4/B4/E11/D11**（SW5=蜂鸣器开关、SW6=数码管/双色LED选择，别占用）。手册⑯节原文：**拨上为"1"（高电平）、拨下为"0"（低电平）**。SW 是静态电平（拨到哪停哪），跟按键（边沿）不同——做模式切换直接读电平、不用检测按下沿，但要打两拍同步消抖。
- 要做「多算法切换」两个选择：① 4 个板载按键改引脚约束（检测按下沿）；② SW1~4 拨码开关（读静态电平，2 位就能编 4 种算法）。

## 拨码选模式：去抖 + 双开关中间态（2026-10-27 实战）
- **去抖必须加**：sw_mode 只打 2 拍（83ns）完全滤不掉拨码机械弹跳（几十 ms）→ 模式码跳动、模式 LED 灯闪。修复：20ms 去抖（`sw[1:0]` 连续稳定 CNT_MAX=24M×20ms 拍才更新 mode，与 debounce 同思路；tb 三场景验证：正常切换 20ms 后更新/抖动 5 拍不误触发/复位正常，见 sim/tb_sw_mode.v）。
- **双开关先后到位的中间态去抖滤不掉**：用户报「该 LED1 亮、LED2 先亮一会」不是抖动——SW1/SW2 两个独立开关手指拨动有时间差（几百 ms），中间短暂出现相邻模式组合，数百毫秒级中间态远超 20ms 去抖窗，与真切换时序上无法区分。方案：演示前拨好模式运行中不拨（零改动）；或按键循环切模式（每次只变 1 个模式，无中间态）；或格雷序拨码（相邻模式只动一个开关）。

## ae_set 模块：tick 连续调节（不是「长按检测」）
ae_set = 按键手动调曝光(AE)/增益(AG)，值变化时打 `O_ae_req` 脉冲通知 uicfgcs500 写摄像头寄存器。三段 always：

1. **计时器**：产生两个步进脉冲 `r_ae_tick`（数 100000 个周期，24MHz 下 ≈ 4.17ms 一个脉冲）、`r_ag_tick`（每 32 个 ae_tick 一个 ≈ 133ms）。曝光调得快（范围 2~1990 约 2000 档），增益调得慢（16~89 约 70 档）。
2. **按键检测+改目标值**：`r_ae_set <= r_ae_set - r_ae_tick` —— **减的是 tick 脉冲不是常量 1**。tick 平时 0、到点才 1，所以是「按住连续减」：按住期间每 tick 减 1、松手就停。`r_button_1` 是电平（两级打拍做同步防亚稳态），不是边沿（真边沿检测要 `r_button_1 && ~r_button_0`）。
3. **输出+触发**：目标值≠输出值 且 cam_cfg_done 且 ae_cfg_done 时，更新输出并打一拍 `r_ae_req`（请求只保持一拍）。

**关键概念区分**：这是「按住连续调节（自动重复）」，不是「长按检测」。长按检测 = 判断按下时长超阈值才触发一次；这里没有阈值，按多久调多久，类似键盘按住自动重复。ae_set 内部只有打拍、没消抖，短按可能抖动连触发，要防误触发再接 key_debounce。

## 归约与 &vector
`&rc_ag_tick` = 对向量所有位做与，**仅当全 1 才为真**。5 位 `rc_ag_tick` 时 `&rc_ag_tick` ≡ `rc_ag_tick == 5'b11111`（==31）。用来在计数器计满时产生 tick 脉冲。
