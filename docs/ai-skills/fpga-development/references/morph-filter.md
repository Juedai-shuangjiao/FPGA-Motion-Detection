# 形态学滤波（可分离 3×1/1×3 开运算）实现要点

前景标记（1bit/像素）去噪的 FPGA 标准做法：先腐蚀去孤立噪点（背景白斑）、再膨胀恢复目标尺寸（开运算）。

## 可分离实现（省资源）

4 级级联：3×1 水平腐蚀 → 1×3 垂直腐蚀 → 3×1 水平膨胀 → 1×3 垂直膨胀。

- 水平级：2~3 拍延迟链。处理中心 = 延迟 1 拍的数据 d1；左邻：p0 用 d2[3]（2 拍前最右位），其余 d1[i-1]；右邻：p3 用 d0[0]（当前拍最左位），其余 d1[i+1]。⚠️ 组合输出 ero_h 用拍前寄存器值（d1_h 拍 n = 输入拍 n-2），水平级实际延迟 2 拍不是 1 拍。
- 垂直级：两级 1280bit 移位寄存器（320 深 + 320 深）。**第二级必须吃第一级尾输出**：`row_v2 <= {row_v2[1275:0], row_v1[1279:1276]}`——写成 `row_v2 <= row_v1` 只延迟 1 拍，不是 320 拍。窗口 = {row_v2 尾（640 有效拍前，上行）& row_v1 尾（320 有效拍前，中心）& 当前（下行）}。
- 总延迟 = 643 有效拍（1+320+1+320 = 642 理论值 + 级 1 组合输出多 1 拍）。valid 链 [0:642]、O_valid = valid_chain[642] && I_valid（精确对齐 643 拍数据延迟）。

## 行深如何定（2026-10-27 错判教训）

行缓冲深度必须 = 每行有效拍数，但「每行有效拍数」不能拿「帧总对数 ÷ 总行数」推——**先确认「帧总对数」是整帧还是半帧**。分帧读架构（每消隐读半帧 360 行）下 cmp=115200 = 360 行 × 320 拍/行（每行 240 个 128bit 解包出 320 个 96bit），误除 720 行会得出 160 拍/行的错判、把正确行深改错。行深 = 每行 128bit 命令数 × 96/128（解包膨胀率），用「行拍数 = 240×128/96 = 320」直推最稳。

## 五个关键坑

1. **行缓冲/延迟链只在 I_valid 拍推进**（空洞拍不 shift）——否则「320 拍」不再是「一行 320 个有效拍」，行窗口在行边界漂移错位。
2. **全链门控策略必须统一**：水平级/垂直级/valid 链全部 valid 门控。部分门控部分日历 shift 时，空洞拍（3/4 节流空洞率约 25%）让两者相对漂移 → 垂直窗口跨行错位 → 输出错位标记 + 背景噪声被腐蚀/膨胀成伪前景线（实机白影错位+白线）。
3. **O_valid = 链尾 && I_valid**：valid 门控链在空洞拍/输入停止期保持 1，不加 && I_valid 门控会持续输出 valid → 下游攒字器重复消费保持的旧数据。
4. **帧尾必然丢弃**：valid 门控链在帧间断层不推进，帧尾 643 拍数据排不出、只能由清链丢弃（每半帧丢底部 2 行 = 64 字）。下游「写满判据」必须放宽（23039 → 22960 这类宽判据），否则写满标志永远等不到。清链时机 = 帧开始延迟 512 日历拍（新帧首数据 ≥ vsync+600，清链不误伤新帧头）。
5. **tb 场景设计**：孤立噪点必须离目标块 ≥2 行（640 有效拍）——1×3 膨胀会把块向邻行扩展 1 行，距离 <320 拍时膨胀正确地把噪点位置覆盖，误判为「噪点没清除」。单行高的块会被 3×3 腐蚀正确整体清除（上下邻全 0），验证块保持要用 ≥3 行高的块。tb 判据映射：输出第 j 个脉冲 = 输入拍 j（第一个输出在输入拍 0 后 643 拍），不是 j+延迟。

## 3×3 开运算的滤除上限 + 5×5 扩展账本（2026-11-02 下板噪声反馈）

下板现象：孤立噪声被圈进显示框（框被拉大/拉偏）。根因：3×3 腐蚀条件 = 窗口全 1 才保留中心，只能滤「1 像素孤立点 + 1px 宽细线」；**2~4 像素小簇的内部像素 3×3 邻域里有其他噪点像素 → 腐蚀后残留 → 进框**。噪点滤不净 = 窗口太小，不是开运算思路错。

升级方案账本（用户拍板后实施）：
- A 5×5 开运算：腐蚀+膨胀都 5×5。≤3px 任意形状簇全灭；行缓冲 2×320→4×320 拍 ×2 级；总延迟 644→2564 有效拍；+80~160 slice；目标净缩 4px。
- B 非对称（5×5 腐蚀 + 3×3 膨胀，推荐）：滤噪力同 A；只腐蚀级加缓冲（+40~80 slice）；延迟 644→1604；目标净缩 2px。
- C 阈值 40→60（一行改动、零成本先行试验）：噪点差 40~60 之间直接滤掉；风险 = 阴影/远距手部弱对比度漏检。
- D 时域两帧一致性（不推荐）：需整帧标记缓存 115200bit，ERAM 已满 45 块无处放，分布式 RAM +500 slice。

实施注意事项（改窗口尺寸时）：valid 链深 = 数据延迟严格同拍（644 这个数多处硬编码：链深/帧尾丢弃拍/下游 fg_init 判据，改窗口全都要联动重算）；帧末丢弃行 2→4 行；5×5 腐蚀吞 2px 细部（手指细节），人手连通区域不受影响。tb 场景加 2px/3px 簇验证滤除、连通块 ≥5 行验证保留。

## 位置映射验证（全白/全 0/全 1 场景测不出，2026-10-27）

位序/列映射类 bug 用「全前景全白」「无差异全 0」都验不出来（全白无位置信息、全 0 无图案）——与 DDR 地址编码教训同构；**「cur/bg 两流零差异错位」的 mis=0 判据也验不出来**（两流同方向整体错位时差异仍对齐，对的是相对位置不是绝对位置）。正解：tb 的 DDR 返回模型注入「已知位置差异图案」（如 bg 数据仅行首 128bit 字翻转字节 0x80，用地址 mod 运算命中每行行首），抓 ERAM 写数据的位序/地址对照期望图案（如行 1 首字 [7:0]=0x7F：行 0 被首行无上行腐蚀清、行 1 起 x=0~6 经腐蚀+膨胀恢复）。**差异图案必须放在垂直/水平窗口完整的位置**：只放帧首行行首 → 3×3 腐蚀把无上行/无左邻的图案整体清除 → 输出全 0 被误判成「链路断」，实际是算法正确吃掉了图案。**判据抓取时机先核对时间戳**：写拍时刻与「同步脉冲 + 清场 + 读延迟 + FIFO 攒行 + 模块延迟」的推算吻合才说明仿真真跑到了该点，全 0 才是真数据（用户会追问「会不会还没仿真完」，先答这条再改 tb）。注意攒字器写地址非阻塞递增：第 n 字写入拍 addr 显示 n+1，tb 判据按显示值抓。

## 仿真性能

iverilog 对 1280bit 移位寄存器 ×4 条 + 643 深 valid 链的仿真极慢（4 帧 × 100 万拍，带 VCD >70 分钟跑 1 帧）。验证策略：单模块 tb（几千拍，秒出）验证滤波逻辑；集成对齐用去 VCD/去逐拍打印的集成 tb；VCD 只在 FAIL 后按需加回。643 深 valid 链用位向量拼接移位（非 reg 数组 for 循环）可再提速 2.4 倍（通用规则见 sim-debug-methodology）。
