# 自适应阈值与阴影抑制四坑（实战收官）

真实画面下板验证的教训，仿真人工构造场景验证不了这些坑。

## 坑 1：均值型自适应边缘阈值 → 全屏白点
- T = 1.564×mean(mag8) 公式：真实 720P 画面 90%+ 像素梯度≈0（平坦区），mean 被拉垮到 1~3，T≈3~5，任何噪声尖峰（mag8 5~8）都过阈 → 全屏白点、数码管显示阈值 3。
- 三区间梯度查表（强≥96/中 32~95/噪 1~31，按分布 40/48/64/32）也翻车：室内纹理场景强边缘计数常满足 hi×4≥lo → 永远落 40 档，40 在 mag8 域（响应 1280）对 8 方向卷积仍太低，继续全白。
- 结论：8 方向卷积（L∞ 取最大）后阈值域必须重标定；手动可调（sobel_threshold_set：KEY2/3 长按调、S_mode==3 使能）比自适应可靠。真实画面的自适应阈值要做就做「非零梯度分位数」级方案，均值/粗查表都不行。
- ⚠️ **亮度分档查表联动同样翻车（提交版已回退）**：avg<70→A / <85→B / <100→C / ≥100→D 这种 4 档查表（二值化、Sobel 各一套）在实机上被判「跟随效果不好、阈值不稳定」——光照/场景变化跨档时阈值跳变，画面效果来回跳。用户决策：阈值调节一律纯手动（I_auto_en 恒 0），自动控制只留给曝光/增益。自适应阈值这条路的结论是两轮实战重复验证过的，不要再推联动方案。
- ⚠️ **步进按「最终使用域」定，不按寄存器域定**：阈值寄存器是 11bit、canny 消费的 high_thr = reg[10:3]（mag8 域，差 8 倍）——寄存器域步进 8 = mag8 域才 +1，长按 200ms/tick 一秒只动 5，画面无感，用户判「按键调不起作用」误报 bug。步进 = 目标域感度 × 域间倍率（mag8 域想每 tick +8 → 寄存器域步进 64）。二值化阈值 8bit 域直用，步进按像素域感度直接定。
- ⚠️ 改寄存器初值要改两处：声明初值（综合 INIT）和复位分支赋值——只改声明、复位分支漏改，上板复位后回旧值（512→复位后 128，mag8 域阈值 16 → 全屏白+噪，与「调不动」混在一起极难定位）。同理，复位值改了声明没改也一样。改后 grep 该寄存器名看全部赋值点，两处值必须一致。

## 坑 2：阴影抑制判据 —— 相对色度容忍（v3 终版，前两版都误伤）
- v1 双向 |ds|<25：手在白墙前色度比墙高（ds 为正且 <25）被当「色度没变」→ 判阴影滤除 → 涂白断续。
- v2 ds<-6 单向 + s_bg≥12 前置：又漏——手挡光致水管变暗（金属灰 s_bg≈0、ds≈0）不满足前置 → 水管被涂白。s_bg 前置的假设自相矛盾：无色表面恰好最需要抑制光照型暗变（它的「阴影」就是纯变暗）。
- v3 终版（下板验证）：shadow = dy∈(-280,-48) && ds≤0 && |ds| ≤ (4 + s_bg/4)。背景色度高时按比例容忍色度降（真影子 ds≈-0.3×s_bg），背景无色时容忍只剩 4（水管挡光 ds≈0 仍滤）；手色度升（ds>0）永不滤；深色实体 dy<-280 兜底。
- ⚠️ Verilog 实现坑：容忍比较式不能写 signed < unsigned——signed/unsigned 混比按 unsigned 处理，负数变超大正数（-14→1010）恒不成立（tb 假 FAIL 3 项）。写法：先显式算无符号绝对值（W_ds[9] ? (~W_ds[8:0]+1) : 0）再与无符号容忍比较，符号判断单独写（W_ds <= 10'sd0）。
- 验证场景：水管挡光（灰表面变暗 ds=0 → 滤）、白墙前的手（ds>0 → 不滤）、深肤色手（dy 兜底 → 不滤）、鲜艳背景真影子（ds=-24 ≤ 4+80/4=24 → 滤）、彩色墙前的手（dy 为正出区间 → 不滤）。

## 坑 3：CRLF Verilog 文件 regex 删行易误伤
- fuse15：字节级替换统计块时把「mag8 打拍块声明」一并删掉 → m8_0_d1 未声明综合失败。
- fuse16：regex 删 O_sobel_adapt_thr 端口行时把下一行 I_sw4 粘到上一行 → 端口丢失综合失败。
- fuse18：同一事故的第二现场——删行时把 `wire [15:0] S_bcd_sobel_threshold;` 粘到上一行 `//Sobel 阈值（0~2040）` 注释后面 → 声明被注释吞掉 → wire 隐式声明成 1bit → bin2bcd 的 16bit 输出接 1bit 线 → 数码管显示垃圾（0x1FFE=「1   E」）+ 按键调了显示不动，但**编译全程零报错**（隐式 wire 合法），底层寄存器其实在动。特征判读：显示恒垃圾值/显示不更新而功能可能正常 = 先查该显示链 wire 声明是否被同行注释吞掉。检测：任何 regex 删行后扫描 `//[^\n]*(wire|reg|input|output)\b` 同行粘连模式（注释正文里含这些字样的行是误报，人工逐行看）。
- 各浪费一轮 50 分钟编译。铁律：删行/删块后必须 iverilog 全工程验证（预期只剩 key_pulse 2 个已知错误），再启动 TD 编译。
- TD 日志查编译失败：grep -E 'BIT-1004|ERROR'；bit 没生成但 final_timing.rpt/phy.area 时间戳是旧的 = 编译早退。

## 坑 4：en 门控的模式状态机，!en 分支不得复位持久状态
- 现象：手动曝光状态拨 SW34 切到其他模式再切回，自动/手动状态丢（变回自动）。根因：!en 分支把 mode 寄存器复位成默认值（自动）——模式切换时用户设置被吞。
- 规则：en 门控的状态机在 !en 分支只清瞬态标志（如 held_flag 防抖标志），持久状态寄存器（mode/auto_manual/用户参数）一律保持不动，en 恢复后照常工作。
- 改语义后 tb 期望必须同步反转：原用例「en=0 锁定自动」改为「en=0 保持 mode=1」，并补用例「en 恢复后长按仍能切回」——语义改动漏改 tb 期望会得到假 FAIL，浪费排查时间。
